# B01 — независимая проверка IndexedDB (только эмулятор)

**Не установка на OnePlus. Не восстановление пользовательской базы.**

Этот экспериментальный модуль собирает отдельный Android APK с package ID
`ru.paseka.journal.diagnostic.restore`, отличный от реального
`ru.paseka.journal`. В нём нет основного интерфейса «Пасеки», импорта,
удаления файлов, Service Worker, доступа к сети и функций изменения данных.

## Что можно доказать

В уже подготовленном изолированном Android-эмуляторе, после **отдельного
безопасного копирования** файлов в его **диагностический профиль**,
приложение может через системный Android WebView проверить:
- наличие IndexedDB базы `paseka-v1` в ожидаемом origin;
- возможность открыть её без изменения версии;
- наличие хранилищ `main`, `full_backup`, `entrance_media`;
- количество записей каждого хранилища через `count()`, без чтения ключей
  и значений.

Каждое заявление требует **реального запуска и обезличенного отчёта**.
Никакого Android/emulator device proof CI-сборка сама по себе не даёт.

## Ограничения

- Стандартные LevelDB-драйверы с bytewise comparator не подходят для
  Chromium IndexedDB, где comparator `idb_cmp1`; открывать ими реальные
  WebView файлы запрещено.
- Подтверждение `V16→V18` относится только к файловой копии на ПК.
  Пользовательские ключи/значения и реальное функционирование базы
  пока не подтверждены.
- Истинный WebView origin захваченной версии должен совпадать с тем,
  в котором работает diagnostic APK. Предполагаемый origin
  `https://localhost` **требует проверки на изолированной цели**.
- Подготовлена отдельная процедура **V20** (см. `README-V20.txt`) для PC-only переноса через ADB в **строго проверенный изолированный эмулятор**, с побайтовой SHA-256-сверкой. До успешного CI и физического прогона на отдельной безопасной цели V20 **НЕ СЧИТАЕТСЯ ДОКАЗАННЫМ**. Ручное копирование приватных файлов запрещено.
- Доступ к конкретным записям/Blob, полнота истории, сравнение их
  содержимого с источником, Gallery/MediaStore и независимое
  восстановление рабочей «Пасеки» не доказаны.

## Защита

1. Другая package ID предотвращает перезапись установленной «Пасеки».
2. Native `MainActivity` проверяет **два** признака эмулятора
   (hardware + fingerprint) и выбрасывает исключение **до**
   `BridgeActivity.onCreate` на физическом устройстве.
3. JavaScript запускается лишь по явному нажатию, использует
   `indexedDB.databases()`, `open()` с запретом upgrade и
   транзакции строго `readonly`. `get`, `getAll`, `put`,
   `clear`, `deleteDatabase` отсутствуют.
4. V20 использует ADB **только** для эмулятора после проверки hardware+fingerprint+qemu+AVD name и пакетного ID. В CI — только synthetic mock, без настоящего телефона. Пользовательские файлы никогда не загружаются в GitHub Actions.
5. Генератор создаёт только новую папку **вне репозитория** и отказывается
   от существующего каталога, симлинков на исходники и неверной package ID.
6. Изолированный диагностический APK собирается с временной debug-подписью
   CI, **не** является обновлением/заменой основной версии приложения.

## Тесты и результат

`node --test tests/b01-isolated-diagnostic.test.mjs` проверяет
отсутствующую БД, несовпадение origin, успешный read-only подсчёт
трёх хранилищ, отклонение upgrades/missing stores, изоляцию source
и нативный emulator-only guard.

`.github/workflows/b01-isolated-diagnostic.yml` создаёт новый,
отдельный diagnostic Android APK. Бинарную сборку и CI проверять
по точному SHA коммита. Это не физический restore.

**B01 остаётся BLOCKED, автоматическое удаление видео FROZEN.**

## V20: автоматизированная доставка копии в эмулятор

- `transfer-to-emulator.mjs` проверяет single persistent V16 reconstruction, симлинки, имена, размеры, обязательные LevelDB-маркеры. Создаёт бинарный TAR только **в оперативном потоке**, без общего промежуточного каталога Android; каждый файл сверяет SHA-256 в диагностическом sandbox через ADB run-as.
- До установки отдельного APK проверяется serial `emulator-NNNN`, `ro.kernel.qemu=1`, hardware `ranchu/goldfish`, emulator fingerprint, и имя AVD `PASEKA_B01_ISOLATED_*`. Если target содержит настоящую «Пасеку» или уже установленную диагностику — отказ. На физический OnePlus ADB-команды не направляются.
- Готовится полностью автономный Windows-пакет с `node.exe`, `adb.exe`, `aapt.exe`, diagnostic APK, `START.cmd` и README. Публичный отчёт содержит только коды состояний и счётчики, без путей/данных/хешей пользовательской базы.
- Отдельные регрессии проверяют полный путь через mocked ADB, включая запрет физического устройства. **Успех переноса и SHA не равен открытому IndexedDB, записи ещё не прочитаны, Android restore не подтверждён.**
