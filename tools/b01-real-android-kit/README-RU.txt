ПАСЕКА — B01. Локальная проверка Android-эмулятора без Console
=============================================================
ТРЕБУЕТ: Node.js 22+, Android Emulator API 35 (запущен),
ADB с диагностическим пакетом ru.paseka.journal.disasterproof2.

ВАЖНО: комплект НЕ устанавливает APK, НЕ настраивает эмулятор, не меняет
рабочий OnePlus, не загружает архив в GitHub и не удаляет файлы.

1. Сначала подготовьте и запустите отдельный Android emulator-5554
   (проверка ro.kernel.qemu=1, API 35).
2. Установленный ТОЛЬКО в эмулятор диагностический APK должен иметь
   packageId ru.paseka.journal.disasterproof2 из CI PR #534.
   Никогда не устанавливайте его на OnePlus. Ни один скрипт комплекта
   не выполняет adb install и не изменяет приложение ru.paseka.journal.
3. Запустите ПРОВЕРИТЬ-ЭМУЛЯТОР-B01.cmd.
   READY_EMULATOR_AND_ARCHIVE означает наличие эмулятора и
   исходного архива, но не создание Android-копии или восстановление.
4. Только после проверки устройства и кода можно выполнить:
   node b01-emulator-owner-stage.mjs --stage
   Команда копирует отдельный экземпляр исходного JSON в Downloads
   исключительно эмулятора (без перезаписи существующего там файла),
   сверяет SHA-256 и запускает тестовый пакет.
5. В тестовом APK вручную выберите JSON из папки Downloads.
   Нужен PASEKA_B01_ANDROID_OWNER_ARCHIVE_REPORT со статусом
   PASS_TARGET_READBACK_NOT_PROCESS_RESTART. Это реальный Android
   target restore/readback, но ещё не доказанная сохранность после
   принудительного завершения Android процесса.
6. Только после этого во ВНЕШНЕМ ADB (на emulator-5554) проверить
   force-stop и повторный запуск диагностического пакета.
   Ни при каких обстоятельствах не выполнять force-stop
   ru.paseka.journal. Отчёт после запуска должен показать
   PASS_READBACK_AFTER_RELAUNCH_DEVICE_CLASS_UNVERIFIED.
   Для подтверждения требуется сохранённый внешний ADB-протокол.

Если установка Android emulator или диагностического APK отсутствует —
BLOCKED; не пытайтесь использовать USB-подключённый OnePlus взамен него.
Существующий пользовательский файл на ПК оставляйте неизменным;
не удаляйте его и не передавайте в чат/GitHub. Только редактированные
PASEKA_B01_REPORT передаются для продолжения B01.

Даже PASS на эмуляторе не является доказательством штатного production
restore/upgrade/rollback, B05 signing key или разрешением на удаление
оригинальных видео.
