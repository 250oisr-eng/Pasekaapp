ФИЗИЧЕСКИЙ СЕАНС S0–S7 — ДОПОЛНИТЕЛЬНАЯ ЗАЩИТА КОМПЛЕКТА
=========================================================
Перед чтением архивов или USB команда ПРОВЕРИТЬ-ПАСЕКУ.cmd автоматически
проверяет SHA-256 всех включённых файлов по
PASEKA-PHYSICAL-KIT-MANIFEST.json. Несовпадение или отсутствие манифеста
останавливает запуск. Это контроль целостности в пределах ZIP,
НЕ цифровая подпись издателя и НЕ разрешение обновлять Android.

Каждый новый обезличенный PASEKA-CHECK-*.json содержит physicalReadiness:
S0 — подтверждение подключённого OnePlus и установленного пакета
     (если USB доступен; не путать с чтением базы);
S1 — полный IDB JSON на ПК: только PARTIAL даже при совпадении байтов,
     пока неизвестны Gallery/MediaStore и отдельные оригиналы;
S2 — пробное восстановление в памяти: только PARTIAL, не восстановление
     рабочего Android;
S3 — внешние оригиналы Gallery/MediaStore: BLOCKED;
S4 — подписанное обновление и rollback: BLOCKED;
S5 — холодный offline на реальном устройстве: NOT_TESTED;
S6 — лицензированная модель и удаление оригиналов: FROZEN;
S7 — подтверждение создания локального отчёта: PASS.
Отдельные PASS на S0/S7 не снимают B01/B04/B05 и не дают разрешения
на установку APK, изменения IndexedDB или удаление видео.

ПРЕДЫДУЩЕЕ ИЗМЕРЕНИЕ НЕ ПОВТОРЯТЬ: в отчёте от 25.11.2026
уже подтверждены USB/run-as/наличие записей в каталоге WebView,
без чтения файлов базы. Новый запуск нужен только для нового
полного архива или изменившегося технического состояния устройства.

ВАШИ ДЕЙСТВИЯ СЕЙЧАС: 0. Когда понадобится единая проверка на ПК,
используйте только полный ZIP успешной Windows CI сборки того же SHA,
не смешивайте файлы разных комплектов. Подключённый OnePlus автоматически
распознаётся только при ранее разрешённой USB-отладке; если доступа нет,
комплект выдаёт NEEDS_INPUT и не пытается обходить защиту.
В чат передавать только последний обезличенный JSON отчёт.

ПАСЕКА 2.0 — ЕДИНЫЙ ЦЕНТР БЕЗОПАСНЫХ ПРОВЕРОК
====================================================

ОДНА ТОЧКА ВХОДА НА ПК: ПРОВЕРИТЬ-ПАСЕКУ.cmd

Один раз распакуйте архив из успешной GitHub Actions сборки
PASEKA-UNIFIED-OFFLINE-CHECK-CENTER. Для каждой следующей проверки
только дважды нажимайте ПРОВЕРИТЬ-ПАСЕКУ.cmd.
Не нужно открывать Android Studio, вводить ADB-команды или
устанавливать APK. Если OnePlus УЖЕ подключён по USB с ранее
разрешённой USB-отладкой, программа попытается получить только
модель устройства и факт установки пакета ru.paseka.journal.
Если телефона или разрешения нет, проверки продолжатся без него.

КОМПЛЕКТ АВТОМАТИЧЕСКИ:
- проверяет, что встроенная среда работает;
- если существует РОВНО ОДИН полный JSON-экспорт P0 в папке комплекта,
  Загрузки/Downloads или Рабочий стол/Desktop, выполняет
  независимое восстановление в одноразовую память (включая Blob),
  закрывает/открывает временную базу и сверяет байты;
- если JSON отсутствует/несколько файлов, сообщает NEEDS_INPUT,
  не пытаясь гадать, какой архив выбрать;
- показывает, что системные Gallery/MediaStore ОТДЕЛЬНО требуют
  реального доказательства, не выдавая это за успешную проверку;
- сохраняет каждый новый отчёт в PASEKA-CHECK-REPORTS без удаления или замены
  предыдущих. Папка отчётов откроется автоматически.
- данные не отправляет в сеть; при доступном USB OnePlus выполняет
  ТОЛЬКО read-only команды getprop и pm path, не выгружает APK и файлы,
  не вызывает открытие приложения, install, backup или удаление.

В чат передавайте ТОЛЬКО самый новый PASEKA-CHECK-*.json
из PASEKA-CHECK-REPORTS. Не отправляйте сам полный JSON-архив,
видеозаписи, содержимое IndexedDB, имена файлов или TAR.

ГДЕ ВЗЯТЬ ПОЛНЫЙ АРХИВ:
В уже установленной «Пасеке» на телефоне:
«Ещё» → «Резервное копирование» →
«P0 · Полный архив IndexedDB (только чтение)» →
«Скачать полный архив текущей базы».
Это сохранит paseka-full-idb-YYYY-MM-DD.json. Если кнопки
нет в установленной версии, НЕ обновляйте приложение ради проверки.
Вместо этого сообщите «нет кнопки», ничего не меняя на телефоне.
Обычный «Скачать JSON (без отдельных видео летков)» НЕ подходит.

КАК ДОБАВЛЯТЬ НОВЫЕ ПРОВЕРКИ В БУДУЩЕМ:
Разработчик добавляет проверку в реестр allowlisted checks
scripts/paseka-check-hub.mjs, регрессионные тесты и выпускает
новый проверенный ZIP в GitHub Actions. Для пользователя остаётся
тот же файл ПРОВЕРИТЬ-ПАСЕКУ.cmd в новом комплекте.
Не запускайте недоверенные скрипты и не копируйте DLL/APK
из устаревших пакетов.

СТРОГИЕ ГРАНИЦЫ:
- Полный JSON-экспорт пока НЕ подтверждён на вашем OnePlus.
- Локальная fake-indexeddb не эквивалентна физическому
  независимому восстановлению в Android.
- Gallery/MediaStore и все внешние оригиналы видео не включены.
- Файл больше 64 МиБ получает BLOCKED; данные остаются нетронутыми.
- Никакие исходники, копии, записи, видео не удаляются.
- Автоматическое удаление видео FROZEN #442.
- Все проверки — read-only, без сети. Только утверждённая проверка
  модели OnePlus и установленного APK может обращаться к USB через ADB.
  Это НЕ подтверждение целостности БД, видео или разрешение обновления.
- На USB должен быть ровно один авторизованный Android. При втором
  устройстве/эмуляторе тест безопасно остановится без чтения телефона.

НОВОЕ: при уже разрешённом USB OnePlus 10 Pro центр дополнительно
считает ТОЛЬКО количество файлов с именем paseka-full-idb-YYYY-MM-DD.json
в стандартной папке Download телефона. Имена других файлов, содержимое
и сами архивы не выгружаются и не передаются. Наличие имени не значит
целостность или пригодность архива. Отсутствие имени в Download не
доказывает, что файла нет в другом месте Android.

НОВАЯ ПРОВЕРКА B01 (read-only): если OnePlus уже авторизован по USB,
центр вызывает только `run-as ru.paseka.journal id`, чтобы выяснить,
может ли Android штатно переключиться в контекст установленного APK.
Данные приложения НЕ читаются, не копируются и не архивируются.
PASS здесь означает только доступность run-as, а не доказанный backup.
На обычной release-сборке ожидается `INSTALLED_APP_RUN_AS_UNAVAILABLE`.
Не включать root, не переустанавливать приложение и не очищать данные.


ЭТАП B01 — ИНВЕНТАРИЗАЦИЯ (без чтения базы):
Если на уже подтверждённом OnePlus доступен run-as, Центр проверок
попробует показать только обезличенные признаки каталогов WebView,
включая возможные IndexedDB. Используются три заранее заданных пути:
app_webview/Default/IndexedDB, app_webview/IndexedDB,
app_webview/Default/Local Storage/leveldb.
Пользовательские имена каталогов/файлов из ответа ADB не включаются
в отчёт. Нет копирования, чтения содержимого файлов, остановки
приложения или записи в его хранилище.
Результат «элементы присутствуют» НЕ означает, что база цела,
принадлежит нужному origin или пригодна к восстановлению.
«Каталоги недоступны» НЕ означает, что данные отсутствуют.
Автоудаление видео и обновление рабочего APK запрещены.
