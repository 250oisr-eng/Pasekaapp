# Контроль журнала на OnePlus — изолированный физический тест

**Статус:** диагностическая сборка в отдельной ветке/Draft. Рабочая «Пасека» `ru.paseka.journal` и её пользовательская база не затрагиваются.

## Что исправляется в обычном приложении

- Ручные измерения Varroa сохраняются с единственной активной отправкой, откатом памяти и auditLog при failed/throwing IndexedDB; форма не очищается при ошибке.
- Отображение измерений по выбранному улью, без перемешивания историй разных ульев.
- Выбранный улей не сбрасывается после удачного сохранения.
- Будущая дата недопустима для фактического измерения.
- Архивировать/восстановить общую запись журнала можно только при подтверждённом сохранении; при отказе/исключении восстанавливаются запись, вложения и история, повторное действие по ID блокируется.

## Что проверяет отдельная Android APK

CI [`android-journal-physical.yml`](../../.github/workflows/android-journal-physical.yml) создаёт **только** диагностический APK с именем `Пасека · Журнал · ТЕСТ` и Android ID `ru.paseka.journal.journalproof`; обычный APK для `ru.paseka.journal` собирается независимо. Сборочный скрипт изменяет `capacitor.config.json` и `www/index.html` **только в рабочей копии CI**, не в исходниках релиза. Результат снабжён SHA-256 манифестом.

Диагностический runner запрашивает **пустое** изолированное хранилище нового APK; в нём создаёт один **синтетический** тестовый улей, ручное измерение, фактически подтверждаемую только **в тестовом сценарии** запись обработки без дозы, архивирует и восстанавливает её; читает фактически зафиксированное состояние через IndexedDB, перезагружает WebView и ещё раз читает записи. После остановки и запуска только тестового пакета проверяет, что записи сохранились. Вся тестовая информация явно помечена `TEST_ONLY`.

Состояния, которые runner **не** проверяет: рабочая пользовательская база/медиа/видео, реальный приём данных из улья, реальный restore производственного архива, полный авиарежим, лицензированное распознавание пчёл, очистка и удаление. Нельзя повышать их до PASS по скриншоту.

## Одно действие пользователя на ПК

После успешной сборки скачать цельный ZIP `Paseka-OnePlus-Journal-ONE-CLICK.zip`, распаковать и запустить `Run-Journal-Phone-Proof.cmd` с OnePlus NE2213/Android16 на USB. Архив содержит уже проверенную SHA-256 сборку; не требуется отдельно загружать APK. Скрипт устанавливает только `ru.paseka.journal.journalproof`, запускает тест, затем останавливает/перезапускает **только тестовый пакет**, снимает два экрана в `Desktop/Paseka-Journal-Phone-Evidence`; исходную «Пасеку» не останавливает. Результат JSON остаётся `EVIDENCE_CAPTURED_REVIEW_REQUIRED` до независимого прочтения экранов. Не менять Wi-Fi/сотовую связь, не очищать базы и не удалять никакие файлы пользователя.

Пользователь должен переслать `Paseka-Journal-Phone-Result.json` и две PNG (одна загрузка на сообщения с файлами). Отсутствие этих данных = **PHYSICAL_ONEPLUS_NOT_TESTED**, даже если Android CI PASS.

## Остановки и дальнейший приоритет

1. Нет USB, разрешения отладки, корректного test package/manifest/SHA-256 или пустого тестового хранилища ⇒ BLOCKED, без замены на production и без `pm clear`.
2. Все автоматические тесты и Android build на точном HEAD должны быть успешны; Android emulator proof — отдельная категория, OnePlus proof — отдельно.
3. Последующий этап после журнала: резервная копия и аварийное восстановление **не-медийных** записей/миграций IndexedDB, изоляция физических профилей/инвентаря, согласованность OP с журналом, затем UX/офлайн/голос.
