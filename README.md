# Пасека — мобильное offline-first приложение

«Пасека» — мобильный журнал и виртуальная модель пасеки. Приложение работает как PWA в браузере и имеет Android-оболочку на Capacitor.

## Что уже реализовано

- Разделы пасеки: обзор, ульи, леток, журнал, ИИ, медоносы, контроль Varroa, досье инцидентов, сезонное планирование и настройки.
- Учёт ульев, пчелиных семей, происхождения и родословной.
- Физическая схема гнездовых и медовых корпусов, рамок и зимней сборки.
- Начат переход к профилям конструкций ульев: версия профиля Фаррар и шаблоны Дадана, Рута/Langstroth и пользовательской системы. Полная работа альтернативных конструкций ещё в разработке.
- История перемещений рамок, откачки и возврата медовых корпусов.
- Журнал осмотров и работ, вложения фото/видео.
- Локальный журнал контроля Varroa: ручные результаты проб взрослых пчёл и контрольных поддонов с раздельными расчётами.
- Локальное досье при подозрении на отравление: GPS по запросу, фото со смартфона, затронутые ульи, обращения и учёт проб.
- Смартфонные календарные расчёты: обратный календарь медосбора, календарь вывода маток и настраиваемый интервал контрольных осмотров. Расчёты дают ориентиры, не гарантии.
- Задачи: создание, принятие предложений, перенос сроков, выполнение с привязкой к записи журнала.
- Проверки целостности модели, аудит, архивирование и восстановление.
- Локальное хранение IndexedDB, автоматические внутренние снимки и ручной JSON backup/restore.
- Защита от конфликтующих записей между вкладками и проверки целостности резервных копий.
- ИИ-советник через Neon Auth и Cloudflare Workers AI.
- Ограниченный ИИ-оператор: предложения пакетного перемещения рамок и задач. Любое изменение проходит локальную проверку, предварительный просмотр и отдельное подтверждение; серверная модель не меняет базу.
- Явная голосовая диктовка в поддерживаемом браузере: распознанный текст сначала попадает в поле ввода и отправляется только отдельной командой пользователя.

## Ограничения, которые важно понимать

- Данные пасеки хранятся локально в браузере/приложении. Облачная синхронизация между устройствами пока не реализована. Делайте резервные копии и храните их отдельно.
- ИИ требует подключения к сети, входа в Neon Auth и доступного Cloudflare Worker. Без сети основные локальные функции приложения остаются доступны.
- ИИ-оператор пока поддерживает только пакетное перемещение рамок и предложения задач. Перевод семьи, автоматическое создание записи журнала по извлечённым структурированным данным и автономный агент-наблюдатель ещё не реализованы.
- Диктовка зависит от поддержки Web Speech API и настроек браузера/устройства. Распознавание может выполняться внешним сервисом; приложение предупреждает об этом до запуска. Физическая проверка диктовки на Android ещё не подтверждена.
- Android debug APK собирается в CI. Это не подписанный релиз для Google Play и не доказательство тестирования на физическом телефоне.
- Не создавайте фиктивные семьи, ульи или рамки в рабочей базе ради проверки. Для успешных сценариев ИИ-оператора используются изолированные тестовые фикстуры.

## Публикация и запуск

PWA: https://250oisr-eng.github.io/Pasekaapp/

На Android откройте ссылку в Chrome и выберите «Установить приложение» или «Добавить на главный экран».

Android debug APK доступен как артефакт успешного workflow **Build Android APK** в GitHub Actions репозитория.

## Серверная часть

- Cloudflare Worker: https://pasekaapp.250oisr.workers.dev/
- Авторизация: Neon Auth.
- Модель: Cloudflare Workers AI.
- Worker развёртывается отдельно через workflow **Deploy Cloudflare Worker** (ручной запуск). Коммит в GitHub и публикация GitHub Pages сами по себе не обновляют Worker.
- Не публикуйте и не передавайте третьим лицам пароли, JWT, API-токены, Cloudflare Account ID или значения секретов GitHub.

## Разработка и тесты

Полный регрессионный набор запускается командой:

```bash
npm test
```

CI разделён на два независимых контура:

- **Fast quality checks** — запускает весь регрессионный набор при изменениях приложения, сценариев, тестов и конфигурации быстрых проверок.
- **Build Android APK** — при изменениях приложения и Android-сборки повторно запускает полный регрессионный набор, готовит Android-проект и собирает debug APK. Тесты не пропускаются ради ускорения.

Для ускорения повторных запусков кэшируются npm-пакеты и Gradle. Android-сборка и публикация PWA остаются отдельными процессами. Тесты голосового режима проверяют разбор ключевых фраз, защиту от обработки обычной речи без активации, обработку только финальных результатов распознавания, перезапуск распознавания и отказ при запрете микрофона.

Успешные workflow относятся только к точному коммиту, указанному в GitHub Actions. Успешная автоматическая сборка не заменяет проверку на физическом Android-устройстве; такая проверка отдельно подтверждается.

## Анализ видео летка — начальная основа

Добавлен независимый модуль расчёта и проверки аналитики видео летка: техническая пригодность файла, оценка качества выборки кадров, расчёт показателей по уникальным траекториям, учёт неопределённой классификации, индивидуальная базовая линия (медиана/MAD) и осторожные предупреждения. Реализованы экран локального видеоархива, выбор улья, импорт/съёмка видео через системную камеру смартфона, проверка длительности/формата/разрешения и отдельное IndexedDB-хранилище оригиналов. Передача на сервер и нейросетевое распознавание ещё не подключены. См. `docs/ТЗ-анализ-видео-летка.md`.
