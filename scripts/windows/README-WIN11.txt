ПАСЕКА — АВТОМАТИЧЕСКИЕ ИСПЫТАНИЯ НА WINDOWS 11 И ANDROID

Содержимое переносимого комплекта:
  START-TESTS.cmd             — двойной щелчок для запуска
  Run-Paseka-Tests.ps1        — открытый сценарий для PowerShell 5.1+
  paseka-device-test.apk      — отдельная тестовая APK
  paseka-device-test.sha256   — контрольная сумма APK
  device-package.txt         — уникальный идентификатор test APK этой сборки
  platform-tools/adb.exe      — официальные бесплатные Android Platform Tools
  platform-tools/*.dll        — библиотеки ADB

Проверка безопасности комплекта:
  - PowerShell-скрипт проверяется на синтаксические ошибки именно в
    Windows PowerShell 5.1 в GitHub Actions ДО сборки и упаковки APK.
  - Файл Run-Paseka-Tests.ps1 сохраняется с UTF-8 BOM.
  - Если старый ZIP сообщает ParserError, не исправляйте файл вручную;
    используйте новую проверенную сборку и отдельную распакованную папку.
  - Синтаксическая ошибка не означает неисправность приложения на телефоне.

Перед первым запуском:
  1. На телефоне: Настройки > Для разработчиков > Отладка по USB — включить.
     На некоторых телефонах сначала 7 раз нажмите «Номер сборки».
  2. Подсоединить телефон к Windows 11 кабелем USB с передачей данных.
  3. Разрешить отладку для этого компьютера на экране телефона.
  4. Распаковать весь ZIP в отдельную папку; дважды нажать START-TESTS.cmd.

Сценарий самостоятельно:
  - проверит SHA-256 тестовой APK;
  - найдёт ровно одно авторизованное USB-устройство;
  - проверит Android 15 (SDK 35) или новее;
  - установит только уникальный тестовый пакет, записанный в device-package.txt;
    каждая новая CI-сборка получает собственный package ID;
    ранее установленные тестовые APK и их данные не затрагиваются;
  - проверит карточки ульев и операции архива на фиктивных данных в
    настоящем Android WebView + IndexedDB;
  - создаст уникальный ТЕСТОВЫЙ архив в Android Downloads/Пасека,
    прочитает его через Android MediaStore, сверит размер и SHA-256,
    затем удалит только при полном совпадении всех проверок.
    Если проверка или удаление не прошли, в Downloads может остаться
    тестовый файл с датой в диапазоне 2080–2099. Не удаляйте другие архивы!;

  - перезапустит тестовую APK для проверки сохранности данных;
  - сохранит report.json, before-restart.png и after-restart.png
    в подпапке reports/<дата-время>.

После завершения отправьте в ChatGPT файлы report.json и before-restart.png.
Реальное приложение ru.paseka.journal и его база НЕ затрагиваются.
Сценарий не очищает данные приложений, не отключает интернет, не
отправляет отчёт во внешние сервисы и не удаляет пользовательские файлы.

Ограничения: штатный выбор файла через Android file picker, работа при отключённой сети
и субъективная читаемость экрана НЕ считаются пройденными испытаниями.

Если Windows не видит телефон:
  - проверьте передачу данных по USB и разрешение отладки;
  - откройте Диспетчер устройств и проверьте драйвер Android ADB;
  - после установки драйвера запустите сценарий повторно.
  - если на телефоне Android ниже 15, APK не подходит: ничего не удаляйте.

Безопасность: приложение устанавливается с другим идентификатором,
не заменяет основную «Пасеку» и использует отдельные тестовые базы.
Открытый код доступен в GitHub Draft PR для аудита.


ВАЖНО: если предыдущая сборка завершилась INSTALL_FAILED_UPDATE_INCOMPATIBLE,
не нужно удалять старое тестовое приложение. Новый комплект с собственным
package ID устанавливается рядом и не трогает уже существующие данные.
Повторно используйте ZIP именно этого запуска Actions, а не старый архив.


БЕЗОПАСНАЯ ОТЛАДКА ЧЕРЕЗ WI-FI (ANDROID 15+)
  - USB является основным и предпочтительным подключением.
  - Сопряжение Wi-Fi выполняется один раз вручную на OnePlus:
    Настройки > Для разработчиков > Беспроводная отладка >
    «Сопрячь устройство с помощью кода сопряжения».
    Компьютер и телефон должны находиться в доверенной локальной сети.
  - На компьютере откройте PowerShell в папке ZIP-комплекта и выполните
    .\platform-tools\adb.exe pair <IP:порт_сопряжения>
    Введите одноразовый код с экрана телефона. Не отправляйте код в чат.
  - Затем в разделе «Беспроводная отладка» найдите ДРУГОЙ IP:порт
    для подключения устройства (не порт сопряжения) и задайте:
    $env:PASEKA_ADB_WIFI_ENDPOINT = '192.168.1.42:37123'
    Вместо примера укажите настоящий частный IPv4:порт телефона.
    Запустите .\START-TESTS.cmd из этого окна PowerShell.
  - Этот параметр действует только в текущем окне PowerShell.
    Не храните IP/порт и данные сопряжения в репозитории.
  - При наличии одного USB и одновременно Wi-Fi выбирается USB.
    Без USB Wi-Fi используется только если адрес указан явно и
    точь-в-точь присутствует в списке авторизованных ADB-устройств.
  - Разрешены только частные IPv4 10.x.x.x, 172.16–31.x.x, 192.168.x.x.
    Публичные адреса, неизвестные устройства и несколько USB блокируются.
  - Сценарий не включает старый режим adb tcpip, не отключает Wi-Fi,
    не удаляет приложения и не сканирует локальную сеть.
  - После первой настройки при повторном подключении может понадобиться
    обновить адрес/порт: Android может менять порт Wireless debugging.
  - Для первого физического испытания используйте USB; Wi-Fi применяйте
    как резервный вариант после подтверждённого сопряжения.

ПОДГОТОВКА ЛОКАЛЬНОГО ЗАПУСКА ПО РАСПИСАНИЮ (НЕ АКТИВИРОВАНО)
  - В комплект добавлены Run-Local-Scheduled.ps1 и
    Register-Local-Scheduled.ps1. Они НЕ создают задачу автоматически.
  - Для каждого нового ZIP сначала обязательно выполнить обычный
    ручной START-TESTS.cmd и получить 8/8 PASS в его собственной папке
    reports. Нельзя использовать отчёт от другого APK/package.
  - Run-Local-Scheduled.ps1 по умолчанию только проверяет комплект:
      powershell.exe -NoProfile -ExecutionPolicy Bypass -File
        .\Run-Local-Scheduled.ps1
    При успехе: DRY RUN; Android не затрагивается.
  - Он проверяет идентификатор test-only APK, SHA-256 локального APK
    и ранее сохранённый 8/8 PASS именно для этого пакета.
    При отсутствии/изменении APK или отчёта запуск блокируется.
  - Для настоящего повтора уже установленного тестового приложения:
      powershell.exe -NoProfile -ExecutionPolicy Bypass -File
        .\Run-Local-Scheduled.ps1 -Run
    Выполнение допускается только после подтверждённого ручного PASS.
    Запускается уже существующий изолированный Android package.
    НЕТ новой установки, переустановки, удаления и очистки данных.
  - После достаточной проверки и отдельного решения о времени можно
    предварительно посмотреть настройку задания, например в 20:30:
      powershell.exe -NoProfile -ExecutionPolicy Bypass -File
        .\Register-Local-Scheduled.ps1 -DailyAt 20:30
    Это только PREVIEW; реальная задача не создаётся.
  - Реальное создание задачи возможно ТОЛЬКО с явным ключом -Install.
    Оно не выполняется CI, ChatGPT и автоматически после скачивания.
    Задача работает без повышения прав и только пока пользователь
    вошёл в Windows. Ранее зарегистрированную задачу не перезаписывает.
  - Задача запускается ежедневно в выбранное время. Телефон должен
    быть физически подключён по разрешённому USB и доступен ADB.
    Для планового запуска Wi-Fi отключён намеренно: pairing и порт
    не сохраняются в задании. Неизвестные APK не загружаются.
  - Результаты остаются только локально в reports. Они НЕ отправляются
    в GitHub, ChatGPT или другие сервисы. При отключённом телефоне
    тест завершается FAIL, пользовательские данные не трогаются.
  - Для остановки расписания отключите или удалите задачу
    Paseka-Local-Android-Selftest через «Планировщик заданий» Windows.
  - Регистрация может требовать разрешения текущей Windows-учётной
    записи; скрипт никогда не запрашивает и не хранит пароль.
  - Эта опция ещё не проверена на реальном пользовательском Windows 11.
    Не включайте расписание до проверки нового ZIP и одобрения режима.

РУЧНАЯ ОФЛАЙН-ПРОВЕРКА ПОЛНОГО АРХИВА — ТОЛЬКО ТЕСТОВАЯ APK
  - Запуск только через START-OFFLINE-TESTS.cmd. Обычный START-TESTS.cmd
    продолжает выполнять стандартные 9/9 проверок, без смены режима.
  - Сначала выключить вручную на OnePlus Wi-Fi и мобильные данные.
    Скрипт НЕ меняет настройки сети, не включает режим полёта и не
    отключает VPN. Требуется физический USB-кабель с разрешённым ADB.
  - Для дополнительного режима Android Native ConnectivityManager обязан
    подтвердить отсутствие активных сетей с INTERNET capability перед
    экспортом/восстановлением и после настоящего перезапуска приложения.
    Если сеть доступна, проверка останавливается с FAIL, данные не меняются.
  - Сценарий использует ту же изолированную APK, только тестовую IndexedDB,
    искусственный полный архив, preflight/commit/rollback, SHA-256 и Guards.
    Отчёт offline: 8/8 до перезапуска и 11/11 после; поле mode=manual-offline.
  - Включить сеть снова вручную можно только после завершения и сохранения
    отчёта. При FAIL передайте report.json, не удаляйте файлы/приложения.
  - Офлайн-сценарий НЕ проверяет системный native file picker и не
    доказывает офлайн-поведение рабочей production-установки.
  - Никакой Task Scheduler, автообновления, сетевых вызовов к серверу,
    загрузки архивов пользователя или изменений реальной пасеки.
