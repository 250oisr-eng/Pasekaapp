# B01 · OnePlus cold app-private USB backup — инструкция и границы

**Дата:** 26.11.2026. **Статус:** LIMITED_SAFE_DRAFT, физический OnePlus NOT_TESTED. **Назначение:** получить *новый* архив существующего `ru.paseka.journal` v1.0 **без кнопки P0 в старом интерфейсе**, используя ранее наблюдавшийся `adb run-as` (при условии, что он действительно доступен на момент запуска). Это отдельный инструмент, не подменять проверкой уже имеющегося архива из #542.

## Запуск с минимумом действий

1. На Windows-ПК подключить **один** OnePlus через USB, разблокировать его и разрешить USB-отладку для уже доверенного ПК (если Windows/Android запросит). На телефоне **штатно закрыть «Пасеку»**, не стирать данные, не удалять APK и не выполнять принудительную остановку.
2. Из [GitHub Actions одноразового Draft PR](../.github/workflows/b01-oneplus-cold-backup-kit.yml) с успешным CI на текущем SHA скачать `PASEKA-ONEPLUS-USB-COLD-BACKUP-KIT`, распаковать и запустить **`RUN-ONEPLUS-BACKUP.cmd`**.
3. В окне выбрать заранее существующую папку **на доверенном отдельном внешнем накопителе**. Скрипт определит системный `adb.exe` либо `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`. Если ADB не найден — безопасно остановится. Если телефон не авторизован, устройств больше одного, APK не `debuggable`/`run-as` недоступен, процесс не прекращается даже после согласия на остановку, WebView sandbox отсутствует — архив не считается успешным.
4. При успешном холодном TAR-снимке создаются **новые** `PASEKA-ONEPLUS-SANDBOX-<random>.tar` и `...json` с SHA-256, размером, количеством TAR-записей и отметкой, найден ли путь IndexedDB. Название файлов — только на ПК. Архив может содержать **секреты/частные записи**; хранить конфиденциально, по возможности на шифрованном накопителе. Не загружать TAR в чат/GitHub.
5. Выходное `APP_PRIVATE_COLD_TAR_ARCHIVED_RESTORE_NOT_TESTED` означает лишь созданный неперезаписанный файл из остановленного app-private sandbox с проверенной TAR-структурой и hash. **НЕ** доказательство согласованного LevelDB runtime restore, MediaStore/Gallery полноты, долгосрочной стабильности и независимого физического восстановления.

## Повторный аппаратный результат — процесс Paseka остаётся активным

Пользователь **два раза** выполнил запуск Windows-набора с одинаковым `Failure code: APP_MUST_BE_STOPPED_MANUALLY`, второй раз после рекомендации ручной остановки. Повторять тот же совет больше нецелесообразно. Это **не** доказательство, что процесс нельзя остановить через ADB, и не доказательство порчи базы.

Новое ограниченное действие доступно в Windows-наборе: **отдельное диалоговое согласие**, по умолчанию **No**, на однократное `adb -s <selected-device> shell am force-stop ru.paseka.journal`, **только** если `pidof`/список процессов обнаружили активное приложение. Перед согласованием все изменённые записи/видео необходимо сохранить; остановка процесса может прервать несохранённую работу. После согласия код повторно проверяет `pidof` и `ps -A -o NAME`, ждёт 1,3 секунды, проверяет снова, и ещё раз проверяет после завершения TAR. Если процесс перезапустился — `BLOCKED`, непроверенный локальный файл остаётся `.partial`. При отсутствии процесса ADB `force-stop` **не вызывается**, даже когда разрешён опцией.

**Не вызываются** `pm clear`, `install`, `uninstall`, `rm`, изменение настроек/данных. В JSON `deviceForcedStopped` показывает фактический факт остановки, а не всегда `false`. Никакая операция не снимает блокировку независимого восстановления Android, Gallery/MediaStore и запрет удаления видео. Прежний ZIP без окна согласия устарел. Перед запуском требуется ZIP с успешным exact-SHA CI. Это явное подтверждение пользователя **в локальном окне**, а не неявное полномочие чата остановить программу.

## Исправление Windows-отказа от реального запуска (26.11.2026)

Фактический первый запуск на пользовательском Windows завершился `BLOCKED / DEVICE_BACKUP_BLOCKED` и дополнительным PowerShell `NativeCommandError` при строке `& $node ... 2>&1`. **Архив не подтверждён.** Старый CLI маскировал причину: 0 устройств, несколько устройств, `unauthorized/offline`, недоступный ADB или неканонический путь могли выглядеть одинаково. Исправлена выдача конкретных обезличенных кодов на stdout и удалено перенаправление `2>&1`, которое под `$ErrorActionPreference='Stop'` приводило к неконтролируемому исключению. На Windows сравнение канонических путей не зависит от регистра буквы диска.

**Не использовать прежний ZIP** из Actions #45794712735: он содержит указанный дефект. Скачивать исправленный артефакт только после **SUCCESS** нового Windows workflow на SHA обновлённого PR #543. Если снова `BLOCKED`, достаточно передать **только строку `Failure code:`** — не TAR, путь пользователя и не приватные записи. Никакой `force-stop`, `pm clear`, переустановки или стирания.

## Что инструмент специально НЕ делает

- Не запускает `pm clear`, `install`, `uninstall`, `rm`, `deleteDatabase` и другие команды изменения пользовательских файлов. **Только после явного локального согласия** возможно остановить процесс `ru.paseka.journal` через `adb shell am force-stop`; это не очистка сохранённой базы, но может прервать несохранённую работу.
- Не использует несуществующую кнопку «Полный архив» на установленном OnePlus.
- Не предполагает, что все оригиналы медиа находятся внутри `app_webview`: Gallery/DCIM/Download и app-specific внешние медиа **не входят** в TAR. Обособленный `ru.paseka.journal.disasterproof2` также **не входит** — это другой package.
- Не объявляет `B01-PHYSICAL=PASS`. Для снятия блокировки нужны независимое восстановление в *пустую* Android/WebView среду, контроль реальных восстановленных объектов/Blob, MediaStore/все источники, backup media-copy и контроль подписей.
- Если код возврата 1, никакой факт наличия резервной копии не подтверждён. Если 2 — существует **только ограниченный sandbox-снимок**. Нет кода выхода 0 для полного B01.

## Технический контракт F0–F3

| Зависимость | Проверка | STOP |
|---|---|---|
| Настоящее устройство | ADB один `device`, без `unauthorized/offline` | любая неоднозначность |
| Installed package | `run-as ru.paseka.journal pwd` и `ls -ld app_webview` | `run-as` недоступен |
| Согласованность snapshot | `pidof` и `ps -A -o NAME` до и после, APP должна быть остановлена вручную; `tar` exit 0 | живой процесс/ошибка/изменение во время TAR |
| Приватные данные | `adb exec-out run-as ru.paseka.journal tar -cf - .` только чтение | слишком большой, пустой, неполный TAR |
| Копия на ПК | `wx` (исключить overwrite), SHA-256 во время потока, fsync, `tar -tf` и независимый повторный SHA-256 с диска | нет места, выход ADB != 0, невалидный TAR |
| Rollback | файлы `.partial` сохраняются как непроверенный вывод; телефон не тронут | при ошибке не удалять оригиналы |
| Миграции | архив — исходные файлы APK v1.0, без преобразования схемы | **нельзя** распаковывать поверх действующей базы |

**F2 = LIMITED_SAFE_DRAFT:** Android 16/OnePlus NE2213 и `run-as` ранее сообщались, но реальный текущий ADB, установленный signer, аппаратный TAR, независимый restart/restore и доверенность USB-накопителя не проверены из облака. Требуется один физический запуск на уже подключённом ПК — без установки приложения на телефон. В случае `RUN_AS_UNAVAILABLE` не пытаться `adb root`/factory reset; сохранить отчёт блокировки и искать отдельно санкционированный экспорт из установленной версии.

**F4–F5:** отдельные тесты имитируют запуск ADB, TAR, SHA, run-as denial, несколько устройств и оба вида живых процессов. Не сравнивать результат synthetic тестов с реальным физическим доказательством. **F6–F7:** Draft PR, не merge и не deploy; изолированный физический план после архивирования.
