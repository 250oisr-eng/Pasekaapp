# Контракт проверки составных событий у летка — только синтетическая подготовка

Дата: 2026-11-21. Статус: **синтетический контракт; независимая оценка реальных видео заблокирована**.

## Проверенные открытые источники

- Nieves-Rivera, Lluberes-Contreras, Mégret (2026), *The Relevance of Compound Events in Bee Traffic Monitoring*, DOI https://doi.org/10.3390/informatics13050065, разделы 3.4.1, 3.5.1, 4.2.
- Авторский публичный репозиторий https://github.com/lablluberes/beeClassificationMethods, immutable commit 295948bb398054684b7b92c18b7bb44ba37566af, README и две CSV; подробный SHA-аудит в docs/VIDEO-EXTERNAL-MANUAL-BEE-EVENT-LABELS-RESEARCH.md.
- По статье: 1690 сырьевых треков объединены по окну 5 с, описано 1421 событие после кластеризации, а далее 1194 вручную размеченных и очищенных события. По публичным CSV — **1422 строки в каждой**, 177 разных меток по group_id. Это нерешённое расхождение, а не основание самостоятельно выбирать 1194.
- Статья прямо указывает **качественные**, а не воспроизводимые по идентификаторам критерии исключения: неправильно помеченные пчёлы (tagging) и ошибки tracking. При спорной траектории авторы просматривали исходное видео. НЕТ авторского финального перечня group_id/eventid или проверенного алгоритма фильтрации 1422 → 1194.
- Статья различает entering, exiting, entering-exiting, exiting-entering; развороты составляют 374 из опубликованных 1194. Метод THRS_BIDIRECTIONAL верно классифицировал 370 из 374 compound в **собственном** эксперименте авторов; это **не точность детектора «Пасека»**.
- Статья описывает вход как движение вверх по изображению, выход как вниз *для своего положения камеры*. Но README/CSV не дают подтверждённой таблицы соответствия символов D/U/DU/UD четырём названиям классов с привязкой к физическому летку.
- Отдельная лицензия для CSV, кода и исходных видео не обнаружена; наличие статьи с Open Access не распространяет автоматически разрешения на сторонний GitHub-репозиторий. Исходных MP4 и их SHA256 там нет. Письмо авторам отправлено 2026-11-21; ответ и разрешения на момент проверки отсутствуют.

## Синтетическая семантика (не интерпретация D/U/DU/UD)

Контракт в tools/bee_event_semantics_contract.py работает только с собственными вымышленными событиями, чьи **семантические** классы и стороны уже заданы. Он не читает авторские CSV, видео, пользовательские данные и не запускает detector/tracker.

| Семантический класс | Начало | Конец | Изменение стороны (net) |
| --- | --- | --- | ---: |
| entering | outside | inside | +1 |
| exiting | inside | outside | -1 |
| entering-exiting | outside | outside | 0 |
| exiting-entering | inside | inside | 0 |
| unknown | unknown | unknown | неопределено |

Для разворотов **net=0 не доказывает число фактических пересечений линии летка**: перед возвращением могла быть или не быть пройдена физическая граница. Поэтому поля physicalEntranceCrossings и physicalExitCrossings всегда равны null. Не смешивать подсчёт завершённых смен стороны, число попыток и количество фактических пересечений. При unknown итоговый totalNetDelta=null, хотя knownSemanticNetDelta остаётся диагностическим числом.

Функция принципиально отвергает сырые D/U/DU/UD/x и не разрешает вход с объявленным источником published_csv. Это защита от случайного применения, **не криптографическая проверка происхождения**. Для настоящих данных потребуется отдельный проверенный адаптер и физическая калибровка линии летка. Ни тест, ни флаг syntheticOnly не доказывают реальный результат.

## Контрольный список для открытия независимого теста

1. Получить явную письменную лицензию/разрешение на конкретную версию **CSV, кода и видео** для независимого теста и предполагаемого обучения/распространения. Сохранить URL/текст и дату подтверждения.
2. Получить авторский codebook D/U/DU/UD и семантику x/пустого значения и флагов качества; проверить ориентацию камеры и соответствие физической линии летка.
3. Получить точный authoritative manifest **1194 уникальных group_id/eventid** и проверяемый фильтр/обоснование каждой исключённой записи; согласовать, какая из двух CSV финальная. Проверить совпадение 374 compound с опубликованной статистикой.
4. Получить исходные MP4, source SHA256 и стабильную привязку event↔video↔время; отдельно доказать независимость train/test по видеосессиям, ульям и сериям, не только именам файлов.
5. Разработать офлайн evaluator, который отдельно считает простые события, развороты, неопределённые случаи, net изменения стороны и физические пересечения по **реально калиброванной** линии. Сначала оценить GT и видео, потом выход настоящего детектора с TP/FP/FN/ID-switch.
6. Проверить веса/лицензии модели, on-device Android, потребление памяти и обработку неполных треков. До этого realDatasetBenchmarkAuthorized=false, measuredDetectorAccuracy=null и videoCleanupAuthorized=false.

## Изоляция и тесты

- Новый файл: tools/bee_event_semantics_contract.py (стандартная библиотека Python, без сети).
- Регрессия: tests/test_bee_event_semantics_contract.py — синтетические вход/выход, оба разворота, unknown, дубликаты, неверные стороны и сырые буквы.
- CI: .github/workflows/test-bee-event-semantics-contract.yml.
- Изменения **не затрагивают** JS-приложение, IndexedDB, backup, offline Service Worker, Android-сборку, production и оригинальные медиа. Никакая очистка видео не включена. Оригиналы пользовательского видео сохраняются до **фактически подтверждённого распознавания**, после чего правило их удаления должно применяться только через отдельно проверенный безопасный runtime-процесс.
