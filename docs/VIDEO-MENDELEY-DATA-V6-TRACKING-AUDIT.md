# Модельный датасет летка: отличия Mendeley v5 и v6

Дата сверки: 2026-11-20. Режим: **публичные карточки исследовательского источника**, без скачивания архивов.

## Версии и проверенные публичные заявления

Исходный проект: `8gb9r2yhfc` (Tomyslav Sledevic / Vilniaus Gedimino Technikos Universitetas, Литва). Ссылка сравнения: https://data.mendeley.com/datasets/compare/8gb9r2yhfc

| Атрибут | Версия v5 (doi:10.17632/8gb9r2yhfc.5) | Версия v6 (doi:10.17632/8gb9r2yhfc.6) |
|---|---|---|
| Категории | Detection / pose / segmentation | Detection / pose / segmentation + tracking / behavior + ramp |
| Detection | 7200 кадров, 8 летков, 1920×1080, YOLO bbox | Те же 7200 кадров согласно публичной карточке |
| Pose | 400 кадров, 50 на улей, 2 ключевые точки (голова/задняя часть) | Формат pose сохранён согласно карточке |
| Segmentation | 2300 вырезанных изображений | 2300 |
| Tracking | Не заявлен в v5 | **17 162 трека, 21 946 кадров** в исходных аннотированных MP4 |
| Behavior | Не заявлен в v5 | Метки: foraging, defense, fanning, washboarding |
| Ramp | Не заявлен в v5 | 156 изображений с 4 точками |
| Лицензия карточки датасета | CC BY 4.0 | CC BY 4.0 |

v6 tracking имеет поля `frame-id, track-id, bb-left, bb-top, bb-width, bb-height` (bbox нормализован по кадру); behavior добавляет `class-for, class-def, class-fan, class-wash`. Это **не готовая разметка количества входящих/выходящих через пользовательскую линию летка**. Смысл границы, схема аннотаций и алгоритм подсчёта проверяются отдельно.

## Лицензии и ограничения — принципиально не смешивать

1. Карточка набора данных v5/v6 заявляет **CC BY 4.0**; научная статья https://pmc.ncbi.nlm.nih.gov/articles/PMC10831503/ имеет **CC BY-NC-ND**. Это разные объекты авторского права. Не приписывать лицензии статьи архиву и наоборот. Перед training проверить реальные notices/README/архивные файлы и условия корректной атрибуции авторов.
2. Аннотации могли быть частично подготовлены с использованием YOLOv8 и проверены вручную (согласно статье). Этот факт **не** утверждает права на любые YOLOv8 веса или использование их в приложении; их не скачивать.
3. Изображения и треки v6 нельзя считать независимо проверенными до чтения оригинальных файлов, фиксации SHA-256 и проверки целостности разметки.
4. Набор содержит кадры/треки одной серии съёмок восьми ульев. Разбивать по кадрам **нельзя**: отделять целые исходные ролики, ульи, дни/сессии; тест должен оставаться независимым. Для демонстрации используемые метаданные остаются self-reported без верификации оригиналов.
5. Специфичный вид летков, ракурс камеры (около 30 см сверху) и световые условия Литвы могут не совпадать с пользовательским ульем и телефоном; обязательна отдельная полевая валидация.

## Реальный следующий этап

- Получить только разрешённые публичные архивы (без частных видео) и сохранить исходные zip/readme/licenses с file SHA-256, версией v6 и атрибуцией.
- Проверить фактическую структуру файлов и формат detection/pose/tracking/behavior. До этого **не выдумывать пути/имена файлов и не реализовывать импорт под предполагаемый формат**.
- Сформировать holdout по независимым исходным роликам и ульям; начать с detection YOLOX training-from-scratch. Измерить precision/recall не только на источнике, но на других условиях.
- В отдельном эксперименте использовать tracking v6 для ID switch / потерь треков и поведения; собственные правила пересечения летка требуют подтверждённой геометрии.
- Только после получения реальных разрешённых весов + ONNX + Android offline inference разрешать интеграцию model adapter. ledger completion и удаление оригинала остаются закрытыми.

Этот документ не подтверждает получение архива, обученную модель, оценку accuracy, Android запуск или cleanup.

Авторские ID позволяют сравнивать ассоциацию рамок по времени; в шести полях отсутствуют события входа/выхода и калиброванная линия их пересечения. Данный этап не измеряет качество детектора и не разрешает удалять видео. Источник — Tomyslav Sledevic, [Mendeley Data v6](https://data.mendeley.com/datasets/8gb9r2yhfc/6), CC BY 4.0.
