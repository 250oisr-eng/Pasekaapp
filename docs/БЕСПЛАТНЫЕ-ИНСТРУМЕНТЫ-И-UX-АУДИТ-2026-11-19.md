# Бесплатные инструменты и UX-аудит «Пасеки» — 19.11.2026

## Назначение и границы

Цель — повысить проверяемость интерфейса на смартфонах/ПК без платных сервисов, без переносов пользовательских данных, без изменения физических моделей ульев и без подмены технологических правил.

Этот документ разделяет **реализованные автоматические проверки**, **подтверждённые инструменты** и **предложения**, требующие отдельной реализации и проверки. Числовые параметры техпроцесса из него не выводятся.

## Проверенные бесплатные инструменты

| Инструмент | Бесплатная часть и лицензия | Применение | Риск / ограничение |
|---|---|---|---|
| Playwright (https://playwright.dev/docs/intro, https://www.npmjs.com/package/playwright) | Open source Apache-2.0, версия 1.65.1 проверена на npm 19.11.2026 | Headless Chromium, mobile/desktop viewport, навигация, скриншоты | Эмуляция экрана **не** равна физическому телефону; нет проверки реальной IndexedDB после обновления APK |
| axe-core + @axe-core/playwright (https://www.deque.com/axe/axe-core/, https://www.npmjs.com/package/@axe-core/playwright) | Open source MPL-2.0, @axe-core/playwright 4.14.0 | Ошибки доступности и HTML-ARIA на локальном интерфейсе | Не все WCAG-ошибки обнаруживаются автоматически; результаты требуют ручной оценки; **не** использовать платные axe DevTools |
| Lighthouse (https://developer.chrome.com/docs/lighthouse/overview) | Open source в Chrome DevTools и CLI | Производительность, производственный контроль Core Web Vitals после UI-стабилизации | Результаты относительны к тестовой среде; браузерный отчёт не заменяет физический Android, добавить отдельным этапом |
| GitHub Actions standard public runners (https://docs.github.com/en/actions/concepts/billing-and-usage) | Бесплатны для публичных репозиториев на стандартных раннерах | Запуск браузерных и текущих Node/Android тестов | Не включать larger runners и сторонние платные marketplace actions; учитывать сроки хранения артефактов |

Облачный внешний платный ИИ/файловый сервис не требуется. Установочные версии в новом workflow зафиксированы явно, без `latest`. В ветке нет секретов и outbound API из приложения; тестовые браузерные запросы разрешены только к `127.0.0.1`.

## Реализованный пилот (отдельный Draft PR)

- `tests/browser-ui-smoke.mjs`: запускает встроенный Node HTTP-сервер строго на loopback, разрешает только UI/JS/PWA-ресурсы репозитория, работает в новых пустых браузерных контекстах; внешние запросы блокируются.
- Четыре геометрии: 360×780, 390×844, 800×390 (альбомная), 1280×800.
- Проверяет открытие пустой главной страницы, переключение на «Ульи» и «Журнал» и возврат к обзору без сохранения записей.
- Формирует `test-results/ui-audit/report.json` и снимки экранов; axe-core собирает нарушения WCAG **как диагностический отчёт**, не как автоматическую оценку безопасности.
- `.github/workflows/ui-browser-audit.yml`: отдельный пилотный GitHub Actions workflow, только на выбранной ветке и вручную; публикация приложения, запись в production, загрузка APK или изменение живой базы **не выполняются**.

Точные SHA, результаты CI и артефакты фиксируются в `PROJECT_STATUS.md` по мере проверки. Нельзя считать пилот пройденным до зелёного workflow и просмотра его отчёта.

## Предлагаемые улучшения интерфейса (пока **не** внедрены)

1. **Режим «Работа на пасеке»** с крупными целями касания и быстрыми действиями «Осмотр», «Записать действие», «Список дел»; подтверждение результата отдельно от открытия формы. Сначала провести UX-тест на 360/390 px. **Не** менять модель операций и не подтверждать технологические действия автоматически.
2. **Контроль внимания без выдуманных выводов**: на главной различать «требует проверки», «запланировано» и «подтверждено выполненным», выводить источник и время последнего фактического наблюдения. Не превращать дату или прогноз в свершившийся факт.
3. **Явное состояние локального хранения и резервной копии**: показывать, какие данные хранятся только на устройстве; дату **проверенного** архива, статус экспортирования и рекомендацию проверить файл на другом носителе. Нельзя утверждать, что архив существует, без подтверждённой записи.
4. **Профили и физическая модель**: перед любыми новыми формами/кнопками нового многоматочного профиля сначала матрица поддержки по секциям, корпусам, инвентарю, осмотрам, операциям, зимовке и восстановлению. По умолчанию неподдерживаемые действия должны оставаться недоступны, а не имитировать Фаррар.
5. **Голос в условиях отсутствия сети**: сперва отдельные подтверждённые события из локальной диктовки/ручного ввода, затем (после проверки устройства) офлайн-распознавание и локальные валидаторы. ИИ-подсказки не должны иметь прямого доступа к критическим изменениям базы.

## Процесс разработки: следующие независимые стадии

- A. Пилот read-only UI-аудита (этот PR) — отчёт, скриншоты, отсутствие записи пользовательских данных, 4 viewport.
- B. Исправить **конкретные** найденные нарушения читаемости/доступности отдельным малым PR; добавить тест до изменения поведения UI.
- C. Проверить PWA при реальном отключении сети и возврате подключения на изолированной пустой базе; не путать с эмуляцией mobile viewport.
- D. Добавить браузерную проверку безопасного открытия/закрытия форм без записи, затем только подтверждённые операции с тестовыми фикстурами.
- E. Приоритетно закрыть физический отчёт Android из цепочки #186 до каких-либо объединений; не создавать ложную уверенность от зелёного browser CI.

Правила GitHub неизменны: только ветка и Draft PR, никаких merge, deployment, production-операций и удаления данных без отдельного согласия.
