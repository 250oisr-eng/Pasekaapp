# Сверка 96 пар с каталогом Mendeley v6

Источник — Tomyslav Sledevic, Mendeley Data v6, CC BY 4.0. Каталог detection включает 7200 кадров. Данная проверка касается 96 JPG и 96 TXT из реестра Work. [Страница набора](https://data.mendeley.com/datasets/8gb9r2yhfc/6).

## Что удалось подтвердить

Дерево папок версии 6 и 16 списков файлов издателя связывают каждый UUID с именем, папкой detection нужной серии, типом images/labels, идентификатором содержимого, длиной и SHA‑256. Все 192 первичные контрольные суммы совпали с каталогом издателя. Первичный проход проверил разметку 93 пар (557 рамок). У трёх остальных TXT координаты рамки вышли за границу изображения при строгом допуске действующего валидатора. Эти три файла также совпадают с издательскими SHA.

| Свидетельство повторного чтения из #290 | Результат |
|---|---|
| Пары, где оба сохранённых хеша непосредственно подтверждают совпадение | 42 |
| Дополнительные совпадения пар по результату сравнения при повторной попытке | 5 |
| Пары хотя бы с одним зафиксированным расхождением | 48 |
| Пары с незавершённой проверкой | 1 |
| Первые повторные чтения отдельных файлов относительно издательского SHA | 107 совпадений, 72 расхождения, у 13 отсутствует сохранённый SHA |

Все 31 ответа с несовпавшим SHA для JPEG также не прошли полное декодирование. При дополнительной попытке 27 из них прошли декодирование и совпали по SHA. Для TXT есть 41 сохранённый несовпавший хеш и семь расхождений, зафиксированных только результатом дополнительного сравнения. Источник изменчивых ответов остаётся неизвестным. Для последующих загрузок сверять длину и SHA с версионным каталогом до использования данных; сохранять результаты декодирования JPEG и проверки геометрии YOLO отдельно.

## Как воспроизвести

Из корня рабочей ветки с установленным Pillow:

```sh
python tools/compare_mendeley_v6_publisher_checksums.py
python tools/audit_mendeley_v6_work_replay.py
```

Первая команда связывает публичный UUID и имя из исходных CSV с метаданными в `tests/fixtures/mendeley-v6-publisher-checksums.csv`, затем сравнивает фактически сохранённые хеши. Вторая разбирает результаты отдельных попыток из #290. Обе выполняются офлайн. SHA‑256 издательского CSV в этой контрольной точке — `30f769a438879adda1f1bcd8669fcdc1c293be8ce2769e29387087985b09c7be`.

Для независимого повторения сбора использовать публичный маршрут `https://data.mendeley.com/public-api/datasets/8gb9r2yhfc/folders/6` и списки `/public-api/datasets/8gb9r2yhfc/files?folder_id=<folder_uuid>&version=6&$start=<offset>&$limit=1000` того же домена. Начать с detection и выбрать images/labels в каждой из восьми серий. Порядок формирования CSV описан в `tools/collect_mendeley_v6_publisher_checksums.py`. Сохранённая таблица содержит идентификаторы, размеры и хеши. Ссылки с ограниченным сроком действия в репозиторий не входят.

## Происхождение кадров

В каталоге tracking_and_behavior перечислены 20 файлов: пять MP4 и по пять TXT с зонами, треками и поведением. У трёх MP4 префиксы имён совпадают с сериями detection; в названиях есть суффиксы def/fan. На просмотренных страницах каталога таблицы соответствия detection JPG, UUID записи и номера кадра не обнаружено. Имена файлов сами по себе не устанавливают это соответствие.

Авторы описывают извлечение изображений из записей 1920×1080 при 50 кадрах/с и связь JPG с одноимённым TXT. В описании набора и рассмотренных публикациях отсутствует подтверждённое правило перевода суффикса имени JPG в индекс кадра конкретного видео. Поле frame-id в разметке треков относится к её собственной последовательности. [Описание detection, 2024](https://doi.org/10.1016/j.dib.2024.110060) · [Исследование поведения, 2025](https://doi.org/10.1371/journal.pone.0318401).

Следующий критерий готовности — подтверждённая по источнику связь конкретного JPG с оригинальной записью и кадром, затем проверка независимости контрольных записей. Результаты исследования не разрешают обучение, распознавание на телефоне или удаление видео.
