## 1. Подтверждённая технология

Первичный пользовательский DOCX «улей для каждого техпроцесс.docx», абзацы P72–P77: альтернативный зимний режим сохраняет три семьи отдельно в колонне 2+1+1 через две сетчатые диафрагмы. После развития семей (не фиксировать примерный срок как DONE) два отдельных однокорпусных отводка ставятся на собственные днища, диафрагмы снимаются; каждой семье даётся второй гнездовой корпус, устанавливаются подкрышники/крышки, восстановленные три семьи обмениваются через технические отверстия. Для раннего медосбора это предшествует установке двух медовых корпусов и двух решёток OP-07.

## 2. F0–F1: технический контракт

- Старт — один зарегистрированный `ALTERNATIVE_WINTERING_COLUMN` 2+1+1, действующий `sectional-multiqueen-v1`, одна активная сезонная запись, valid source layout и полная append-only lineage. Неверная ревизия после другой вкладки/restore — отказ.
- Пчеловод вручную назначает исходные три familyId в позиции left/middle/right; сильная семья сохраняет два своих корпуса и прежнее дно/stackId, две слабые сохраняют по своему корпусу и берут ровно по одному реальному складскому корпусу с полным регистром 6 рамок. Выбранный порядок нижний/верхний явно задан, не выводится из дат.
- Каждая из трёх семей получает собственные реальное дно, крышку, подкрышник и ID стопки; кормушка необязательна и может быть назначена лишь одна и лишь по существующему inventory ID. Нельзя повторно использовать аксессуар.
- Для `SIDE_BY_SIDE` обязательны 8 фактических технических openingId, по 1 отверстию на каждый боковой корпус и по 2 на каждый центральный. Пользователь вводит реальные openingId и наблюдавшийся диаметр (доменная модель требует 50 мм), выбирает отдельную физически зарегистрированную складскую `technicalQueenExcluder` для каждого отверстия. Известные source openingId должны сохраняться, неизвестные ID новых складских корпусов требуют отдельного визуального/личного подтверждения и остаются предметом физической приёмки.
- `technicalConnections` связывает left↔middle и middle↔right с двумя рядами и подтверждённым буфером. `meshDiaphragms` снимаются только с явно указанными местами хранения. Иные незарегистрированные предметы/корпуса блокируются.
- `prepare/plan` создают предварительный манифест из точных ID; физический `PasekaSectionalSeasonPhysicalManifestV2.plan` определяет изменения и требует индивидуальные подтверждения; CAS, IndexedDB, DONE, запись маток и удаление видео не вызываются. Явное отсутствие буфера устройства/архива не маскируется.
