# P1 — OP-11: пошаговая сборка трёх верхних корпусов в зимнюю колонну

Дата: 24 ноября 2026. Stacked Draft #461, основан на Draft #460; main и production не меняются.

## F0 — факты и источник

- Первоисточник: пользовательский «улей для каждого техпроцесс.docx», раздел обычного осеннего объединения: убрать медовые корпуса и решётки до этой операции, сохранить три прежних верхних гнездовых корпуса, совместить их на одном дне, убрать остальные три гнездовых корпуса и два лишних дна, закрыть боковые технические отверстия пластиковыми заглушками, сверху установить подкрышник с потолочной кормушкой. Оставшаяся матка **не определяется программно**.
- Порядок трёх сохранённых корпусов не задан как универсальный идентификатор; пользователь выбирает конкретные ID снизу вверх. Нельзя автоматически считать совпадение календарной даты фактом выполнения.
- Только режим `SIDE_BY_SIDE`, ровно 3×2 исходных гнездовых корпуса, активный сезон, правильный sectional profile, подтверждённая ревизия. Нет медового яруса. При неподтверждённом состоянии — отказ.
- OP-11 не задаёт автоматически состояние летков и не подменяет местные требования к зимовке. В дальнейшем проверка летков — отдельный эксплуатационный gate.

## F1 — физический контракт

- `js/sectional-season-op11-guided-v2.js` строит исключительно в памяти `targetLayout` `SINGLE_FAMILY/primary_wintering` с **тремя исходными верхними bodyId** в порядке пользователя. Пластиковая пробка выбирается из реально зарегистрированного склада отдельно для каждого существующего бокового отверстия сохранённых корпусов.
- Обязательно лично назначить оставляемое реальное днище, крышку, подкрышник и потолочную кормушку. Дублированные, чужие и занятые пробки недопустимы.
- Все снятые корпуса и аксессуары требуют реальных складских назначений; каждое изменённое расположение требует отдельной отметки пользователя. При изменении выбора ранее введённые подтверждения сбрасываются.
- Новый внутренний ID объединённой семьи создаётся только для временного предварительного плана. `queenIdentityStatus=unresolved` / `currentQueenId=null`; ИИ не определяет лучшую матку.
- Только `PasekaSectionalSeasonPhysicalManifestV2.plan` и текст предварительной проверки; не вызываются IndexedDB, CAS, DONE, видеораспознавание или удаление. Источник проверяется `PasekaSectionalPhysicalLayout.validate` перед показом формы.
- Поддержка подкрышника в `SINGLE_FAMILY` и `ALTERNATIVE_WINTERING_COLUMN` добавлена в `js/sectional-physical-layout.js` с обязательной проверкой правильного `stackId`, вместо молчаливого игнорирования физического предмета. Existing SIDE_BY_SIDE semantics не изменены.
