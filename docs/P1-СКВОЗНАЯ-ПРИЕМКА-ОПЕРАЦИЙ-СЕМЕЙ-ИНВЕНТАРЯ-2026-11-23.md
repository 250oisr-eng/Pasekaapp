## Сквозные инварианты

1. Источником истины о текущем расположении служат реальные `sectionalLayouts`, `equipmentInventory`, `families`, `queens`, `familyEvents`, `queenEvents`. Нельзя переводить план в физический факт без личных подтверждений.
2. Постоянные `frameId/frameUid/labelCode` при переносе рамки неизменны. Изменение распределения требует явного учёта каждой рамки и её места, сохранения append-only истории, инвентарных и аудиторских событий. При полном шестирачном корпусе нельзя просто добавить две рамки без подтверждённых освобождённых мест.
3. Для OP-06-RESCUE **отдельный operationId**, который не равен OP-06 DONE. Программа проверяет наличие свежих яиц по DOCX P31–P33; пользовательское требование «2 рамки с расплодом» не означает, что любое состояние расплода достаточно для вывода матки.
4. Единственная допустимая физическая запись всех критических изменений: verified preflight → independent externally verified full recovery → staged executor → local physical+lineage+inventory inspectors → optimistic CAS → cold read → доказательство совпадения snapshot и event. При отсутствующем gate операцию не записывать.
5. Сезонный ledger фиксирует rescue как отдельный `STAGE_CONFIRMED` с operationId `OP-06-RESCUE`; он не добавляет OP-06 в `compatProcess` и не означает наличие третьей плодной матки.
6. Отсутствующая подтверждённая реальная копия и полноценная физическая приёмка не заменяются синтетическим тестом. Video cleanup #442 — FROZEN, оригиналы не удалять; main и production-данные не изменять.

## Почему P1 нельзя объявить полностью завершённым

Существует код всех 14 OP, но **не существует подтверждённого полного пользовательского UI→CAS сценария для каждой OP и всех сезонных ветвей**. Отсутствует физическое подтверждение независимого полного архива/восстановления на втором устройстве, реальный OnePlus E2E без сети после перезапуска и совместимости после миграций. Ветка #456 не стирает этот блокер. Выпуск требует отдельно разрешённой последовательной интеграции PR #453 → #454 → #455 → #456, точного финального CI и полноценной фактической приёмки.
