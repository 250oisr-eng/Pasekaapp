# Mendeley v6: подготовка реальной разметки пчёл у летка для будущего обучения

Дата 2026-11-20. Статус: **read-only staging importer + тестовые фикстуры; не обученная модель**.

## 1. Подтверждённый первичный источник

- Публичная версия **6**, DOI `10.17632/8gb9r2yhfc.6`, опубликована 27 августа 2024 года. Карточка Mendeley Data и сравнение версий указывают **Creative Commons Attribution 4.0 International (CC BY 4.0)** на **данные**:
  - https://data.mendeley.com/datasets/8gb9r2yhfc/6
  - https://data.mendeley.com/datasets/compare/8gb9r2yhfc
- Рецензируемое описание данных: Sledevič & Matuzevičius, Data in Brief 52, 110060, https://pmc.ncbi.nlm.nih.gov/articles/PMC10831503/ . **Статья** опубликована под CC BY-NC-ND 4.0 — это не лицензия исходного набора, переносить условия между ними нельзя.
- Отдельная статья о поведении у летка, PLOS ONE 2025, https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0318401, описывает в v6 треки и поведение и даёт прямую ссылку на эту версию.
- На исходных кадрах исследованы **медоносные пчёлы у летков**, не безжальные пчёлы другого вида. Это существенно уменьшает, но не устраняет сдвиг ракурса/освещения относительно будущих видео пользователя.

## 2. Что проверено, а что ещё нет

Проверена **публичная карточка** и изложенная авторами иерархия коллекций. Попытка получить `https://api.data.mendeley.com/datasets/8gb9r2yhfc?version=6` без учётных данных возвращает HTTP **401**; не выполнять обход ограничений и не выдавать несуществующие SHA/список исходных файлов за проверенные. **Ни один реальный JPEG, TXT, MP4 или архив v6 в данном блоке не скачан, не декодирован, не обучен.**

Имена групп — свидетельство опубликованного набора; **не** индивидуальные криптографически удостоверенные исходные видео. То, что фотографии имеют имена одной коллекции, не подтверждает одной физической видеосессии, независимости разных дат или отсутствия повторного использования кадров.

## 3. Локальный конвертер

`tools/prepare_mendeley_v6_yolo_unassigned.py` — строго локальный Python без третьих библиотек. **Ожидаемая локальная форма** после получения настоящих данных:

```
detection/
  _bee_20230609a/
    images/
      <filename>.jpg
    labels/
      <filename>.txt
  ...
```

Официальная публикация подтверждает отдельные подпапки изображений и меток, но их точные **имена** `images` и `labels` на конкретных байтах v6 пока не сверены. При несовпадении реальной структуры код обязан отказать, а не угадывать пути.

Команда после **законного локального получения и проверки структуры**:

```sh
python3 tools/prepare_mendeley_v6_yolo_unassigned.py /path/to/detection /path/outside/unassigned-mendeley-v6.json
```

Проверяет: только восемь опубликованных папок, парность имён image/label, единственный класс `0` (bee), пять нормированных чисел YOLO, `NaN`/Inf/вне рамки, дубли SHA между группами, ограничения размера, JPEG/PNG header (без полного декодирования), реальные SHA-256 image bytes, неизменность оригиналов, отказ от symlink/hardlink и перезаписи выходного файла. Конвертация `(x_center, y_center, width, height)` → COCO bbox в пикселях.

**Не** создаёт train/validation/test, sourceRecordingSha256, треки или направление пересечения. В `info`: `split=unassigned`, `trainingAuthorized=false`, `sourceVideosVerified=false`, `licenseFileRightsAudited=false`. Поле `completeAgainstPublication` — лишь числовая сверка опубликованных количеств, не proof integrity и не разрешение на обучение. `hiveCollectionFolder` хранит имя группы, `sourceRecordingSha256=null`.

## 4. Подготовка настоящего training benchmark — следующий логический блок

1. Получить инвентарь **реальных байтов v6** и сверить license/attribution, точные файлы, SHA, фото/label пары, формат трекинга, исходные видеоклипы и group/session mapping. Правила CC BY 4.0 требуют атрибуции авторов, DOI, ссылки на лицензию и указания изменений при распространении.
2. Выделять holdout **по независимым ульям и съёмкам**, а не по случайным отдельным кадрам. Возможная политика 5/1/2 группы для train/validation/test — только предварительный вариант; фактические видеосессии, объём по условиям погоды и время съёмки требуют проверки. Группа в имени файла не доказывает отсутствия утечки.
3. Оценивать **детекцию** отдельно от pose, tracking и пересечения летка. Учесть классы негативных кадров (нет пчёл), закрытые/частично видимые объекты, высокая плотность, сумерки, блики, тряска, быстрый пролёт.
4. Технический кандидат для обучения **с нуля**: YOLOX-Nano/Tiny, upstream код Apache 2.0 (https://github.com/Megvii-BaseDetection/YOLOX), возможен ONNX export. Перераспространение отдельно загруженных pretrained весов **не подтверждено**. Offline inference-кандидат ONNX Runtime Web WASM (MIT), реальная совместимость Android и FPS неизвестны. Прежде чем ставить зависимости и обучать — отдельно проверить конкретную версию, права на веса/исходный датасет, исполнимость бесплатного обучения.
5. Для подсчёта **прилётов и вылетов** необходима отдельная реальная верификация треков и направленных пересечений физически откалиброванной линии. Счёт обнаруженных рамок не равен числу пересечений. Вызов детектора, даже с идеальным COCO, **не подтверждает распознавание**.
6. Видео пользователя сохраняется до завершённого распознавания; удаление требует независимых evidence ledger, подтверждения обработки, отсутствия пропущенных фрагментов и доказательства всех локальных копий. До этого `recognitionSucceeded=false`, `cleanupAuthorized=false` без исключений. Пользовательские видео в этом шаге не используются.

## 5. Тестирование и обратимость

Только 11 Python unit fixtures с синтетическими JPEG/PNG и YOLO TXT + Node bridge в общем `npm test`. Чужие изображения, исходные видео, приложение, локальная база и Android media не меняются. Тесты не измеряют качество будущей модели.

Это изолированная подготовка реального набора — **не работающий детектор**. Никакого внедрения в UI/Service Worker, миграций или автоматического удаления.
