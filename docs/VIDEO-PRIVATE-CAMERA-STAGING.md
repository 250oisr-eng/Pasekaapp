# Приватная съёмка через браузерную камеру — staging-only (2026-11-20)

Цель: уменьшить риск неконтролируемых внешних копий при выборе `<input type=file capture=environment>` и подготовить путь для видео, которое приложение может контролировать. **Это пока не активировано и не проверено на физическом Android.**

`js/video-private-camera.js` представляет неактивный API `startPrivateCapture`, который в будущем **может вызываться только после явного нажатия кнопки пчеловодом**. Запрашивает видеопоток `getUserMedia` без аудио, предпочитает камеру `environment` и использует `MediaRecorder`; результирующий Blob возвращается исключительно в памяти вызывающего кода. Не вызывает picker/Gallery, не использует MediaStore, не пишет в IndexedDB и не отправляет в сеть. Пока нет UI, не выполняется запрос на камеру.

Технические границы: поддерживаемые MIME только `video/webm`/VP8 и `video/mp4`, максимальный суммарный размер фрагментов 250 MiB, ограничение времени захвата 90 секунд. При stop/ошибке/таймауте камера освобождается вызовом `track.stop()`. При пустом захвате, отсутствии поддержки браузера, отказе пользователя или ошибке MediaRecorder результат fail-closed. Дальнейшее сохранение потребует отдельного существующего `putEntranceVideo` с SHA и валидатора длительности/разрешения; текущий модуль **не записывает видео**. При сбое/аварии браузера память и OS media buffer не гарантируют отсутствие временных служебных копий.

Даже если браузер не вызывает Gallery, это не является аппаратным доказательством отсутствия системного кэша. Возвращается `externalCopiesVerified:false`, `recognitionSucceeded:false`, `cleanupAuthorized:false` — ни один из этих флагов не обходит защищённый `deleteEntranceVideoBlob`.

`tests/video-private-camera.test.mjs` использует тестовые getUserMedia/MediaRecorder и проверяет user opt-in API, получение Blob, закрытие потока, permission denied, unsupported format, empty capture и отсутствие live connection.

Перед возможным включением: физический Android тест разрешений, браузерных MIME, старта/остановки, возврата из background, memory usage и отсутствия Camera/Gallery экспортов; встроить UI с явным подтверждением; добавить fail-safe источник provenance; связать с проверенным распознавателем и защищённым ledger. Удаление разрешать только после отдельного all-copy workflow и тестов.
