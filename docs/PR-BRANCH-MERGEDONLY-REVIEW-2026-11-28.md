# B08 — полная структурная проверка merged-only веток (28.11.2026)

**Тип проверки:** реестр GitHub + pinned Git Compare + выборочная проверка содержимого Git blob. **Не** полный построчный semantic review каждой из 137 веток с уникальными коммитами. **Никаких merge/retarget/close/delete, production, APK/release, изменений пользовательских данных.** Основной исходный SHA: `dcf8a7c519a4ec64e1d2c86a0cfeb72ba3497417`.

## 1. Восстановление точного множества 170

Прежние «170 непроверенных» — разность исторических **176 merged-only** и шести предыдущих точечных сравнений. Для устранения неоднозначности мы повторили сравнение **всех 176**, включая исторические шесть. Это закрывает **метаданные/ancestry** прежнего остатка, **не** означает завершённый semantic review 170 изменений.

Прочитаны GitHub REST с полной пагинацией и завершающими пустыми страницами:
- Открытые PR: **407**, страницы 20×20 + 7 + 0 (и повторная пустая).
- Закрытые PR: **243** = **178 merged / 65 closed-unmerged**, страницы 20×12 + 3 + 0.
- Ветки: **674**, страницы 100×6 + 74 + 0.
- Неиспользуемые открытыми PR ни как head, ни как base: **260**; из них **176 merged-only**, **61 closed-unmerged-only**, **23 без PR**, смешанных состояний нет.
- Повторная веточная пагинация 100×6 + 74 + 0 подтвердила 674 имён и зафиксировала текущие head SHA для 176. Эти SHA получены **после** операций compare, не являются атомарным доказательством SHA каждой ветки в момент сравнения.

**Исходные таблицы:** `PR-BRANCH-LIVE-PAGES-1..5-2026-11-28.json`; `PR-BRANCH-MERGEDONLY-CENSUS-2026-11-28.json`; `PR-BRANCH-MERGEDONLY-HEADS-2026-11-28.json`. Документы в этой ветке являются снимком, не автоматическим live-мониторингом.

## 4. Обнаружен реально отсутствующий в main кандидат — CSV инвентаря

В `main` нет `function inventoryCsvCell`, `function buildInventoryCsv`, `function exportFilteredInventoryCsv`, строки «Скачать CSV по фильтрам»; также отсутствуют `tests/equipment-inventory-csv.test.mjs` и `tests/e2e/inventory-csv.e2e.cjs`. Функция/тесты есть в **открытом Draft #633**, а нужные функции `index.html` **также есть в Draft #647**. Поэтому нельзя ошибочно учитывать #633 среди «176 merged-only», он **open**.

На GitHub снимке:
- **#633:** base=устаревший main `a0e52b83...`, head `2d970d29cab5c48f12eb3cd79f4169433c423a8f`, `mergeable=false`, Android / Chromium E2E / Governance success на этом head (не разрешение на merge).
- **#647:** base=`dcf8a7c...`, head `8a221bc73a09f995cd425250ec41bb53028d5c97`, 32 changed files, `mergeable=true`; 7 PR workflows на этом SHA завершились `success` (Fast, Governance, Android, Journal E2E, отдельные QA-сборки). Это **CI_VERIFIED_EXACT_SHA для перечисленных workflows**, не device proof и не доказательство корректности всех 32 файлов.

**Решение:** основной кандидат на предметное ревью — **#647** с явной проверкой CSV, истории, IndexedDB, Service Worker, а #633 — только исходный Draft для сопоставления реализации. Не сливать #633 параллельно с #647, не создавать третий дублирующий CSV. При обнаружении критических несоответствий #647 — адресный перенос и новые регрессии в независимом Draft, без изменения main.

## 5. Минимальная очередь после аудита

1. **F0–F3 #647**: все 32 файла, контракт текущего `main`, негативные сохранения/откаты, CSV injection, автономность, PWA-cache; проверить runtime и E2E на точном head. Разрешение на merge отдельно, даже при всех CI PASS.
2. **#648 / #651**: обе ветки содержат конкурирующие `index.html`/`sw.js`, GitHub `mergeable=false` на снимке. Сначала установить уникальные изменения по сравнению с #647; никакого автоматического retarget и одновременного изменения storage/schema.
3. **Среди 41 runtime merged-only** — только адресные тесты уникального поведения по выявленным пробелам, не повторная интеграция уже вошедших #623/#627/#649/#609.
4. **B01/B04/B05/B07/#442** не расширять: физический OnePlus, подпись, восстановление, технология и видео живут за отдельными воротами. Не обновлять production и не удалять оригиналы.
5. **39 `ahead=0`** не являются списком для удаления: требуется отрицательное доказательство worktree/automation/внешних ссылок и отдельное управляемое решение; в данном цикле удалений нет.
