## План минимизации интеграционных рисков

1. **Не объединять всё в main автоматически.** Приоритет — доказательство P0 совместимости legacy/v2 state+media. P1 не может разрешать выпуск, если P0 открыт.
2. **Зафиксировать стабильную кодовую точку.** Для каждого кандидата проверить точные base/head SHA, diff относительно актуального main и статус CI на его HEAD; проверять transitive overlap с родителями.
3. **Объединять только логические блоки по одной ветке за раз** и только после отдельного разрешения пользователя. Не считать один Fast/Android CI достаточным для миграций, реальных видео или физического устройства.
4. **Независимые корневые PR не объединять по номеру/дате.** Документы, архив, профили ульев, запись операций, UI, видео и Android тесты имеют разные критерии; сохранять активные пользовательские функции.
5. **Дубли и закрытие.** Фактические дубли определяются по changed files/patch и merge-base, не по одинаковым названиям. До такого сравнения статус кандидатов — UNREVIEWED; массовое закрытие запрещено.
6. **Условия P1.6 READY:** карта зависимостей актуальна, для интеграционной ветки выполнены diff+регрессии+Android checks и есть отдельное разрешение на merge. Сейчас **NOT READY**.
