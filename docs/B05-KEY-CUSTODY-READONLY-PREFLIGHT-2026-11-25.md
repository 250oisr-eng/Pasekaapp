# B05 — проверка сертификата существующего keystore без передачи ключа (25.11.2026)

## F0–F2 и первичный источник
Физическая V5 проверка `apksigner.jar verify` подтвердила сертификат **установленного** `ru.paseka.journal`: SHA-256 `9b10baf04e1e09bfe2d58e72b1c1eecf04b48f532940b5e91a3083bd73ddb0aa`. APK SHA-256 `a6e14157fcdce06885cb8c6a5ad55c8a76170c3fa4cefa234b1715d80865aec6`. Из публичного сертификата нельзя восстановить закрытый ключ; GitHub Android Debug собирается через `assembleDebug` и не подтверждает тот же сертификат. Keystore владельца **не предоставлен**.

F2 — LIMITED_SAFE_DRAFT. Не создавать новый ключ текущего package ID, не сканировать пользовательские диски автоматически, не запрашивать пароли в чат, не подписывать и не устанавливать APK. Без существующего ключа B05 остаётся EXTERNAL_DEPENDENCY.

## Код / наблюдения
- `scripts/check-b05-keytool-certificate.mjs`: ограниченный однократный локальный анализ **только** вывода `keytool -list -v -alias ...`, поданного через stdin. Сравнивает ровно один SHA256 публичного сертификата с физическим V5, требует `Entry type: PrivateKeyEntry`, не возвращает alias, путь, пароль и полный отчёт.
- `MATCHING_PRIVATE_KEY_ENTRY_METADATA_ONLY` означает **только**, что в доступном keystore указан ключевой entry с совпадающим публичным сертификатом. Это не доказывает способность реально подписать APK, доступность пароля приватного ключа, защищённую резервную копию, право установки или успешный upgrade/rollback.
- `trustedCertEntry`, чужой digest, неоднозначный/неполный отчёт — fail-closed. Тесты используют синтетический text; не открывают keystore.
- `.gitignore` исключает локальные keystores, секретные signing configs, .env и диагностические signer JSON. Gitignore **не защищает** уже отслеживаемый секрет и не заменяет ручной контроль перед push.

## Будущий физический тест (только при найденном реальном keystore)
Владелец выполняет локально `keytool -list -v -alias <локальный-алиас> -keystore <локальный-путь>` и передаёт вывод *только в локальный анализатор*, не в чат, GitHub или CI. Путь/пароль/alias остаются на ПК. По умолчанию тест **не требуется**, пока не обнаружен кандидат; если кандидата нет, B05 BLOCKED.

## F5–F7
Пять синтетических негативных/положительных тестов, exact GitHub CI и дальнейшее подтверждение при необходимости. Для полного B05 нужна независимая защищённая копия оригинального ключа, проверяемое подписание отдельного тестового APK тем же сертификатом и потом B01 + rollback; никаких прямых обновлений OnePlus без отдельного разрешения пользователя.
