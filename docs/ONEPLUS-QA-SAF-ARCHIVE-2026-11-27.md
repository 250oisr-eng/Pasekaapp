Дата: 27.11.2026. **F0–F2: LIMITED_SAFE_DRAFT**, начальный main `e5fdb2d295c062795820268b0997ebca01a54fde`.

## Наблюдение и причина

Физический QA цикл 3: пользователь сообщил, что файл `paseka-full-idb-*.json` в загрузках **отсутствует**. Ранее был найден файл ≈330000 байт, и верификатор получил `Unexpected token 'P', "PK"...is not valid JSON`. Без исходного файла нельзя доказать, что это ZIP от GitHub, но **полный внешний JSON архив фактически не подтверждён**. Действующий `downloadDisasterArchive` выполняет `Blob URL + <a download>.click()`, после чего говорит только «Файл подготовлен»; в Android WebView это не даёт подтверждения записи в Downloads. Новый `#617` улучшает диагностику выбранного ZIP, **но не исправляет отсутствие файла**.

## Безопасный дизайн

**Никаких обновлений установленной `ru.paseka.journal.qa`**, поскольку её ephemeral debug signer не позволяет гарантировать совместимость и сохранность искусственных записей. Новый **третий, отдельный пакет**: `ru.paseka.journal.qa.archive`, отображаемое имя «Пасека QA — архив»; исходная QA и рабочая `ru.paseka.journal` остаются независимыми.

В новую QA-сборку только после генерации `www` внедряются:
- `qa/native/qa-saf-export.js`: клиент с кодированием UTF-8 в ограниченные 48KiB чанки, расчётом полного файлового SHA-256 и последовательной отправкой через Capacitor-native bridge.
- `qa/native/PasekaSafExportPlugin.java`: отдельный Android plugin без доступа к IndexedDB/MediaStore. Временный сборный файл сохраняется в **личный QA cache** (не является внешним архивом), контролируется размер/хеш, затем пользователь **сам выбирает цель** в системном `ACTION_CREATE_DOCUMENT`. После копирования plugin **повторно читает содержимое выбранного URI и проверяет длину и SHA-256**. Только после этого UI может сообщить о проверенной передаче. Отмена или несоответствие — fail-closed; возможный частичный файл у провайдера сохранять для диагностики, не делать автоматического удаления.
- `scripts/prepare-android-qa-saf.mjs`: строгая проверка appId, webDir и статических якорей кода, интеграция **только в сгенерированный QA `www` и Android wrapper**. Основной `index.html`, Android production config, формат `js/disaster-archive.js`, OP и IndexedDB не изменяются.
- `.github/workflows/android-qa-saf-archive.yml`: новый отдельный Android 15+ APK с aapt/apksigner/SHA provenance, **без публикации**. Никаких новых Android storage permissions или произвольного доступа к Downloads; используется системный документ-провайдер.

Технический предел прототипа: до 256 MiB полного JSON в QA. Если архив больше, экспорт **отклоняется**, нельзя выдавать частичный результат за полную копию. Доказательство больших архивов с реальными видео не получено; B01 по прежнему BLOCKED.

## F3–F5 / критерии

- Node: fail-closed QA ID, инъекция строго по текущему исходнику, контроль названия, отсутствие сетевых запросов, UTF-8 и пачек, отказ при недостоверном результате; native Android Java compile/build, SAF picker, staging SHA, read-back проверяются компилятором и code-review.
- CI exact SHA: полная регрессия, APK package `ru.paseka.journal.qa.archive`, один signer, SHA, проверка источника. **Это не реальная проверка диалога Android**; физический OnePlus цикл нужен отдельно.
- На телефоне новое QA можно установить **рядом** с прежним QA, не заменяя его. На новом QA нужна небольшая НОВАЯ синтетическая семья/запись; старые записи из `.qa` автоматически не переносятся, не удаляются и не восстанавливаются.
- Физический цикл: открыть «Пасека QA — архив», создать синтетическую запись, «Ещё» → «Резервное копирование» → «Скачать полный архив текущей базы», выбрать «Загрузки» в системном диалоге, проверить файл `paseka-full-idb-*.json` и SHA через read-only приложение, затем вне телефона вторую копию. До пользовательского отчёта `DEVICE_NOT_TESTED`.
