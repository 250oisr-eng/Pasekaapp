# Физическая проверка полного архива schema 16 на Android

## Назначение и безопасность

Проверяется полный цикл `.paseka` export → preflight/staging → commit → rollback для состояния app schema 16, содержащего отдельный список `varroaTreatments`.

- Только изолированное тестовое приложение: package ID `ru.paseka.journal.varroa.test`, название «Пасека — тест Varroa».
- Не устанавливать APK поверх рабочего приложения. Разные package ID позволяют установить тестовую версию отдельно.
- Использовать только созданные в тестовом приложении тестовый улей и тестовое событие. Не импортировать рабочий архив и не вводить реальные данные пасеки.
- Не очищать данные, не удалять приложения test2/test3/test4 и не менять рабочую базу.
- При любой неоднозначности или неожиданном запросе остановить проверку и сообщить, на каком шаге это произошло.

## Последовательность проверки

1. Скачать artifact ZIP со страницы workflow, распаковать и установить APK как отдельное приложение. Убедиться, что название — «Пасека — тест Varroa». Не удалять и не заменять другие версии приложения.
2. Открыть тестовое приложение и создать один тестовый улей.
3. Создать тестовое событие обработки Varroa, указав тестовые дату/время и подтверждение фактического выполнения. Убедиться, что событие появилось в истории обработок.
4. Открыть настройки полного архива и выполнить экспорт `.paseka`. Убедиться, что приложение сообщает об успешном завершении и файл доступен в загрузках/системном выборе файла.
5. Выбрать только что созданный архив для восстановления. Запустить preflight и staging. Проверить, что архив принимается, показывает поддерживаемую схему и не сообщает об ошибке события обработки.
6. До commit убедиться, что тестовый улей и событие по-прежнему видны в исходном состоянии. Выполнить commit только после явного подтверждения в интерфейсе. Убедиться, что тестовый улей и событие обработки остаются в приложении после импорта.
7. Выполнить rollback этой импортированной сессии. Убедиться, что прежнее состояние и событие обработки восстановлены, а использованная точка отката обработана приложением штатно.
8. Создать после commit/восстановления новую тестовую запись (например, ещё одно тестовое событие) и затем попытаться выполнить rollback предыдущего импорта, если интерфейс оставляет такую возможность. Ожидаемый результат: rollback блокируется из-за изменения revision; новая запись остаётся на месте. Не пытаться обходить блокировку.
9. Полностью закрыть приложение, включить авиарежим и открыть его снова. Проверить доступность истории и сохранность тестовых записей офлайн.
10. Сообщить результат: «все проверки прошли» либо номер шага и точный текст ошибки. Не прикладывать реальные данные пасеки.

## Критерий результата

Проверка считается завершённой только после подтверждения всех применимых шагов на физическом Android-устройстве. Успешная CI-сборка и проверка package ID не доказывают фактическую работу MediaStore, импорта, commit или rollback на телефоне.
