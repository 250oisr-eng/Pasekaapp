# #596 — двухрядная навигация: безопасный кандидат Draft #606

**F0–F1 / Источник.** Утверждённые пользователем [принципы эргономики](ПРИНЦИПЫ-ЭРГОНОМИКИ-ИНТЕРФЕЙСА.md) §2/7 требуют визуально двухрядную симметричную нижнюю навигацию, центральный единственный вход ИИ, прямой доступ к разделам, читаемые подписи и безопасные зоны нажатия. [Issue #596](https://github.com/250oisr-eng/Pasekaapp/issues/596) фиксирует конфликт трёхрядной реализации текущего `main=1578fb70b4f14e6fc808f02ccefeaf9fca96d270` с этим правилом. Владелец ещё не утверждал конкретную альтернативную компоновку.

**F2 / Feasibility.** CI Chromium может проверить вычисленную геометрию, клавиатурный порядок и отсутствие перекрытий без личных данных. OnePlus/TalkBack/жесты Android/работа в перчатках не проверены и не заменяются CI. Поэтому допустим LIMITED_SAFE_DRAFT, но не DEVICE_VERIFIED. Изменения IndexedDB, Service Worker, медиа, OP, профилей, ИИ-API и production не требуются.

**F3–F4 / Контракт.** На компактных экранах шесть обычных кнопок размещаются сверху, ещё пять (с ИИ посередине) снизу. Все **11 прямых** маршрутов остались; количество кликов не увеличено, «Ещё» не поглотил другие разделы. CSS grid 12 виртуальных колонок, каждый маршрут span 2, нижний ряд смещён на один виртуальный столбец. Компактные кнопки — скруглённые прямоугольники без hex clip, ≥11 CSS px шрифт, ≥44×44 CSS px hit target. На широком экране (≥700px) и короткой альбомной ориентации — прежняя однорядная схема с сотами. `matchMedia` переставляет **исходные кнопки**, не создаёт дубликатов, восстанавливает фокус и сохраняет визуальный DOM/Tab порядок. Отказ при некорректном составе nav не изменяет элементы.
