# Система буквенно-цифровой маркировки пасеки

## Решение

Для физической маркировки рамок принят структурированный буквенно-цифровой код с разделителями. Код должен быть коротким, однозначно читаемым с самой рамки и удобным для произнесения голосом.

Примеры формата (иллюстрация, не присвоенные номера):
- рамка: `РМ-7К-М2`;
- корпус: `КР-4Н-8А`;
- улей: `УЛ-3В-7К`.

Префиксы показывают тип объекта: `РМ` — рамка, `КР` — корпус, `УЛ` — улей. Суффикс состоит из двух групп по два символа, разделённых дефисом.

## Правила идентичности

1. Код рамки закрепляется за физической рамкой навсегда. Перенос рамки в другой улей, корпус или режим сборки не меняет её код.
2. Код корпуса закрепляется за физическим корпусом и не меняется при перестановке между ульями.
3. Код улья закрепляется за физическим ульем. Порода пчёл, матка, тип конструкции и текущее содержимое не являются частью кода.
4. Позиция рамки в корпусе — отдельное изменяемое поле, не часть постоянного кода.
5. Коды не переиспользуются после выбытия объекта из эксплуатации.
6. Генерация и ручное назначение должны проверять уникальность. Для упрощения голосового ввода в алфавите кода следует исключить визуально неоднозначные символы (например, O/0 и I/1); распознавание произнесённых кодов должно учитывать дефисы и варианты диктовки.
7. Код не должен кодировать тип ульевой системы, назначение рамки (гнездовая/медовая), местоположение или принадлежность конкретному улью: эти сведения изменяемы либо хранятся в характеристиках объекта.

## Внутренняя модель данных

- Существующие UUID/внутренние ключи остаются техническими первичными идентификаторами и не заменяются маркировкой.
- Для физических объектов вводится отдельное поле видимого кода (например, `labelCode`) с уникальным ограничением.
- Текущий шестизначный `inventoryNumber` рамки сохраняется на переходном этапе для совместимости с существующими журналами, резервными копиями и миграциями. Он не должен оставаться единственным пользовательским обозначением.
- Отсутствие видимого кода у старых записей допустимо до этапа безопасного назначения/печати этикеток. Нельзя автоматически менять или перенумеровывать уже промаркированные физические рамки.
- История перемещений связывает неизменный идентификатор рамки с датой, ульем, корпусом и позицией на момент события.

## Интерфейс и голосовое управление

- В списках, карточках, осмотрах, поиске и подтверждении действий основным отображаемым обозначением становится структурированный код.
- При упоминании рамки показывать и код, и контекст: например, «рамка РМ-7К-М2, корпус КР-4Н-8А, позиция 3».
- Голосовой ввод должен различать постоянный код рамки и номер позиции. Если распознано неоднозначно несколько объектов, ассистент обязан уточнить выбор и не менять данные до подтверждения.
- Ручное назначение кода и автоматическая генерация должны быть доступны; повтор кода блокируется с указанием уже занятого объекта.
- Предусмотреть печатные этикетки с крупным кодом. QR-код может быть добавлен как дополнительный способ открытия карточки, но не заменяет читаемый код.

## Масштабирование

Система должна поддерживать как минимум 10 ульев разных конструкций, большое количество сменных корпусов и рамок. Идентификаторы глобально уникальны в пределах пасеки и не зависят от выбранного каталожного типа улья.
