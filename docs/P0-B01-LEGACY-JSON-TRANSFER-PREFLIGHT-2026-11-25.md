# B01 — отдельная безопасная проверка старого JSON, не полного видеоархива

**25.11.2026.** Основа: `main=635e4e3dded87a595645bb479e2c74040577ea5d`. F0–F7; source-backed предшественник — исторический Draft #469. Никаких production действий.

## F0–F2
Существующая на OnePlus v315 обычная функция экспорта состояния создаёт JSON, который **не** включает отдельный IndexedDB store `entrance_media`. Полный архив формата `paseka-idb-full-v1` — другой файл/процесс. Пользователь не должен принимать проверенный старый JSON за полноценную копию всех видео. В старом #469 есть полезная независимая `auditPasekaJsonTransfer`, но там общее чтение файла через `readFileSync` без ограничения байтов; целиком переносить #469 небезопасно.

## F3–F4
Изолированы только `scripts/audit-oneplus-json-transfer.mjs` и тесты из #469. При вызове `node scripts/audit-oneplus-json-transfer.mjs /local/path/export.json [--expect-hives=N --expect-families=N --expect-records=N]`:
- читается **только** выбранный существующий локальный `.json`, без ADB, сети, браузерной БД, restore, установки или удаления;
- один read-only descriptor, строгий лимит фактического чтения 512 MiB, file identity, отказ на symlink, изменении файла, ошибках UTF-8/JSON; exit nonzero при неизвестной схеме или несоответствии ожидаемого количества;
- проверяются `app:'Paseka'`, совместимый `schemaVersion`, списки ульев/семей/записей, дубликаты id, ссылки, тип массивов media и (по желанию) количество тестовых записей;
- вывод содержит только статус, типизированные причины без содержимого записей и агрегированные counts; аварийное исключение CLI скрывает путь и текст данных. `REVIEW_REQUIRED` не считается PASS;
- результат `JSON_STATE_PREFLIGHT_ONLY` и предупреждение: **оригиналы отдельных видео летков не включены**, full recovery NOT_VERIFIED.

## F5–F7
Негативные и регрессионные тесты только на синтетических данных: неполный/повреждённый JSON, дубликаты/несогласованность, symlink, отсутствие файла и повторное чтение без мутации. CI Android/Governance exact code SHA; затем main exact SHA, если безопасно интегрировано.

**Ограничения:** CLI не обрабатывает и не восстанавливает отдельное `entrance_media`, не удостоверяет Blob/все внешние источники. Для полного P0 экспорта использовать отдельный `verify-exported-archive.mjs`. B01 независимый restore/MediaStore/Gallery и B04/B05 signer остаются BLOCKED. #442 auto-cleanup FROZEN.
