## Дополнение 2026-11-16 — утверждена цифровая идентичность семей

Открытый вопрос о модели семьи/секции закрыт решением пользователя.

Утверждённая модель:
- при основной зимовке перед OP-04 — одна объединённая зимовавшая семья;
- при альтернативной зимовке OP-12 — три самостоятельные семьи в одной колонне, разделённые двумя сетчатыми диафрагмами; нижняя сильная семья на двух корпусах, две верхние семьи — по одному корпусу;
- после OP-04 — три самостоятельные семьи с разными familyId, секциями и общей историей происхождения; по решению пользователя исходная запись становится исторической, а все три результата получают новые ID; идентичность матки фиксируется только по факту;
- общая группа происхождения colonyGroupId связывает три семьи с исходной семьёй;
- межсекционные решётки и общие медовые корпуса — физические каналы сообщения рабочих пчёл, не объединение учётных семей;
- OP-11 — событие объединения без поиска маток: пчёлы оставляют одну из трёх, конкретная матка неизвестна. Создаётся новая учётная запись результата с новым familyId, без присвоения одного из исходных queenId; событие хранит ссылки на три исходные семьи и три матки-кандидата.

Следующий подэтап этапа 2: спроектировать аддитивную модель связей и событий для обоих режимов зимовки и раннего медосбора после OP-12; определить совместимость старых family/queen records, архивов и backup/restore; добавить unit/regression тесты на независимую зимовку трёх семей, ранний медосбор, временное объединение на 3–5 дней, повторное разделение, lineage и отказ при повреждённых ссылках. Реализацию не связывать с физическим изменением улья без отдельного подтверждения операции пользователем.


## Уточнение OP-11 — результат с неизвестной идентичностью матки

Это уточнение заменяет противоречивый абзац ранней редакции о выборе `survivorFamilyId`. При основной OP-11 маток не ищут: пчёлы сами оставляют одну из трёх. Итоговая запись получает новый `familyId`; это идентификатор цифровой записи, не новая биологическая семья. Нельзя назначать итоговой записи один из трёх исходных `queenId`. Событие объединения хранит все три исходные `familyId` и три `queenId` как кандидатов; `queenId` результата остаётся неизвестным до фактической идентификации. Исходные семейные и маточные записи сохраняются. OP-12 оставляет три семьи самостоятельными.

Перед реализацией требуется спроектировать аддитивную модель `familyId` / `colonyGroupId`, связи секций и маток, события разделения/объединения и совместимость старых записей, IndexedDB и архивов. Отдельно учесть промежуточное состояние OP-04: расположение старой матки неизвестно, две новые матки ещё выводятся; нельзя создавать фиктивные записи маток. Затем добавить тесты переходов, повторного разделения, lineage, legacy и backup/restore.
