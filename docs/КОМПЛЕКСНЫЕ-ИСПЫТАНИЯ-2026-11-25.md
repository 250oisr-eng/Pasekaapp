# Комплексные испытания «Пасека 2.0» — система QA и план допуска

**Дата:** 2026-11-25. **Контрольная база:** `main=fdcca080b68aa5b0014b8e99cd3e4f1d428e7ba2`.  
**Статус:** IMPLEMENTED_DRAFT (автоматический слой), DEVICE_NOT_TESTED. Не является разрешением на merge, установку APK, реальное восстановление, очистку или публикацию.

## 1. Основание, назначение и границы (F0–F2)

Источники — `AGENTS.md`, `docs/PROJECT-CONTROL.md`, стратегия F0–F7, [существующий план QA](АВТОМАТИЗИРОВАННЫЕ-ТЕСТЫ-И-МИНИМУМ-УЧАСТИЯ-2026-11-23.md), реестр B01–B15 и фактические исходники/CI. Технологические правила OP берутся из пользовательского DOCX и подтверждённых уточнений, а не из предположений тестировщика.

**Цель:** единая система испытаний с минимальным участием пчеловода, дающая проверяемое различие между (а) автоматической синтетической регрессией, (б) CI конкретного коммита, (в) независимой интеграцией взаимозависимых Draft, (г) физическим OnePlus, (д) реальным резервированием/восстановлением, (е) выпуском. Зелёный CI уровня (а)/(б) не завершает (г)/(д)/(е).

F2: автоматическая часть технически доступна в бесплатном GitHub Actions на существующем `npm test`; новых платных сервисов и доступов к данным не требуется. Для реальных OnePlus/видео/независимого recovery доказанных исходных ресурсов пока нет — эти проверки остаются `BLOCKED/NOT_TESTED/FROZEN`, даже если CI полностью зелёный.

## 2. Уровни испытаний и критерии

| Уровень | Объект и критерий | Доказательство / допуск |
| --- | --- | --- |
| Q0, контроль покрытия | **Каждый** `tests/*.test.mjs` назначен ровно одному направлению: существующие файлы зафиксированы явно, новые автоматически распределяются по **уникальному самому длинному префиксу**. Неизвестные/неоднозначные и удалённые из репозитория файлы блокируют CI; это устраняет необходимость править центральную матрицу в каждой параллельной ветке. | `qa/comprehensive-matrix.json`, `validateQAMatrix`, негативные тесты; при неизвестном или неоднозначном имени теста — CI FAIL, при однозначном — включение автоматически |
| Q1, полный автоматический регресс | Одна существующая команда `npm test`, итог TAP; `fail=0`, `cancelled=0`, `skipped=0`, `todo=0`, `tests=pass`, итог присутствует. | Fast quality; отчёт `qa-results/comprehensive-report.json`; пропавший/частичный TAP не может стать PASS |
| Q2, доменная и операционная логика | Раздельные физическая модель, Farrar, семейные связи, экипировка, OP, журнал, план ≠ действие; регрессии подтверждённого OP-02 (100–200 г **в сутки на семью**, 2:1, `gramsPerColonyPerDay`). | Существующие доменные/журнальные тесты, индекс по области; не объявлять реальное выполнение OP |

| Q4, офлайн и безопасность UI | SW/CacheStorage: строгий allowlist, private/no-store, 204/206, redirect и query, не удалять пользовательские кеши; журнал fail-closed при ошибке save. | Service Worker и UI тесты; реальный cold start OnePlus отдельная Q7 |
| Q5, видео и ИИ | Оригинал нельзя удалять/перезаписывать без V0–V6; модели без лицензии и эталона не использовать; fake/synthetic detection не является распознаванием. | CI тесты разрешённых read-only путей, отдельный composed Draft #518; #442 FROZEN |
| Q6, готовность к интеграции | Параллельный read-only audit открытых Draft: реальный `head.sha`, checks на **том же SHA**, отсутствие `PENDING/FAIL/ABSENT`; конфликтующие изменения нуждаются в отдельной проверенной композиции. | `qa/tracked-drafts.json`, `scripts/comprehensive-pr-checks.mjs`, отдельный `draft-checks.json`; `EXACT_SHA_CI_SUCCESS_ONLY` не даёт права merge |
| Q7, устройство и recovery | Реальные исходные байты OnePlus, все источники (в т.ч. Gallery/MediaStore), независимый restore, signer/rollback, cold offline, запуск/камера/хранилище и реальная производительность. | Только физические подтверждения по [единому сеансу](ONEPLUS-ЕДИНЫЙ-СЕАНС-ИСПЫТАНИЙ-2026-11-25.md); сейчас BLOCKED/NOT_TESTED |
| Q8, выпуск | Конкретный approved SHA, полный Q0–Q7 в применимой области, миграции и откат, независимое явное разрешение пользователя. | Отдельный manual release gate; ни тестовый workflow, ни Draft не могут публиковать |

Правило приёмки: отсутствие проверки обозначается `NOT_TESTED/NOT_VERIFIED`, а не `PASS`. При запуске свежего PR прежний зелёный SHA не наследуется.

## 3. Реализованная автоматика — без повторного запуска тестов

1. Изменение в отдельной ветке запускает **существующий** `.github/workflows/quality.yml`. Оставлены прежний Node 20 и `npm test`; результат один раз передаётся также в TAP-файл. Нет нового полного повторного набора тестов.
2. `scripts/comprehensive-qa.mjs` сверяет полный перечень тестовых файлов с матрицей, итог TAP и точный `GITHUB_SHA`. Создаёт машиночитаемый `qa-results/comprehensive-report.json`, содержащий **только синтетические счётчики, области и статусы**. При ошибке/пропуске тестов PASS запрещён. Отчёт не содержит пользовательских записей.
3. `scripts/comprehensive-pr-checks.mjs` выполняет исключительно GitHub REST **GET** с ограниченным read-only `github.token`. Для набора открытых Draft запрашивает `pulls/{number}` и `commits/{head.sha}/check-runs`; по каждому необходимому имени check требует `completed/success` на том же SHA. Отсутствие API, SHA mismatch, ошибка, pending или закрытый PR дают `REVIEW_REQUIRED`, но **не разрешение на merge**. Результат — `qa-results/draft-checks.json`.
4. Два JSON-отчёта помещаются в один ограниченный 7 днями CI-артефакт. **Raw TAP, APK, файлы пользователя, видео, архивы, keystore, токены и USB-идентификаторы туда не попадают.** Штатный Android CI остаётся отдельным: он подтверждает сборку, а не установку.
5. На docs-only изменение матрицы не выдаётся результат устройства. При любой ошибке источника данных итог соответствующего уровня — `NOT_VERIFIED`. Автоматического развёртывания, APK install, изменения IndexedDB и слияния PR нет.

## 4. Направления матрицы и конкретные негативные сценарии (F3–F5)

| Контур | Обязательные сценарии сверх счастливого пути |
| --- | --- |
| Журнал | двойное нажатие, запись без улья, реальный save error, rollback после сбоя, журнал после reopen, история семьи, неподтверждённая обработка Varroa |
| IndexedDB | миграция старой версии, неправильный `versionchange`, abort/read error, отклонение повреждённой v3, start blocked, изменения не сохраняются при fail |
| Архив | полный перечень stores, store без входного ключа, неизвестный/дублирующийся store, changed bytes при тех же counts, файл больше лимита, symlink, UTF-8, сохранение сторонних originals |
| Офлайн | настоящий cache namespace, отказ 204/206 и redirect, query path не отравляет основной ресурс, private/no-store, offline JS не HTML, пользовательские/будущие caches сохраняются |
| Физическая модель | рамки/секции/матки/летки, ownership, баланс корпусов, недопустимые перестановки, изоляция Farrar и multi-queen, нет автоподтверждения OP |
| Сезон/наблюдения | план ≠ факт, проверяемые источники норм, запрещённые/пустые данные не превращаются в выполненные мероприятия |
| Голос | офлайн-разбор без удалённого сервиса, неизвестный улей, черновик ≠ физический акт, явное подтверждение критического действия |
| Видео | недостоверная модель не становится детектором; оригинальные Blob не очищаются; опасные ID в UI, stale asynchronous list, не хранить все Blob в RAM при listing |
| Выпуск | строгие ручные release ворота, корректные ссылки на SHA, отсутствие автоматического Pages/Cloudflare publishing и утечки ключей |
| Сам QA | тест без регистрации блокирует инвентарь, дублирующийся тест блокирует инвентарь, `SKIPPED/PENDING/FAIL` не считается `PASS`, запрет `externalGate=PASS` из CI |

Здесь перечислены направления контроля, а не утверждение, что каждый конкретный negative test уже включён в `main`. Дополнительные видео- и offline-исправления остаются в собственных Draft #512/#514/#518/#530, а независимый архив #524. Для будущей интеграции требуется повторная оценка общего SHA.

## 5. Приоритетная очередь испытаний (F6)

**Этап A — автоматическая база:** Q0/Q1 на `main` и Draft этого QA-контура, наблюдаемые JSON-артефакты, полный CI и причины ошибок; завершается при точном SHA с Fast + Governance + применимым Android.

**Этап B — проверка пересекающихся Draft:** использовать имеющуюся синтетическую композицию #518 как доказательство ограниченного сценария. Проверять связку #512→#511/#514, #515→#530, #510→#531 и независимые #516/#524. При расхождении версий и изменении файлов не считать отдельные зелёные ветки проверенной общей сборкой. **Никакого автоматического объединения PR.**

**Этап C — восстановление:** когда существует реальный локальный полный архив, проверить неизменность источника и restore на пустой изолированной цели. Внешние оригиналы и MediaStore/Gallery проверяются отдельно. Без B01 и B04/B05 **не обновлять реальное приложение**.

**Этап D — одна физическая сессия:** после выполнения предпосылок провести единый безопасный check hub, холодный offline, UI smoke и ресурсные замеры без оригинальных файлов и без удаления. Потребность в действиях пользователя описана в отдельном протоколе; **сейчас 0 действий**.

**Этап E — решение о выпуске:** только после результатов предыдущих этапов и отдельного прямого разрешения; не входит в QA-контур.

## 6. Реакция на ошибки, метрики и запреты

- Состояния: `PASS_SYNTHETIC`, `FAIL`, `PARTIAL`, `NOT_VERIFIED`, `BLOCKED`, `FROZEN`, `DEVICE_VERIFIED` — не взаимозаменяемые. Отменённый или ожидающий CI не имеет итогового PASS.
- Каждая неисправность: текущий head SHA → конкретный тест/лог → минимальное исправление → один повтор на новом SHA → журнал. Не создавать 100 синтетических smoke вместо физического доказательства.
- Количественные метрики: число тестовых файлов, 10 направлений, число запущенных/успешных/упавших/пропущенных тестов, SHA каждого Draft, фактически незакрытые gate. Время CI — не доказательство улучшения производительности устройства.
- Расходы: только имеющиеся npm/Node/GitHub Actions и репозиторий. Новых обязательных платных подписок и API нет. 
- Без отдельного разрешения нельзя merge, deploy, APK update, production data restore, изменение схемы рабочей базы и оригинальное видео delete.

**Итог внедрения:** система автоматически сообщает, что испытано в синтетическом CI, а что остаётся непроверенным. Не пытается заменить отсутствующий полный архив, ключ Android или реальные видео выдуманным PASS.
