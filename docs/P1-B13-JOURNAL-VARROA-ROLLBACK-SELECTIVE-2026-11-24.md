# B13 — исправление отката Varroa и архивации журнала на актуальном main

Дата: 2026-11-24. Исходный `main=6b865fe0b338f360d763ce3d0599829b7c34dedc`.

## F0: подтверждённое отличие

На актуальном main `saveVarroaObservation()` мутирует массив и audit перед `await save()`; его отказ / throw оставлял риск несогласованного состояния, а повторный submit не защищён. `deleteRecord()/restoreRecord()` изменяли `archivedAt` и audit и затем `await save()` без локального отката при отказе. Нельзя терять старую историю или необоснованно утверждать, что запись сохранилась.

В старом [Draft #451](https://github.com/250oisr-eng/Pasekaapp/pull/451) уже имеются локальные исправления и `tests/journal-varroa-archive-recovery.test.mjs`; но весь PR отстаёт от main и включает диагностический APK, который здесь не нужен.

## F1: минимальное безопасное действие

- Точно перенесены только две функции из #451: сохранение Varroa с защитой повторной отправки и откатом состояния после отказа; атомарная по признанному `save()` архивация/разархивация записей журнала с восстановлением снимка при ошибке.
- Не изменены `DB_VERSION`, store schema, `js/disaster-archive.js`, SW, основная модель ульев, параметры препарата и технологические операции.
- `tests/journal-varroa-archive-recovery.test.mjs` перенесены как регрессии; они используют только синтетические состояния, не OnePlus.
- Конкурентное сохранение разных записей и физический Quota/транзакционный rollback требуют дополнительных доказательств: успешный Node CI не равен физической проверке; запреты PASEKA02 #442 сохраняются.
