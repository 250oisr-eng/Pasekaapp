# Надёжное чтение исходных DOCX-файлов

Этот протокол обязателен для всех чатов и рабочих сеансов проекта «Пасека». Он предотвращает остановку разработки из-за временной недоступности одного инструмента анализа.

## 1. Приоритетный порядок чтения

1. Сначала найти файл через Project Files (files__search, запрос по точному имени). Если файл индексирован и доступен для чтения, использовать files__read.
2. Если Files не возвращает содержимое или недоступен, проверить автоматически смонтированные файлы рабочего контейнера. Файлы текущего разговора обычно доступны в /mnt/data; имя может отличаться, поэтому сначала выполнить поиск по маске/имени, а не угадывать путь.
3. Читать DOCX через обычную среду выполнения контейнера (container.exec), а не через python_user_visible. python_user_visible предназначен для пользовательских вычислений/файлов и не должен быть единственным способом доступа к исходному документу.
4. Если пакет python-docx установлен, извлекать абзацы и таблицы через docx.Document.
5. Если python-docx отсутствует или падает, DOCX является ZIP-контейнером: извлечь word/document.xml стандартными средствами ZIP/XML (Python zipfile + xml.etree.ElementTree). Это резервный способ, не требующий стороннего пакета.
6. Если контейнерный инструмент недоступен, повторно проверить Project Files и поискать текстовую расшифровку/аудит в документах репозитория через GitHub fetch_file. Не заявлять, что исходник прочитан, если получен только пересказ из другого документа.
7. Если все способы действительно недоступны, записать точную ошибку инструмента и остановиться только на утверждениях, которые не требуют проверки исходника. Не повторять общий ответ «не удалось выполнить advanced data analysis», если можно использовать альтернативный путь.

## 2. Команда для извлечения через контейнер

Сначала найти файл:

~~~bash
find /mnt/data -maxdepth 2 -type f -iname '*улей*техпроцесс*.docx' -print
~~~

Затем выполнить:

~~~bash
python - <<'PY'
from pathlib import Path
from docx import Document
files = list(Path('/mnt/data').rglob('*улей*техпроцесс*.docx'))
if not files:
    raise SystemExit('Исходный DOCX не найден в /mnt/data')
for path in files:
    doc = Document(path)
    print(f'ФАЙЛ: {path}')
    print(f'АБЗАЦОВ: {len(doc.paragraphs)}; ТАБЛИЦ: {len(doc.tables)}')
    for i, paragraph in enumerate(doc.paragraphs, 1):
        if paragraph.text.strip():
            print(f'[{i}] {paragraph.text}')
    for ti, table in enumerate(doc.tables, 1):
        print(f'[ТАБЛИЦА {ti}]')
        for row in table.rows:
            print(' | '.join(cell.text for cell in row.cells))
PY
~~~

Если python-docx недоступен, извлечь XML:

~~~bash
python - <<'PY'
from pathlib import Path
from zipfile import ZipFile
from xml.etree import ElementTree as ET
files = list(Path('/mnt/data').rglob('*улей*техпроцесс*.docx'))
if not files:
    raise SystemExit('Исходный DOCX не найден в /mnt/data')
ns = {'w': 'http://schemas.openxmlformats.org/wordprocessingml/2006/main'}
for path in files:
    with ZipFile(path) as z:
        root = ET.fromstring(z.read('word/document.xml'))
    print(f'ФАЙЛ: {path}')
    for i, paragraph in enumerate(root.findall('.//w:body/w:p', ns), 1):
        text = ''.join(node.text or '' for node in paragraph.findall('.//w:t', ns))
        if text.strip():
            print(f'[{i}] {text}')
PY
~~~

## 3. Правила достоверности

- Сохранять номера абзацев/страниц и цитировать исходные формулировки по возможности. Автоматическая расшифровка может содержать ошибки распознавания; не исправлять смысл догадкой.
- Абзацы и таблицы проверять отдельно; не считать отсутствие таблиц доказательством отсутствия структурированных данных в других частях документа.
- Не заменять исходник транскриптом видео, предыдущим чатом или сводным документом, если требуется проверить точную формулировку.
- Сверять выводы с docs/СВЕРКА-ТЕХПРОЦЕССА-С-ИСТОЧНИКОМ.md, но при расхождении заново читать исходный DOCX.
- Разделять: прямо сказано в DOCX; подтверждено пользователем отдельно; выведено из структуры; неизвестно. Не повышать гипотезу до факта.
- Не коммитить полный текст пользовательского DOCX в репозиторий автоматически. Для предотвращения повторного чтения достаточно закрепить способ доступа и вести проверенные требования в профильной документации.
- Не менять исходный файл. Извлечение — только чтение.

## 4. Контрольная проверка текущего исходника

На рабочем сеансе 2026-11-16 файл «улей для каждого техпроцесс.docx» был успешно прочитан через контейнерный python-docx (без python_user_visible):
- размер файла: 36 198 байт;
- SHA-256: 4bdd0d2fad822b2a7aea9e1dbbf95137034091d0188e0e7fa44c5c2515413052;
- 94 абзаца, из них 93 непустых;
- таблиц: 0.

Это контрольная сумма именно той копии, которая была доступна в данном сеансе. При получении новой версии документа проверить SHA-256 повторно; не считать различие хеша ошибкой, если пользователь обновил файл.
