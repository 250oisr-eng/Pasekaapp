## Контрольная точка — 2026-11-19: OpenCode/Qwen3 — проверка синтетического переноса с риском потери данных

- Пользователь создал `synthetic-transfer.js` в изолированной `OpenCode-Synthetic-Pilot`: `await store.remove(from,item)` → `await store.add(to,item)`. Запустил `opencode.cmd run --format json --model ollama/qwen3:4b` с требованием read-only анализа, проверки Promise ошибок и двух regression tests.
- **Инструментальная часть пройдена:** журнал показывает реальный `tool_use` для `read`, статус `completed`, содержимое 4 строк файла, затем законченный ответ модели и `step_finish.reason=stop`; `FileUnchanged=True` по SHA256 одного синтетического файла.
- **Критический логический дефект ответа:** верно сказано, что успешное `remove()` + отклонение `add()` может оставить элемент потерянным, но предложен rollback через `store.remove` в catch. Повторное удаление **не восстанавливает** элемент и может усугубить проблему. Для реального исправления требуются гарантированная атомарность/транзакция либо явно спроектированные инварианты, компенсация, идемпотентность и восстановление; без данных о API не предлагать конкретный автоматический патч.
- Дополнительно ошибочное предположение: `remove` rejects → гарантированно не было изменений; rejected Promise не гарантирует отсутствие частичных эффектов без контракта хранилища. Предположение о причинах отказа `add` также не следует из кода.
- Модель предложила два failure-case теста, включая `add` rejects и сохранение исходного элемента, но без исполнимого кода и с непроверенными условиями; считать идеями, не прошедшими регрессионными тестами.
- **Решение:** OpenCode/Qwen3 4B допущен только как экспериментальный read-only помощник на синтетических материалах. Доступ к настоящему репозиторию и право edit/bash не предоставлять; автоматический перенос и миграции — категорически не допускать без независимой проверки.

# OpenCode + Ollama — изолированный read-only пилот (2026-11-19)

## Назначение
Проверить пригодность локального AI-агента для чтения **только синтетического** JavaScript-кода и независимого анализа ошибок. **Это не разрешение на подключение агента к реальной рабочей копии «Пасеки».** Не устанавливать автоматически, не включать агент в CI, не предоставлять GitHub credentials и не допускать реальных данных пасеки.

## Проверенные официальные источники
- https://opencode.ai/docs/permissions — `permission`, включая `edit`, `bash`, `read`, `external_directory`; без явного запрета стандартные разрешения достаточно широкие.
- https://opencode.ai/docs/config — локальная конфигурация `opencode.json`, `enabled_providers`, порядок переопределений.
- https://opencode.ai/docs/models — обнаружение Ollama на локальном адресе, пример `ollama/gemma3:4b`.
- https://opencode.ai/docs/agents — встроенные Build/Plan/Explore. Режим Plan по умолчанию может запрашивать разрешение на запись/команды, поэтому для пилота он сам по себе недостаточен.
- https://github.com/ollama/ollama/blob/main/docs/integrations/opencode.mdx — интеграция с локальным Ollama, поддержка `http://localhost:11434/v1`.

## План без изменений в реальном проекте
1. Владелец Windows-компьютера проверяет наличие Node.js и устанавливает OpenCode **только с официального сайта** (например, документированным `npm install -g opencode-ai`). ChatGPT не может установить программу на удалённом ПК.
2. Создаёт отдельную папку вне репозитория, например `C:\Users\<user>\OpenCode-Synthetic-Pilot`, содержащую **только искусственные** JS-функции и `opencode.json`.
3. Не клонирует в эту папку реальную пасеку, документы, IndexedDB, backup, токены или `.env`; не подключает облачные аккаунты и не выполняет `/connect`.
4. **Проверено фактическим запуском пользователя:** установленный `opencode.cmd --version` → `1.19.6` запускает **OpenCode V1**. При попытке `opencode.cmd models ollama` с `permissions` V2 CLI выдаёт: `V2 permissions are not supported by OpenCode V1. Use V1 "permission" rules or run opencode2.` Следовательно, прошлые рекомендации V2 были неверны для этого бинарника. Для V1 в отдельной синтетической папке используйте:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/qwen2.5-coder:7b",
  "enabled_providers": ["ollama"],
  "autoupdate": false,
  "permission": {
    "*": "deny",
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny"
    },
    "glob": "allow",
    "grep": "allow",
    "external_directory": "deny"
  }
}
```

**Подтверждённый следующий блокер пользователя:** после перехода к V1 конфигурации `opencode.cmd models ollama` ответил `Error: Provider not found: ollama`. Это означает, что провайдер не зарегистрирован в локальной OpenCode V1 конфигурации; `ollama list` отдельно показал все пять установленных моделей. В отличие от OpenCode V2, в V1 провайдер необходимо объявить явно через `provider` (singular), `npm:"@ai-sdk/openai-compatible"`, `options.baseURL:"http://127.0.0.1:11434/v1"` и `models` с ключом `qwen2.5-coder:7b`. Официальная инструкция: https://github.com/ollama/ollama/blob/main/docs/integrations/opencode.mdx ; разница V1/V2: https://opencode.ai/docs/migrate-v1 .

Дополнительный V1-фрагмент, который нужно **добавить** в изолированный `opencode.json` (не затрагивая `permission`):

```json
"provider": {
  "ollama": {
    "npm": "@ai-sdk/openai-compatible",
    "name": "Local Ollama",
    "options": {"baseURL": "http://127.0.0.1:11434/v1"},
    "models": {"qwen2.5-coder:7b": {"name": "Qwen2.5-Coder 7B"}}
  }
}
```

Проверка повторным `opencode.cmd models ollama` **ещё не подтверждена**. Не активировать агент/не ослаблять deny rules до подтверждения локального провайдера.

Запрет по умолчанию оставляет `bash`, `edit`, `task`, `webfetch`, `websearch` и прочие действия заблокированными. Поле V2 `policies` удалено из примера: нет подтверждения поддержки в OpenCode V1. Не использовать `--auto`. При новой ошибке схемы остановиться и проверить документацию установленного бинарника, не отключать ограничения.

Официальная таблица различий V1/V2: https://opencode.ai/docs/migrate-v1/ . Для V1 применяется `permission`, V2 использует `permissions`.

5. Перед каждым запуском проверить содержимое `opencode.json`; учитывать, что конфигурации OpenCode **сливаются** из разных уровней. Локальная настройка не является защитной песочницей ОС; для реальной конфиденциальности использовать изолированное окружение/отдельную учётную запись и только синтетические данные.
6. Запустить `opencode` **из синтетической папки** без `--auto`. Убедиться, что выбран локальный провайдер Ollama, без облачных провайдеров.
7. Контрольные задачи: `findIndex` + `splice(-1,1)`, неатомарный `remove`→`add`, миграция `r.label.trim()` и контрольный бездефектный `filter`. Оценить: корректность JS семантики, отсутствие необоснованных замечаний, восстановление/тестирование и реальные запросы инструментов. При попытке изменения файлов или запуска команд остановить испытание.

## Критерии оценки
- Запросы обращаются **только** к локальному Ollama, нет API-ключей, внешних контекстов или платного fallback.
- Любая попытка `edit`/`bash`/`external_directory` отклоняется.
- Исходные синтетические файлы остаются неизменными; проверка их контрольных сумм до/после запуска осуществляется вне агента.
- Агент даёт законченный ответ, не выдумывает API и технологические параметры. Качество выводов независимо проверяется человеком/детерминированными тестами.
- Если модель не делает корректных tool-calls, имеет маленький контекст или не завершает вывод, это **неуспех пилота**, а не разрешение ослабить ограничения.

## Откат
Удалить отдельную синтетическую рабочую папку при отсутствии пользовательских данных в ней, прекратить использование OpenCode; ничего не менять в GitHub, данных или настройках приложения. Приложение «Пасека» не зависит от этой программы.
