## F0 — проверенные факты

- Прочитаны `js/disaster-archive.js`, `tests/disaster-archive.test.mjs` и P0 UI в `index.html` именно из ветки #452. Функция `getRecords(db)` читает **все object stores одной открытой базы** в общей readonly IndexedDB-транзакции. Файл архивирует имена хранилищ, `keyPath`, `autoIncrement`, ключи и значения; данные Blob/File/Date/ArrayBuffer кодируются отдельно, а неподдерживаемые типы приводят к отказу экспорта.
- `inspectArchive` проверяет формат, имя базы `paseka-v1`, точную версию IndexedDB, SHA-256 сериализованного payload, полное совпадение состава хранилищ, количество записей, уникальность ключей и соответствие inline keyPath.
- `atomicRestore` применяет полную замену всех хранилищ в одной `readwrite` транзакции с проверкой `main.state.meta.revisionId` перед записью. Это **атомарность транзакции в пределах одной базы**, а не аварийное восстановление всех внешних мест хранения.
- UI `downloadDisasterArchive` предупреждает, что вызов загрузки ещё не доказывает сохранение файла; `verifyDisasterArchive` повторно читает выбранный файл и валидирует его без записи; `restoreDisasterArchive` запрашивает два явных подтверждения **перед потенциально разрушительной заменой**, но не удостоверяет независимую внешнюю копию автоматически.

## F1 — покрытие и непреодолённые границы

| Источник данных / сценарий | Фактическое покрытие #452 | Статус допуска |
|---|---|---|
| `paseka-v1/main` | Полное считывание и однотранзакционное восстановление, если версия и структура совпадают | Автоматические тесты, **не рабочий пользовательский restore** |
| `paseka-v1/full_backup` | Попадает в снимок и подлежит атомарной замене вместе с остальными | **Нельзя** считать независимой внешней резервной копией |
| `paseka-v1/entrance_media` | Значения Blob включаются в архив; в тестах проверены исходные байты небольшого MP4 fixture | Реальные крупные MP4, квота, скачивание на устройство и внешняя копия **NOT_VERIFIED** |
| Отдельные БД или хранилища PASEKA02, `record_media`, прежние форматы | Код #452 адресован только переданной базе `paseka-v1`; общее покрытие иных источников не доказано | **OUT_OF_SCOPE / BLOCKED #442** |
| Gallery / Downloads / Android MediaStore / файлы камеры / экспортированные копии | IndexedDB-экспорт не инвентаризирует их и не удаляет | **NOT_COVERED**, удаление запрещено |
| Внешний файл после скачивания | Есть локальная read-only проверка выбранного файла | Независимый физический носитель и второе устройство **NOT_VERIFIED** |
| Возврат оригинальных пользовательских файлов после полной потери телефона | Синтетический импорт в чистый `fake-indexeddb`; исторический отдельный OnePlus disaster smoke для другого APK | Полный пользовательский end-to-end **NOT_VERIFIED** |
| Старые схемы, другие версии IndexedDB | На несовпадающей версии экспорт/импорт отклоняется | **Миграция не реализована в этом модуле** |
| Остановка ОС, нехватка места, большие файлы | Негативные автоматические тесты и изолированный диагностический APK | Достоверная физическая приёмка исходных видео **NOT_VERIFIED** |

**Критическое различие:** SHA-256 файла подтверждает внутреннюю целостность *этого* снимка, но не полноту **всех** источников медиа, не наличие сохранённой копии вне телефона, не способность восстановиться с неё и не права на удаление оригиналов. Проверка возвращаемого файла на том же телефоне не равна восстановлению на другом физическом устройстве.

## F2 — следующий безопасный путь

1. Составить полный read-only реестр фактически используемых баз IndexedDB и файловых источников PASEKA02/legacy/record_media с конкретными appId/DB/store/version; оставить неизвестные поля `UNKNOWN`, ничего не очищать.
2. Только после подтверждения перечня проверить, что архив переносит **все** необходимые исходные Blob/файлы и их метаданные; для отсутствующих источников нужна отдельная реализация экспорта и обратимого восстановления, а не изменение статуса #452.
3. Перед любым реальным restore сохранить исходные данные и проверенную копию вне телефона. На независимом физическом тестовом устройстве/профиле выполнить экспорт → чтение скачанного файла → перенос → полный restore → restart → сравнение исходных байтов, истории и ссылок. Не выполнять destructive test на рабочем профиле.
4. Если нельзя подтвердить хотя бы один источник/копию/хэш/лицензию/реальное устройство, остановить переход к live PASEKA02 и `cleanupAuthorized`. Не запускать автоочистку даже после успешного P1 OnePlus smoke.
