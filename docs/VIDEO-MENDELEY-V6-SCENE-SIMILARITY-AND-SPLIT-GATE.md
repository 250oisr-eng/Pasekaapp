# Mendeley Data v6 — предотвращение ложной независимости видеокадров и безопасное расширение реестра

Дата: 2026-11-20. **Рабочий исследовательский набор без обученной модели.** Draft PR #289, исходная ветка поверх Draft #288.

## Подтверждённые источники и смысл разметки

- **Tomyslav Sledevic**, *Labeled dataset for bee detection and direction estimation on beehive landing boards*, **version 6**, DOI [10.17632/8gb9r2yhfc.6](https://doi.org/10.17632/8gb9r2yhfc.6), данные **CC BY 4.0**. Атрибуция и уведомление о преобразованиях сохранены.
- В рецензируемом описании данных [Sledevič & Matuzevičius, Data in Brief 52 (2024), 110060](https://pmc.ncbi.nlm.nih.gov/articles/PMC10831503/) авторы пишут, что исходные записи сняты с **50 кадрами/с**, затем из видео извлекались изображения. Опубликованы восемь коллекций из восьми ульев, всего **7200** размеченных кадров `detection`. Это **не** доказательство SHA и номерных идентификаторов каждой исходной видеосессии.
- **Ключевое технологическое условие:** в исходном detection размечались пчёлы **в любой части изображения — на передней стенке улья, прилётной доске и даже траве**. Следовательно, любая область детекции пчелы ≠ направление `in/out` или пересечение летка. Для подсчёта необходимы отдельно откалиброванная линия, подтверждённые track IDs, достаточная temporal coverage и ground-truth directional benchmark. Ни один исследовательский инструмент ниже не должен менять это требование.

## Блок 1. SHA-pinned оригиналы и визуальное сходство камер

`tools/audit_mendeley_v6_original_scene_similarity.py`:

1. Получает **строго 16** original JPG URL из `tests/fixtures/mendeley-v6-user-16-pairs-pinned.csv`, по два из каждой восьми опубликованных групп. Все URL проверяет существующий строгий `parse_manifest`/public-file downloader (HTTPS allowlist, лимиты) и **реальный SHA-256 каждого JPG**.
2. Полностью декодирует оригинал 1920×1080 через свободный Pillow 12.0.0. Никакие изображения/MP4 пользователя не читаются.
3. Вычисляет 64-битный `dHash` (grayscale 9×8, горизонтальные разности) и расстояния Хэмминга для **8 внутригрупповых** и **112 межгрупповых** сочетаний. Выводит не более 12 ближайших межгрупповых пар в метаданных. Raw JPEG остаются только в кратковременной памяти бесплатного runner, бинарные artifacts **не сохраняются**.
4. Порог **6 бит** — **только диагностическая эвристика**, не научно валидированный duplicate/independence threshold. Отсутствие близких пар при любом таком пороге **не** подтверждает, что группы состоят из независимых исходных видео.

**Фактические первые результаты:** в [реальной исследовательской CI #44772676835](https://github.com/250oisr-eng/Pasekaapp/actions/runs/44772676835) на SHA `245d0787590a05491fab69fa09cc4e1fd0a32ade` **completed/success**: все 16 pinned JPEG прочитаны, полностью декодированы и сверены по SHA; **8** внутригрупповых, **112** межгрупповых пар; межгрупповых расстояний dHash не более 6 — **0**. Минимальная обнаруженная межгрупповая дистанция — **19 бит** (пример: `_bee_20230609d/20230609d1002.jpg` и `_bee_20230711c/20230711c1005.jpg`). Расстояние 19 — не доказательство разных видеосессий, дат, мест или физических ульев; оно лишь значение данного алгоритма.

## Блок 2. Объединение множественных CSV-пакетов без загрузки 7,21 ГБ

`tools/merge_mendeley_v6_pinned_manifests.py`:

- Вход — от **1 до 500** CSV-пакетов по максимум 16 строк каждый, только с оригинальными public-files v6 URLs, реальными `image_sha256,label_sha256`, восемью опубликованными `hive_group`. Ограничение суммарно 7200 строк.
- Не принимает повтор одного CSV, дубль `(hive_group,image_filename)`, повторный JPG SHA, один file UUID под разными именами, невалидный lowercase SHA или число файлов сверх опубликованного количества каждой серии. Проверяет symlink/hardlink источников.
- Атомарно создаёт новый `JSON` с индексом URL+SHA, без перезаписи прежнего и без копирования изображений. **Сами исходные байты при этом шаге не скачиваются и SHA повторно не подтверждаются**: это честный `sourceHashesPinnedInCsvNotRecheckedByMerge=true` атрибут.
- Фиксирует количество найденных файлов относительно официального числа 7200, но **совпадение чисел не доказывает подлинность, независимость исходных записей или готовность модели**.

Фактический реестр текущей оригинальной минивыборки: **16/7200**, недостача **7184**, по **2 из каждой 8** коллекций. 16 реальных JPG+TXT с полной SHA-проверкой были ранее подтверждены [#44770020180](https://github.com/250oisr-eng/Pasekaapp/actions/runs/44770020180). В текущей CI объединение — **строго metadata-only**.

Пример (при наличии локального CSV):

```sh
python tools/merge_mendeley_v6_pinned_manifests.py \
  tests/fixtures/mendeley-v6-user-16-pairs-pinned.csv \
  --output-json /tmp/paseka-new-v6-inventory.json
```

## Блок 3. Независимость train/validation/test — отдельная блокирующая проверка

`tools/audit_mendeley_v6_grouped_split_proposal.py` читает реестр и **только структурное предложение** о распределении восьми опубликованных коллекций между `train`, `validation`, `test`. Проверяет, что группы не пересекаются, каждая встречается ровно один раз, отсутствуют неизвестные имена, дубли кадров и исходных SHA. Не раскладывает JPEG по папкам и не запускает обучение.

Пример **только для теста блокировок**: `tests/fixtures/mendeley-v6-group-disjoint-NOT-TRAINING.json` содержит 5/1/2 группы, соответствующие **10/2/4 реальным изображениям** при двух в каждой группе. Это **не утверждённое** распределение для обучения. Источники кадров, фактические записи, независимые физические ульи и video frame mapping **не имеют независимой криптографической и визуальной проверки**.

Даже если все восемь папок не пересекаются структурно, результат обязан быть:

```text
publishedFoldersStructurallyDisjoint = true
sourceVideoRecordingHashesVerified = false
frameToRecordingProvenanceVerified = false
actualPhysicalHivesIndependenceVerified = false
independentHoldoutVerified = false
splitReadyForTraining = false
trainingAuthorized = false
recognitionSucceeded = false
cleanupAuthorized = false
```

Прямые поддельные значения `sourceVideoSha256`, `recordingIndependenceVerified=true` в пользовательском JSON **не разрешают** обучение: выданные пользователем строки нельзя принимать за проверку реальных видео.

## Регрессии и безопасность

- Созданы отдельные Python тесты: **11** для real-source JPEG dHash, **14** для накопительного metadata-only CSV merge, **13** для group-proposal gate = **38** synthetic/offline случаев.
- Бесплатный workflow `.github/workflows/audit-mendeley-v6-scene-and-inventory.yml` проверяет реальную image similarity, real manifest inventory, предложение без разрешения training, все негативные тесты, и стирает временные derived JSON даже при ошибке. Он не публикует исходные JPEG, не использует аккаунт Mendeley, платные сервисы, копии видео пользователя, БД, приложение или модель.
- CI необходимо перепроверить на **финальном SHA** после обновления документов; успешность промежуточного запуска не приписывать последнему коммиту.
- Изолированный archive workflow `skipped` не считать прошедшим.
