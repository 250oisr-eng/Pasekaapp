## Сценарии приёмки

1. Журнал: один день / включительный период, CSV идентичен неархивной выборке; неверный диапазон блокируется до создания файла.
2. Матки: поиск/история; переход только при уникальных и актуальных ID матки, семьи, улья. Повреждённые индексы — сообщение, без перехода, записи и исключений.
3. Инвентарь: фильтр физического корпуса, офлайн CSV и корректное неизвестное число рамок; устаревшие/дублированные ID и неоднозначное расположение блокируют экспорт полностью.
4. Рамки: вощина/полоска — только «Вощина», сушь — 11 состояний; неверное сочетание блокирует commit без аудита/мутации; исторические записи не исправляются молча.
5. OP02: `gramsPerColonyPerDay` 100–200 г на семью в сутки, сироп 2:1, ежедневная белковая подкормка; курс 12–15 дней — ориентир. Только pending-модель; новый профиль B07 не активирован.
6. Совместное испытание: улей → семья → матка → осмотр/подкормка → корпус/рамка → CSV → повторный запуск; сравнить ID, фотографии, историю и offline state в отдельной synthetic IndexedDB.
7. До релиза дополнительно B01 backup/restore, B04/B05 signer/rollback, B09/B11 offline recovery, QA на OnePlus. Синтетический CI не является device proof.

**Запрещено без отдельного разрешения:** merge, deploy, production-обновление, восстановление и удаление реальных данных.
