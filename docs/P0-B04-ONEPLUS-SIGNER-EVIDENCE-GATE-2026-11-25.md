# B04/B05 — read-only аудит готовности обновления OnePlus
Дата: 25.11.2026. Основа main `bf2c451106e8c0cea71ad94c84b8ccb4d65ff8b3`. Контроль: AGENTS.md, PROJECT-CONTROL.md, реестр B01–B15, Draft #469.

## Подтверждённый код
В ещё не интегрированном Draft #469 находится `scripts/check-oneplus-upgrade.mjs`. Его `--installed-only` проверяет один авторизованный ADB device, выполняет `pm path ru.paseka.journal`, временный `adb pull` только `base.apk`, `aapt dump badging`, `apksigner verify --print-certs`. В `finally` удаляется только временная копия на стороне хоста. Команд install/uninstall/pm clear, private app data copy и restore в этой функции нет. Веточный код и CI сами по себе не являются фактическим снимком установленной версии.

## Блокирующие факты
- Отсутствует **полученный с рабочего OnePlus** packageName, versionCode и fingerprint реального подписанта; положительный synthetic-test не даёт эти факты.
- Не подтверждено контролируемое владельцем долгоживущее хранилище private signing key и его внешняя резервная копия.
- B01 полный внешний архив плюс независимое восстановление физически не доказаны, поэтому устанавливать даже совпадающий по подписи APK и переносить user data нельзя.
- Считать debug APK из CI подходящим для in-place upgrade запрещено; сравнение двух тестовых APK не доказывает signer уже установленного.
- Версия Android, service worker и модель данных в реальном OnePlus остаются непроверенными для безопасного upgrade.

## Решение F0–F7
**B04/B05 = EXTERNAL_DEPENDENCY / FROZEN_INSTALL.** Не делать повторных синтетических проб подписи без нового свидетельства. Отдельно допустим только read-only сбор подтверждённой identity при контролируемом доступе к устройству, вне production mutation, после чего записать byte-level результаты и разработать reversible plan. Без этих доказательств нельзя утверждать, что пользовательское «все разрешения даю» превратило опасный upgrade в восстановимую операцию.

Этот документ — аудит, **не тест устройства и не изменение запуска приложения**. Следующие независимые полезные задачи: B01 отдельный архив, B08/B11 регрессии, B15 ручной релизный gate. Никаких секретов и личных данных в Git.
