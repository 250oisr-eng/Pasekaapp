- `tests/archive-staging.test.mjs`: 9 дополнительных синтетических негативных сценариев (3 носителя защищённых копий × stage, late commit, rollback), проверка неизменности protected rows и live state. CI подтверждать только на фактическом кодовом SHA этого PR.

## Не включать автоматически

1. **PASEKA02 portable integration**: готовность изолированного codec/ledger не равна готовности восстановления реальной базы. Нужен scoped audit самих v2 snapshot/stage/commit/rollback contracts и миграций, чтобы не перезаписывать новые v1 проверки.
2. **Ledger/tombstones и все копии оригиналов**: проверка сторонних Camera/Gallery/Downloads, внешних Android MediaStore копий, staging, journal Data URLs, quarantine/full_backup; unverified => deletion blocked.
3. **Offline/Service Worker/IndexedDB migration**: сравнить актуальный runtime bootstrap, persistent schema и версии сохранённых данных до активации PASEKA02.
4. **Физический Android**: изолированное тестовое приложение, данные без реальных записей, подтверждённое сохранение ledger, rollback, перезапуск и восстановление; **никакое удаление оригиналов не разрешено**.
5. **Слияние/production**: только отдельное явное разрешение пользователя. Draft #408 не разблокирует main и Restore335.
