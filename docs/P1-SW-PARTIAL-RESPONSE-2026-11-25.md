# P1 — HTTP 206/204 нельзя сохранять как полную офлайн-оболочку (25.11.2026)

## F0–F2
Источник: установленный код `sw.js` в `main=fdcca080b68aa5b0014b8e99cd3e4f1d428e7ba2`. Исходный `cacheableResponse()` проверял `response.ok`, который допускает HTTP 206 (частичный ресурс) и 204 (без тела). Эти ответы непригодны как полноценные JS/HTML/иконки офлайн-оболочки, хотя могут стать доступны как успешная сеть. Риск: нерабочий офлайн-запуск, не доказанная реальная неисправность устройства.

F2 LIMITED_SAFE_DRAFT: только cache-policy, нет IndexedDB, медиахранилища, физических ульев, внешнего сервиса, пользовательских данных. Кеш приложения получает новую версию v319, чтобы старый v318 не был повторно использован как проверенный. Запрещено распространять или активировать на устройстве без B01/B04/B05 и отдельного разрешения release.

## F3–F5
- Только HTTP 200 + существующие `basic/default` и публичные Cache-Control могут сохраняться как shell. HTTP 204/206 не записываются, даже если `response.ok=true`.
- `install` не вызывает `skipWaiting` при неполном ресурсе; предыдущие кеши остаются нетронуты. `fetch` возвращает полученный 204/206 вызывающему коду без кеширования.
- Остаётся ограничение `SHELL_PATHS`, same-origin, только GET. Удаление CacheStorage разрешено только для прежних **точно именных версионных** shell кешей, пользовательские/будущие кеши не затрагиваются.
- Регрессии: `tests/service-worker-install-private.test.mjs`, `tests/sw-cache-boundary.test.mjs`, `tests/service-worker-offline-lifecycle.test.mjs`. Синтетическая проверка SW с Node VM не заменяет физический Chrome/OnePlus offline smoke.
- Для offline-функции требуются exact Fast/Android/Governance CI и отдельное реальное устройство перед release. Никаких удалений пользователя, переустановок или изменения production.
