## F0. Подтверждённое основание

Источник: пользовательский «улей для каждого техпроцесс.docx», раздел альтернативной зимовки: наиболее сильная семья на 2 корпусах, две остальные на одном каждая, два сетчатых разделителя между ними. Точные решения о том, какие конкретно корпуса и какой инвентарь остаются, должен ввести пчеловод. Дополнительные размеры, число рамок, открывание летков не выводятся алгоритмом.

Кодовая база: stacked Draft #453→#454→#455→#456→#458→#459; #457 — параллельный однотипный кандидат, **не объединять вслепую**. Main остается отдельным. Перед реальным применением обязательны данные, независимый archive restore с оригинальными Blob и отдельные device tests.

## F1. Контракт и ограничения

- Локальный источник берётся из единственной `sectionalLayouts` выбранного улья с профилем `sectional-multiqueen-v1`, ровно трёх 2-корпусных семей, ревизия должна совпадать с открытой формой. Чужие и устаревшие ID блокируются.
- Пользователь лично указывает сильнейшую семью (сохраняет два собственных корпуса), средний и верхний ярусы (каждый — свой зарегистрированный корпус), крышку, по желанию кормушку, две реально зарегистрированные **складские** сетчатые диафрагмы.
- Текущие `openings` выбранных корпусов сохраняются по ID. Объединённой матки не назначать, семей не объединять. Поле `technicalConnections` для зимней колонны снимается из целевой раскладки, соответствующие зарегистрированные принадлежности необходимо отдельно направить на склад.
- Каждое удаление корпуса или принадлежности требует введённого пользователем места хранения. Каждое реально изменившее позицию тело/предмет получает персональную галочку подтверждения. Неизменённые позиции не выдаются за перемещённые.
- Алгоритм создаёт только `targetLayout` и `itemDestinations`, затем передаёт их штатному `PasekaSectionalSeasonPhysicalManifestV2.plan`; **не вызывает CAS, IndexedDB, completion или запись событий**. Формулировка результата: проверен лишь предварительный манифест, не закончен full physical validation или actual work.
- Вход `sourceRevisionId` сохраняется от `inspectSource`; конфликт другой вкладки / восстановления требует заново открыть экран. Недостоверная дата, ложное подтверждение действия или неполная раскладка — fail closed через manifest.
- Совместимость: новые schema/store не добавляются; существующие v1 журналы, другие ульи, Farrar, видео, backup и offline media не модифицируются.
