# P1 — протокол физической проверки полного архива и сезонной модели (Android)

Дата: 2026-11-23. Draft PR #454. **Не является отчётом о проведённом испытании.**

## Цель и ограничения

Доказать восстановление **исходной** IndexedDB, включая все отдельные Blob-оригиналы `entrance_media`, на другом физическом Android; выполнить многосезонные сценарии OP-01–OP-14 (кроме незавершённой двухматочной ветви OP-06) без потери истории, ID и работы Farrar. Тесты Node, поддельная IndexedDB, SHA экспортированного JSON и Android-эмулятор не заменяют этот этап.

Отдельный диагностический пакет `ru.paseka.journal.disasterproof` предназначен только для тестовых данных. Он не должен иметь доступ к рабочей базе `ru.paseka.journal`. Синтетическое видео в таком пакете доказывает работу механизма, **не** восстановление реальных оригиналов PASEKA02.

## Подготовка и последовательность фактического испытания

1. Зафиксировать SHA APK, packageId, версию Android, точный источник архива и исходный `meta.revisionId`; остановить запись новых технологических операций на время резервирования.
2. На исходном устройстве создать полный архив `PasekaDisasterArchive.exportArchive`. Проверить `inspectArchive` с независимым пересчётом SHA-256, число object stores и число Blob-видео. Убедиться, что архив сохранён **вне телефона** и не является только копией внутри исходного IndexedDB.
3. Перенести неизменённый файл на **другое физическое Android-устройство**. Не передавать оригиналы медиа в GitHub, CI, ChatGPT или лог GitHub Actions; не тестировать восстановление поверх единственной пользовательской базы.
4. На отдельном устройстве восстановить архив в отдельной тестовой установке/изолированном хранилище без доступа к рабочей базе; перезапустить приложение/процесс и заново открыть IndexedDB.
5. Сверить SHA-256 полного экспортированного содержимого и независимые SHA каждого Blob, MIME, размер, идентификаторы видео; выполнить выборочное воспроизведение оригинального разрешённого ролика. Сравнить все stores, количество семей/маток/рамок и исторические события, включая сезонные циклы.
6. Проверить OP01–14 на тестовой копии, включая альтернативную зимовку OP12→OP13→OP14→новый OP04, журнал корпуса/рамки, отказ при физическом противоречии, offline cold restart и отсутствующий/частично повреждённый архив. Для OP06 с двумя матками ожидать **BLOCKED**, без физического снятия сеток.
7. Запротоколировать устройство-источник, независимое устройство-получатель, SHA APK, SHA архивов, фактические media counts/bytes, результат restore после перезапуска и инспекторы целостности. Любая несовпавшая запись ⇒ FAIL, без активации миграции или cleanup.
8. Только после независимого, воспроизводимого отчёта второй устройства может быть добавлена строго проверяемая возможность `SECOND_DEVICE_VERIFIED` для конкретного исходного revision; подтверждение факта локальным флажком/именем файла или результатом эмулятора **недопустимо**.

## Обязательные защитные проверки

- PASEKA02 original videos не удалять, пока реальная модель распознавания и полное внешнее восстановление не проверены; issue #442 FROZEN.
- Не очищать/перезаписывать исходные пользовательские данные. Сбой CAS/cold-read ⇒ `UNCERTAIN`, а не автоматический откат с потенциальной потерей изменений.
- Не смешивать `sectional-multiqueen-v1` с Farrar; не назначать выжившую матку после объединения автоматически.
- Не менять production database/schema, main, не сливать Draft и не публиковать без отдельных разрешений.
- Физические условия, отсутствующие в исходном DOCX, должны оставаться неизвестными/требовать уточнения.
