# Pascal VOC → COCO для проверенных локальных изображений пчёл (без train/test)

Дата: 2026-11-20. Status: **staging-only подготовка аннотаций, не обучение модели и не разрешение лицензии**.

## Подтверждённый исходный формат

Draft #272 действительно прочитал пару `ML-Data/Chueried_HempBox_1.xml` / `.jpg` из публичного LILA ZIP без полного скачивания архива: Pascal VOC `annotation/size/object/name/bndbox`, 1920×1080, пять объектов `bee`. Исследовательский GitHub run #44733392890 succeeded и проверил JPEG SOF с XML на 10/10 unit fixture tests. Это только один проверенный образец, не анализ 4993 изображений.

## Новый исполняемый модуль

`tools/convert_bee_voc_unassigned.py` — локальный CLI на Python standard library, без сети, платных сервисов и AI-модели.

```bash
python3 tools/convert_bee_voc_unassigned.py ./licensed_local_LILA/ML-Data ./output/unassigned_coco.json
```

**Важные ограничения:**
- Папка с изображениями и XML уже должна существовать и иметь разрешённое происхождение. Скрипт не скачивает LILA ZIP, не извлекает неизвестный архив и не читает приватные пользовательские видео.
- Требуется ровно одна одноимённая `.jpg` или `.jpeg` для каждого XML; посторонние JPG, отсутствующие пары, symlink, выход за каталог и слишком большие файлы отвергаются.
- Проверяются JPEG SOF width/height (это **не полное декодирование**), совпадение размеров и `filename` внутри VOC, безопасность XML и допустимость bbox.
- Поддерживаются только явно известные на карточке LILA названия классов `bee` и `pollen`; неизвестные имена отвергаются, а не превращаются в произвольный новый класс.
- Координаты Pascal VOC (xmin/ymin/xmax/ymax, абсолютные пиксели) преобразуются в COCO `[x, y, width, height]` с контролем границ. Считывается и сохраняется SHA-256 реальных JPEG в `images[].sha256`.
- Создаётся только **один** JSON, `info.split="unassigned"`, `info.trainingAuthorized=false`. Файлы JPEG остаются в source-root и не копируются; `file_name` в JSON — путь относительно source-root. Это **не самодостаточный training dataset**.
- Выход нельзя размещать внутри source-root; существующий JSON запрещено перезаписывать. Результат сначала записывается во временный файл в destination directory и публикуется только через `os.link` без перезаписи; при ошибке удаляется только **собственный временный файл**, не пользовательские исходники.
- Максимум 10 000 изображений, 500 000 bbox, 16 MiB на JPEG, 256 KiB на XML; больше — fail closed. Параметры обучения и source-video принадлежность не выдумываются.

## Почему набор остаётся unassigned

Имена файлов `Chueried_HempBox_1` и т.д. **не доказывают** идентичность исходного видеоролика/дня/улья. Без реального source-video provenance невозможно надёжно разделить кадры на train, validation и независимый test и получить достоверную оценку детектора. Предыдущий `tools/prepare-bee-coco.mjs` требует source IDs/SHA и физически проверенные JPEG хеши — подменять эти данные на фиктивные запрещено.

## Лицензия

LILA заявляет `CDLA-Permissive-1.0`: https://lila.science/datasets/boxes-on-bees-and-pollen . Официальный текст https://cdla.dev/permissive-1-0/ разрешает computational use и публикацию с условиями: при публикации полученных или изменённых данных требуется приложить ссылку/текст соглашения; сохранять имеющиеся атрибуции; помечать изменённые данные. Отсутствие в ZIP отдельного LICENSE по именам не отменяет публичное объявление на сайте, но права на конкретные изображения/источники и корректность атрибуции до распространения должны быть отдельно учтены. **Лицензия данных не является лицензией будущей обученной модели или предобученных чужих весов**.

## Проверки и следующий этап

`tests/test_convert_bee_voc_unassigned.py` — восемь тестов на преобразование bbox, классы, размеры, неполные пары, path/output safety и отсутствие автоматического train split. `tests/convert-bee-voc-unassigned.test.mjs` включает их в общий `npm test`. Результаты общего Android CI подтверждаются отдельно на точном SHA.

Следующий этап: получить полный разрешённый архив/подтвердить сведения о происхождении кадров; независимая группировка по видеосессиям/ульям, затем подготовка воспроизводимого YOLOX training-from-scratch. Реальный ONNX/Android inference и автоматическое удаление оригинального видео остаются выключенными.
