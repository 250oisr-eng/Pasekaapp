## F0–F2: ограниченное допустимое доказательство
Для полного архива важно, чтобы успех индивидуальных запросов `getAll/getAllKeys` не выдавался за завершённый снимок транзакции чтения. `getRecords` в main разрешает Promise только на `transaction.oncomplete`, отклоняет `onerror/onabort`, проверяет обязательные три store. До дополнительного теста это утверждение о коде, а не независимое регрессионное доказательство. **LIMITED_SAFE_DRAFT**: доступны локальные синтетические транзакции без пользовательской базы/телефона.

## F3–F4: инварианты и тесты
Создан `tests/disaster-archive-read-abort.test.mjs`, извлекающий **настоящую** функцию `getRecords` из текущего модуля, не дублирующий её реализацию. Пять случаев:
1. `getAll/getAllKeys.onsuccess` без `tx.oncomplete` оставляет Promise pending; успешный commit возвращает реальный store inventory.
2. `tx.onabort` **после всех успешных requests** отклоняет snapshot.
3. `tx.onerror` после частичного результата отклоняет snapshot; поздний oncomplete не делает его действительным.
4. Синхронный отказ создания `readonly` транзакции отклоняется.
5. Отсутствующий обязательный store отклоняется **до** создания транзакции.

Физическая оригинальная резервная копия, MediaStore, рабочий OnePlus, реальные видео и любые данные пасеки в тестах не используются. Изменений IndexedDB schema, `js/disaster-archive.js`, UX restore или APK нет.
