# План независимого Android preflight полного архива видео — 2026-11-22

Статус: **DESIGN ONLY / NOT EXECUTED**. Продолжение Draft PR #356; никакое сохранённое видео не открывалось и не удалялось.

## Цель и границы

Доказать на **отдельном тестовом APK и синтетических данных**, что архивные сценарии PASEKA01/PASEKA02 корректно обнаруживают неполные/повреждённые копии, отказывают в восстановлении при недоказанной сохранности и не модифицируют исходное хранилище. Это НЕ тест распознавания пчёл или удаления видео после распознавания.

## Изоляция

- Отдельный `applicationId`, отличный от production и прежних диагностических приложений. Не использовать production provider authority, sharedUserId, shared storage или production IndexedDB origin.
- Фикстуры создаёт только тестовый APK: синтетические записи журнала, source-bound ledger и искусственные короткие байты вместо MP4; реальные фото/видео, MediaStore и внешний архив пользователя не читаются.
- Никаких permission на камеру и медиа, никакой сети, облака или внешних AI-моделей.
- Экспортировать только обезличенный отчёт со status, code, packageId, build SHA, suite version, состоянием проверок, без URI, Blob, видео, персональных данных.
- Код диагностики не должен вызывать delete, очистку backup, production restore, миграцию пользовательского хранилища или завершение распознавания; `cleanupAuthorized:false`, `restoreAuthorized:false` в любом результате диагностического preflight.

2. Реализовать тестовый APK **в следующем отдельном code PR**, используя существующий read-only аудит, без включения нового функционала в production.
3. Добавить автоматические Node/fake-indexeddb регрессии по A01–A10; выполнить проверку исходников APK, packageId, отсутствия опасных permissions и заявленных сетевых вызовов.
4. На точном code SHA: регрессионный CI и debug APK build. Проверить статус success/failed/skipped отдельно, затем digest APK и содержимое пакета.
5. При наличии тестового APK — локальный запуск одной кнопкой на Android, отчёт PASS/BLOCKED через локальный файл. Не использовать экранные записи как подмену бинарных видео.
6. Если все тесты PASS, всё равно оставить фактический restore, реальный MP4 provenance, beeRecognition и удаление как **NOT_TESTED** до отдельной независимой проверки.

## Критерии запрета

Любая неизвестная версия формата, частичный ledger, конфликт источников, прерванная транзакция, отсутствие backup copy, неверный hash/length или несовпадение origin → BLOCKED / manual review. Ни один синтетический PASS не может активировать удаление настоящих видео.

- Удаление временного видео **только после доказанного распознавания и подтверждения политики сохранности оригинала**; пока оно запрещено.
