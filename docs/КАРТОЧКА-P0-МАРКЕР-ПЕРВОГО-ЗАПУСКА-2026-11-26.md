# Карточка F0–F6 — безопасный повторный запуск после потери IndexedDB

**Дата:** 2026-11-26. **Статус:** IMPLEMENTED_DRAFT / exact-head CI pending. **Исходная база:** main `e57279b6ca98df0cb99444618268efa5d3fe6eaa`. Отправная точка: [audit G](PR-AUDIT-CHECKPOINT-2026-11-26-G.md), исторический [PR #8](https://github.com/250oisr-eng/Pasekaapp/pull/8).

## A. Фактический сценарий и источник

Существующий `index.html` определял первичный запуск только по факту `indexedDB.open(DB,3)` с `oldVersion===0` и отсутствию записи `main`/автокопии. Полная потеря IndexedDB была неотличима от первого использования, что могло создать новую пустую пасеку. Это P0-риск сокрытия утраты истории (не доказательство реального удаления на OnePlus).

**Владелец данных:** пчеловод. Маркер хранит только `'1'`, не сведения о семьях, видео, местоположении, паролях или ключах. Архив/восстановление — отдельный B01, маркер не заменяет их.

## B. Feasibility и действия при ошибках

Используется стандартный браузерный `localStorage`, отдельный от IndexedDB, без платных API и Android permissions. Он доступен в обычном PWA/Capacitor WebView, но может быть недоступен/сброшен браузером. Прямой вызов осуществляется внутри `try/catch`; если чтение запрещено, значение повреждено либо прежнее использование подтверждено, **пустая база не создаётся**. При отсутствии маркера пользователь должен явно подтвердить, что это действительно первая установка. Отказ → нет первичного сохранения. Открытие существующих корректных данных не требует первичного согласия; после проверки основного состояния маркер ставится для следующих запусков.

Если запись/проверка маркера не проходит, запуск останавливается с предупреждением; исходный IndexedDB не удаляется. После полного удаления **обоих** хранилищ отсутствие маркера не доказывает первый запуск — явное подтверждение остаётся обязательно. Возможность восстановить медиа этим механизмом не заявляется.

## C. Данные и инварианты

| До / событие | Решение, без реконструкции данных |
|---|---|
| Первый запуск, `oldVersion=0`, main/backup нет, маркера нет | Обязательное информированное подтверждение; без него никаких main writes |
| `oldVersion=0`, маркер `'1'`, main/backup нет | BLOCKED, нет silent init и destructive reset |
| Любая ошибка чтения/записи маркера | Fail-closed startup, сохранённый main не удаляется |
| Существующий main корректен | Обычная проверка модели/миграции, без prompt; затем read-back state и маркер |
| main потерян, full_backup пригоден | Прежний атомарный rollback/recovery path, без подмены на пустую базу |
| Старая пустая IndexedDB, main/backup нет | BLOCKED существующим `canInitializeFreshDatabase`; не принимать за первую установку |
| Конкурирующие вкладки | Сохраняется `writeMainIfUnchanged` с проверкой `revisionId` и `db.onversionchange` |
| Сохранение основной базы не завершилось | Маркер не считается записанным до успешного `readMain` с проверенным `revisionId` |
| Профиль, семьи, медиа, IndexedDB store `entrance_media` | Не изменены |
| `deleteAllData`, исходные видео | Полная очистка остаётся жёстко запрещённой до B01/V0–V6 |

Никаких миграций данных, переименования store, изменения API медиа и развертывания. Версия shell Service Worker меняется v322→v323; сохраняются user/future caches.

## D. Негативные проверки и принятие

Отдельные тесты на fake-indexeddb: новый пустой store с согласованным первым запуском; отказ; существующая пустая база; сохранённое прежнее использование + полная потеря IndexedDB; corrupt/denied localStorage; проверка маркера только после durable write; восстанавливаемая full_backup; отсутствие прямого удаления и сохранение контроля версии cache. Целевой Android CI плюс регрессии на точном HEAD; успешная сборка не равна физической проверке OnePlus.

**Готовность:** CI_VERIFIED_EXACT_SHA после финального SUCCESS, но **не** IN_MAIN, не RELEASED, не PHONE_TESTED. Слияние этого нового PR требует отдельного разрешения, так как пользователь дал явно только #570/#571.
