# Передача работы между чатами ChatGPT

Эта инструкция нужна, чтобы разработка не зависела от длины контекста отдельного чата.

## Обязательная модель работы во всех чатах

Новый чат обязан применять единый порядок из AGENTS.md и docs/ПРАВИЛА-РАЗРАБОТКИ.md: один главный технический приоритет; свежая инвентаризация main/веток/открытых PR/CI; сначала модель данных и инварианты, затем доменная логика и валидаторы, затем UI; небольшие законченные блоки; один PR — одна логическая задача; отсутствие параллельных конкурирующих изменений одного файла или модели; карта зависимостей и интеграция stacked PR в правильной последовательности. Не дублировать уже существующие PR. Не закрывать/сливать старые PR без анализа diff, зависимостей и актуальности. Статусы «не начато», «в разработке», «реализовано», «проверено» использовать строго по критериям правил разработки.

## В начале каждого нового чата

1. Открой репозиторий https://github.com/250oisr-eng/Pasekaapp.
2. Прочитай AGENTS.md.
3. Прочитай docs/ПАСПОРТ-ПРОЕКТА.md.
4. Прочитай docs/ПРАВИЛА-РАЗРАБОТКИ.md.
5. Прочитай docs/ПОЛИТИКА-БЕСПЛАТНЫХ-СРЕДСТВ.md.
6. Прочитай docs/ПЛАН-РАЗРАБОТКИ.md.
6а. Прочитай docs/КАРТА-ОТКРЫТЫХ-PR-2026-11-17.md как снимок; перед действиями обязательно обнови live-состояние GitHub.
7. Прочитай docs/СВЕРКА-ТЕХПРОЦЕССА-С-ИСТОЧНИКОМ.md.
8. Прочитай docs/СОСТОЯНИЕ-ПРОЕКТА.md и последние записи docs/ЖУРНАЛ-ИЗМЕНЕНИЙ.md.
9. Проверь GitHub: текущий main SHA, активную ветку, открытые PR и статусы CI.
10. Проведи короткую инвентаризацию незавершённых PR и зависимостей (если их много — сначала полную карту); выбери один главный приоритет. Кратко сообщи пользователю: где остановились, что подтверждено, что не сделано, какой один следующий шаг.

Не проси пользователя заново описывать проект, если нужная информация есть в этих документах.

## В конце каждого рабочего сеанса

Обнови в той же ветке/PR:
- docs/СОСТОЯНИЕ-ПРОЕКТА.md — текущий этап, ветка, PR, точный SHA, результаты проверок, открытые вопросы и следующий шаг;
- docs/ЖУРНАЛ-ИЗМЕНЕНИЙ.md — что сделано, почему, какие файлы затронуты, что не менялось, результаты тестов;
- docs/ПЛАН-РАЗРАБОТКИ.md — только если изменился статус этапа или критерии завершения.

Перед завершением сформируй короткий handoff:
- подтверждённое состояние;
- последний commit SHA;
- ссылки на PR/CI;
- незавершённые задачи;
- запрещённые действия;
- конкретный следующий шаг.

## Внешняя AI-помощь

Если для независимого анализа полезны Qwen или DeepSeek, подготовь готовый запрос с необходимым контекстом и ограничениями. Пользователь сам переносит его в нужный чат и возвращает ответ. Сверь ответ с кодом, требованиями и источниками; не считай его утверждением пользователя. Не используй платные режимы и не передавай секреты.

## Если контекст потерян

Не восстанавливать детали по догадке. Повторно прочитать документы и GitHub. Если файл недоступен или исходник не приложен, честно сообщить об этом и попросить только недостающий материал.
