# OP-06 — восстановление трёхматочной схемы при отсутствии одной матки

**Основание:** отдельное подтверждение пользователя 23.11.2026. Это дополнение к исходному «улей для каждого техпроцесс.docx», а не дословная выдержка из источника. Относится только к профилю трёхсекционного многоматочного улья; Farrar не затрагивается.

## Завершённый технологический алгоритм

1. Пчеловод фактическим осмотром определяет, **в каком именно из трёх корпусов отсутствует матка**. Нельзя определять безматочность только по времени после разделения, без наблюдения.
2. В **этот безматочный корпус** переносятся **ровно две рамки с расплодом** из других корпусов, где матки присутствуют. Допустимо взять **по одной рамке из каждого** из двух маточных корпусов; это разрешённый вариант, а не обязательное распределение.
3. Перед перемещением пчеловод проверяет отсутствие матки на каждой переносимой рамке. У каждой рамки сохраняется постоянный ID; записываются корпус-источник, корпус-получатель и фактическое подтверждение переноса.
4. Если безматочный корпус **центральный**, имеющиеся металлические сетки **остаются на местах**; операция не должна автоматически снимать их.
5. Если безматочный корпус **левый или правый крайний**, **между ним и центральным корпусом** применяется **то же правило установки сеток, что и при первоначальном разделении единой семьи на три корпуса**. Нельзя автоматически применять его к другой границе либо считать все сетки снятыми.
6. После фактических действий наблюдение за появлением и яйцекладкой матки регистрируется отдельно. Перестановка рамок сама по себе не подтверждает появление матки и не завершает OP-06.

## Границы автоматизации и безопасность

- Для временной изоляции исходный DOCX описывает установку сетчатых заглушек на 8–11-й день после *первого разделения* и снятие после подтверждения плодных маток. **Срок повторной установки или снятия после нынешнего переноса двух рамок пользователь не устанавливал**. Нельзя механически запускать отсчёт 8–11 или 20–21 день от переноса; фактические условия должны быть подтверждены пчеловодом.
- Центральный корпус: сохраняются фактические существующие сетки; крайний: проверяется конкретная граница «крайний ↔ центральный» и фактические состояния сеток. Никакого автоматического действия с инвентарём.
- Если соответствующие сетки уже отсутствуют, повреждены или состав не соответствует исходной раскладке, требуются инвентаризация и ручное решение, а не фиктивная отметка «установлено».
- Отсутствие матки, наличие расплода, конкретные рамки, отсутствие матки на переносимых рамках, физическое перемещение, состояние сеток и последующая яйцекладка — **разные факты**. Их нельзя подменять одним checkbox или предполагаемой датой.
- До поддержки этой ветви полным атомарным OP-06 executor + журналом equipment/frames/queen observations и P0 archive gate существующий переход OP-06 с двумя матками остаётся **fail-closed**. Новый `PasekaOP06TwoQueenRecovery.plan` создаёт только проверяемую read-only инструкцию, не сохраняет DONE.
- Не затрагивать production IndexedDB, старые записи или видео; никаких миграций для этого read-only этапа.
