# Передача разработки другому ИИ или разработчику

Начните с корневого README и всех файлов в `docs/continuity/`.

## Обязательный порядок
1. Проверить текущую ветку, последние коммиты, открытые PR и их зависимости.
2. Прочитать описание задачи и фактический diff; не полагаться только на текст PR.
3. Найти существующие функции и тесты до добавления нового кода.
4. Работать в отдельной feature-ветке.
5. Не делать push в `main`, не сливать PR и не публиковать приложение без явного разрешения владельца.
6. Не добавлять платные сервисы, тарифы, API или автопополнение без отдельного согласия.
7. Не запрашивать у владельца пароли, коды 2FA или API-ключи в чате.
8. Не помещать секреты в исходники, тестовые фикстуры, документацию и логи.
9. Добавлять регрессионные тесты для исправлений и сценариев отказа.
10. В отчёте разделять реализованное, проверенное CI, проверенное вручную и оставшееся неподтверждённым.

## Запреты
- Не создавать фиктивные ульи, семьи и записи в рабочей базе.
- Не менять формат архива или схему IndexedDB без миграционных тестов.
- Не считать облачную синхронизацию включённой по умолчанию допустимой.
- Не удалять локальные данные при ошибке сети, авторизации или облачного сервиса.

## Формат завершения задачи
Указать ветку и PR, изменённые файлы, результаты тестов, известные ограничения, зависимости от других PR и точные действия, которые ещё требуются от владельца.
