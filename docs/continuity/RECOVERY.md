# План восстановления проекта

## Сценарий A: потерян доступ к ИИ или сервису разработки
1. Получить актуальную резервную копию Git.
2. Прочитать этот каталог `docs/continuity/` и корневой README.
3. Проверить открытые PR, их base/head и CI.
4. Продолжить работу в отдельной ветке; не менять `main`.

## Сценарий B: недоступен GitHub
Использовать заранее созданный локальный Git bundle или mirror-клон. Bundle должен быть создан на доверенном устройстве и храниться отдельно от устройства с рабочей копией.

Проверка bundle:
```bash
git bundle verify paseka-backup.bundle
git clone paseka-backup.bundle Pasekaapp-restored
cd Pasekaapp-restored
git branch -a
```

## Сценарий C: повреждена рабочая база приложения
1. Прекратить операции записи, не переустанавливать приложение и не очищать данные браузера.
2. Если приложение ещё доступно, экспортировать полный архив `.paseka`.
3. Проверить архив и контрольные суммы до восстановления.
4. Использовать штатный экран предпросмотра/восстановления.
5. Не восстанавливать старый архив поверх более новых записей без осознанного решения.
6. После восстановления проверить число ульев, семей, записей журнала и видео.

## Сценарий D: утёк или истёк секрет
Отозвать/ротировать только затронутый ключ в панели соответствующего сервиса. Не публиковать старый или новый секрет в issue, PR, чате и логах. После ротации проверить работу только зависимой функции.

## Важное ограничение
Локальные IndexedDB-снимки не защищают от потери телефона, очистки браузерных данных или отказа накопителя. Нужна отдельная внешняя копия архива и Git bundle.
