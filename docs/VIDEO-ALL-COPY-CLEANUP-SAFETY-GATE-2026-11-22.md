# Безопасность всех копий и протокол удаления видео — контрольный этап (22.11.2026)

Статус: **BLOCKED / NOT VERIFIED** для реальных пользовательских записей. Это проект безопасного протокола и read-only предохранитель, **не разрешение на удаление**.

## Факты исходного кода и пределы подтверждения

В текущем UI видео поступает через HTML `<input type=file capture="environment">`: камера/проводник могут создать внешнюю системную копию. Пользователь подтвердил, что основной APK `ru.paseka.journal` на телефоне не установлен; есть только диагностические пакеты. Поэтому физический аудит всех копий основной «Пасеки» сейчас невозможен.

`js/video-archive-v2-copy-inventory.js` уже выполняет единое readonly чтение `main`, `entrance_media`, `archive_staging`, `archive_history`, `full_backup`. Его отчёт обнаруживает управляемые копии по *метаданным*, но не доказывает их байтовую тождественность; неизвестные архивы и старые журнальные video Data URL остаются защищёнными. Копии в Android Camera / Gallery / Downloads / MediaStore и файловые кэши не перечисляются. Хэш в записи и одинаковый размер не означают, что все физические оригиналы найдены.

| Область | Что известно | Безопасность полного удаления |
| --- | --- | --- |
| `entrance_media` | IndexedDB Blob и записанные размер/SHA | NOT VERIFIED: повторная SHA каждого Blob и гонки |
| `main/state.records[].media` | Журналовые Data URL, в т.ч. старые без videoId | BLOCKED для legacy / неизвестного происхождения |
| `archive_staging` | pending originals, legacy video, rollback_video, rollback_state, opaque state | BLOCKED: защищённые и непрозрачные копии |
| `full_backup` | карантин, before/after, legacy state, другие неизвестные backup | BLOCKED: резервные данные не удалять |
| `archive_history` | Статусы и ссылки на операции, не содержимое всех архивов | NOT VERIFIED для полного происхождения |
| Внешние Android Camera / Gallery / Downloads / MediaStore | Нет доказуемой карты владения и URI | NOT TESTED, вне полномочий IndexedDB |
| Архивы вне IndexedDB, синхронизация и системные кэши | Полный перечень неизвестен | NOT VERIFIED |

## Реализованный отдельный программный предохранитель

`js/video-cleanup-preflight.js` не активирован в UI. `assess(db, guard, {source,videoId})` вызывает существующий readonly-инвентарь и выдаёт `status:'BLOCKED'`, `cleanupAuthorized:false`, `deleteAllowed:false` **без исключений**. Возвращает только количество и расположение найденных управляемых копий, ограниченные машинные коды блокировок, без Blob/Data URL и содержимого ошибок. При плохом ID, недоступности IndexedDB, невалидном отчёте и неизвестных копиях тоже блокирует. Входные флаги `cleanupAuthorized:true` не используются как доказательства.

Этот компонент НЕ создаёт новый путь удаления, НЕ выдаёт token/URL файлов и НЕ открывает readwrite-транзакцию. Тесты только с синтетическими IndexedDB/Blob.

## Будущий алгоритм, не активирован

1. **Контроль происхождения при захвате.** Новая съёмка только через отдельно проверенный in-app private capture; явное подтверждение, что приложение создало именно собственную временную копию. Выбор из Gallery/Downloads должен оставаться внешним пользовательским источником, удаление которого запрещено. Историческим файлам нельзя задним числом присваивать происхождение private capture.
2. **Зафиксировать исходник.** Оригинальные байты, уникальный videoId, SHA-256, размер, сеанс, версия состояния и provenance проверяются после перезапуска; все управляемые копии выявляются по проверяемому манифесту в момент создания. Если встречается неизвестная копия — запрет.
3. **Подтвердить реальное распознавание.** Проверенный офлайн детектор, достоверный результат привязан к SHA исходника и версии модели/данных; результат записан атомарно, прочитан после reopen и однозначно принадлежит видео. Завершение задачи, synthetic ONNX add-2 или состояние `completed` не являются подтверждением правильного распознавания пчёл.
4. **Установить точные границы удаления.** Исключить защищённые `full_backup`, `archive_staging`, карантин, restore/rollback, legacy, импортированные внешние файлы. Пока они содержат копию, не считать полное удаление состоявшимся. Потребуется отдельный протокол их безопасного жизненного цикла без уничтожения резервных данных.
5. **Атомарное намерение и обратимость.** В новой *тестовой* схеме сначала сохранять durable tombstone `deletion_pending`, snapshot revision, список собственных временных файлов и подтверждённый результат; повторно проверять непосредственно внутри IndexedDB транзакции. На сбой/повтор/конкурентный запуск отвечать fail-closed, без ложного `deleted`.
6. **Фактическое освобождение только собственных временных копий.** Потенциальное удаление разрешается только отдельным подтверждённым кодом после успешных Android физических испытаний; не выполнять auto-delete для Gallery / MediaStore / внешних URI и неизвестных оригиналов. IndexedDB удаление и файловая система Android не образуют одну атомарную транзакцию — обязательны recovery, повторная инвентаризация и явные статусы.
7. **Проверка после удаления.** Reopen базы, сверка истории/результата/tombstone, отсутствие принадлежащих приложению временных копий; физическая проверка Camera/Gallery на тестовом устройстве. При неизвестном результате писать `deletion_unverified`, не выдавать пользователю «всё видео удалено».

## Критерии для смены BLOCKED на разрешение

Независимый физический Android эксперимент на тестовых (не пользовательских) видео; provenance каждой временной копии; полная повторная SHA, сохранность результата; без потерь при power/process kill; отдельные тесты backup/restore/reopen; отсутствие новых разрешений на удаление внешних файлов; явное решение по retention резервных копий. Нужна отдельная ревизия архитектуры и явное разрешение пользователя на тестирование фактического удаления **только изолированных синтетических данных**. До этого **ничего не удалять**.
