# P1 — сквозная сезонная модель v2: текущее состояние и допуски
Дата: 2026-11-23. Ветка: `feat/p1-season-ledger-v2-contract-2026-11-23`, stacked Draft #454 поверх Draft #453. **Не в main.**
## Реализовано и автоматически проверяемо
- Многоцикловая модель: номера циклов, ровно один активный, проверяемое терминальное событие, immutable physical snapshots, v1 read-only dual-read и архив исходных записей; временный откат при ошибке подготовки, CAS для сохранения.
- OP-02 полный курс по ежедневно подтверждённым записям; OP-08 подтверждаемое извлечение запечатанных рамок; OP-09 личное наблюдение летков; OP-10 staged снятие 2/4 корпусов и двух решёток с возвратом крыши и подкрышников.
- OP-11/12/13/14 staged варианты физической раскладки, привязанные к lineage family/queen events и истории корпусов и рамок; настоящая матка после merge остаётся неизвестной.
- P0 full IndexedDB archive из Draft #452 (все stores, включая `entrance_media`, SHA-256), UI экспорта/проверки/восстановления с ручными подтверждениями. Дополнительно безопасный isolated replay в отдельной временной базе (не трогает текущую БД), сравнение SHA полного payload, включая оригинальные Blob.
- Защищённые runtime/migration/lifecycle CAS-мосты; нельзя использовать локальный replay как доказательство внешнего архива: требуется отдельный `verificationScope: 'SECOND_DEVICE_VERIFIED'`, `externalCopyConfirmed: true` с подтверждённым исходным revisionId. Никакая кнопка без такой доказательной функции не может активировать цикл.
- Мобильный read-only обзор сезонных историй. Service Worker v325 содержит только реально загружаемые модули.
## Не завершено
- Полный безопасный ввод данных через UI OP-04–07 и OP-08/10–14 с актуальной раскладкой, конкретными ID маток/корпусов/решёток/рамок; coordinator v1 не может обслуживать последующие циклы без v2-adapter.
- Runtime bridges ещё не подключены к production-кнопкам: нет реального second-device proof, пока нет завершённых full archive+restore демонстраций на OnePlus; отключать эти ворота запрещено.
- OP-06: в подтверждённом двухматочном исходе снятие временных сеток **BLOCKED**: источник не содержит доказанной процедуры. В трёхматочном исходе требуется подтверждение реальной яйцекладки и состояния маток.
- Нужны real-device приемочные E2E многосезонного цикла, полная история предметов до/после, P0 реальный полноразмерный архив и обратное восстановление на другом Android, регрессии Farrar/offline/service worker, независимый аудит final HEAD.
## Что считать завершением
Все OP-01…14 проходят отрицательные и позитивные физические тестовые сценарии с одним UI, atomically durable save, cold reopen, off-device full-media restore, history immutability, stock/lineage invariants, фактическим устройством; нет ни одного обхода валидаторов. Затем — отдельное разрешение пользователя на слияние конкретного PR, публикация — отдельный допуск. **Пока P1 не считать завершённым.**
