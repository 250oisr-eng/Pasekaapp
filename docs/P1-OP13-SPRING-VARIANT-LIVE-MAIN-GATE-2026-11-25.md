## F0–F2: подтверждённая развилка из оригинального DOCX

| Параметр | Обычное весеннее развитие (абзацы 72–74) | Подготовка к раннему медосбору (абзацы 74–79) |
|---|---|---|
| Решение пчеловода | Не стремиться получать ранний мёд, дать отводкам развиться | Получить ранний мёд при подходящих условиях взятка |
| Старт | После облёта **не сразу** отделять, дождаться развития и смены пчелы | Дождаться, когда два отводка достаточно усилятся при совместном тепле |
| Время | «Около полутора месяцев» — **ориентир**, не автоматическое разрешение или факт выполнения | Жёсткий автоматический срок не указан |
| Физические действия | Позднее отделить два отводка на собственные днища; далее наращивать корпуса при фактическом развитии | Дать два дополнительных днища, отделить два верхних отводка, убрать диафрагмы; **по одному дополнительному пустому гнездовому корпусу на каждую молодую семью** |
| Медовый ярус | Не является обязательной частью данного разделения | Позднее, при фактическом приближении/начале подходящего раннего взятка и хорошей погоде — две разделительные решётки и два медовых корпуса; преимущественно сушь |
| Подтверждение | Реальное развитие и перемещение подтверждает пользователь | Тоже обязательна личная проверка развития, фактической конфигурации и операций |

**Нельзя** применять два дополнительных корпуса раннего варианта автоматически к обычному. Не превращать совет по сроку или погоде в записанное выполнение, не выдумывать норму подкормки для этой ветки. Медовые корпуса устанавливать парами (подтверждённое пользователем общее правило 2 или 4); конкретный описанный ранний вариант устанавливает 2.

## F3–F4: разрыв текущей реализации и старой цепочки PR

Live `main` на исходном SHA содержит `js/sectional-operation-coordinator.js`, но **не содержит** `js/sectional-season-op13-guided-v2.js`, `js/sectional-season-runtime-v2.js` или `js/sectional-physical-browser-commit-v2.js`. Их нельзя считать активированными. Его `sw.js` использует старое дерево shell v338, тогда как live main shell v318 с отдельными правилами cache ownership. **Целиком сливать старую цепочку без переосмысления и регрессий нельзя.**

## F5–F7: минимальная следующая безопасная цепочка

1. На новой основе main выделить **один** физический read-only план с явным вариантом `EARLY_HONEY_PREPARATION` или `REGULAR_DEVELOPMENT`, без молчаливого значения по умолчанию, с отдельными подтверждениями развития и physical inventory.
2. Сначала договориться о read-only модели двух вариантов (обычное развитие не имеет права запускать ранний 2+2+2 target); только затем — source-bound тесты на старые Farrar записи, семьи/матки/сетки/корпуса, CAS и защиту восстановления.
3. Не подключать новый OP13 v2 к живому интерфейсу, `sw.js`, startup/save или транзакциям IndexedDB до поддержки всех модулей физической модели, совместимости и локальных валидаторов.
4. Для будущего фактического выполнения нужны достаточные внешние B01 backup/recovery, B04/B05 signer при обновлении APK, физический OnePlus E2E и пользовательские подтверждения каждой операции. `CI_VERIFIED` ≠ `DEVICE_VERIFIED`.
