# UI — быстрый поиск → история конкретной семьи

Дата: 27.11.2026. Продуктовый запрос: PR #600, выборочный перенос на актуальный main `f67ca3427fd6c352011b8628d7359ebdaa8e0d3d`.

## F0–F2: назначение и ограничения

Цепочка «Обзор → быстрый поиск семьи → история семьи → обратно к выбранному улью». Существующий main уже имеет историю семьи (#598) и поиск прямых переходов к записи/корпусу (#599). В старом #600 (`fbd78afeccf9f65c806014178b697bbbb03289e9`) было ровно две изменения для семей; переносить его старую ветку целиком запрещено из-за изменившейся базы.

Если ID семьи неоднозначен, семья удалена или перенесена между ульями после формирования поиска — никаких чужих карточек: обновить выдачу и показать предупреждение. При прямом открытии карточки из улья сохранить существующее поведение. Операции только read-only, состояние IndexedDB не менять.

F2: **LIMITED_SAFE_DRAFT**. Локальный HTML+JS, без миграций/внешней сети. Режим офлайн сохраняется. Реальное устройство не требуется для разработки, но является отдельным последующим UX gate.

## F3–F4: минимальное изменение

В `index.html` функция `openFamilyHistory(id,sourceHiveId)` проверяет ровно одно соответствие по ID, фактическое размещение семьи и существование улья. Для результата поиска сначала открывается нужный улей, затем существующий `familyHistoryDlg`. При невалидном результате происходит только обновление выдачи и предупреждение без навигации. Прямые карточки из улья используют прежнюю схему без нового предупреждения, если семья недоступна.

В `openGlobalSearchResult` только `kind==='family'` вызывает историю; `hive`, `frame`, `record`, `corpus` сохраняют свои действующие пути. Профиль улья, OP, физическая сборка, видео, IDB, backup/restore, PWA/SW и маршруты 4–3–4 не меняются.
