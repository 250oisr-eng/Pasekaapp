# B04 — безопасная проверка фактически установленной подписи Android (F0–F7)

**Основа:** `main=f106e2aa7990ecc5c5ebf99baf5a3c45c54738b1`. **Предшественник:** [Draft #469](https://github.com/250oisr-eng/Pasekaapp/pull/469). Новый PR переносит **только** независимый локальный инструмент из большой конфликтующей ветки, не переносит её `index.html`, старые миграции, секреты и release workflow.

## F0–F2
Нельзя считать новый APK совместимым с установленным OnePlus только на основании CI debug signer. Фактический установленный `ru.paseka.journal` требует read-only проверки package/versionCode/signing SHA-256. Источник — проектные B04/B05 и пользовательские факты устройства. Нет возможности подтвердить текущий аппарат без авторизованного ADB.

## F3–F5
`node scripts/check-oneplus-upgrade.mjs --installed-only` запрашивает ровно один авторизованный ADB device, читает `pm path`, временно извлекает **только** `base.apk` на компьютер, считывает `aapt dump badging` и `apksigner verify --print-certs`. Не создаёт keystore, не устанавливает/не удаляет приложение, не вызывает `pm clear`, `force-stop`, не читает пользовательский IndexedDB/видео. Веточный код расширен строгой проверкой **ровно 64 hex** символов SHA-256 fingerprint и запретом нескольких несовпадающих путей `base.apk`. Поддельный префикс и неоднозначный APK → BLOCKED. `--compare-files` остаётся **только сравнением метаданных** двух файлов, а не доказательством установленного пакета.
Тесты подменяют команды ADB/SDK, не обращаются к телефону. CI проверить на точном кодовом и финальном SHA.

## F6–F7
Включение CLI в `main` **не** запускает его и не подтверждает сертификат OnePlus. B04/B05 остаются BLOCKED/EXTERNAL; нужен доступ к телефону и независимый внешний B01 backup/restore прежде чем разрешать in-place upgrade. Нельзя передавать содержимое APK, личные файлы или приватный signing key через PR/CI.
