# P1 — OP-01…OP-14: аудит реализации и ворота готовности

Контрольная дата: 2026-11-23. База: main `13c724a634f0987ff634a058a5fa37a1b8e20c92`. Источник: файл пользователя **«улей для каждого техпроцесс.docx»** (транскрипция). Номера OP-01–OP-14 — **внутренние ID приложения**, отсутствуют в источнике. Отдельно подтверждённые параметры пользователя отмечены явно.

## Итог по физической и программной модели

- **В main**: `sectional-operation-coordinator.js` имеет `completeOP04`, `completeOP04SecondRow`, `completeOP05`, `completeOP06`, `completeOP07`; `sectional-physical-layout.js`, `family-lineage.js`, `equipment-inventory.js`, `equipment-items.js`; состояние `sectionalTechProcesses` в IndexedDB и backup-пути. Существуют unit/regression tests этих переходов.
- **Не найдено в runtime main**: вызовов завершения `completeOP04(...)` и аналогичных из UI (глобальный объект только используется в integrity checks), прямых OP-08–OP-14 completion APIs. Наличие физического validator не означает, что пользователь может выполнить операции.
- **В данном Draft**: новый источник-ориентированный **только для чтения** справочник всех OP в разделе оборудования, со статусом `coordinator_only` для OP-04–07 и `not_implemented` для остальных. Он не активирует профиль `sectional-multiqueen-v1`, не меняет S, IndexedDB, маток, летки или инвентарь. Не использовать эту карту как подтверждение готовой технологии.
- **Блокер полного ввода**: по каждой физической операции нужны UI → local preflight → доменная проверка → единый durable commit → обновлённая история и инвентарь → reopen → offline → архив/restore. Пока цепь не доказана, статус NOT_READY.

## Открытые вопросы (нельзя придумывать)

1. Безопасный порядок снятия временных сеток при **двух** подтверждённых плодных матках: DOCX не даёт отдельного перехода OP-06. BLOCKED.
2. Неизвестные конструктивные варианты технических отверстий вне описанной схемы и комплектность постоянного буферного коридора: не расширять физические ограничения на другие ульи.
3. Точные варианты подтверждения готовности мёда и порамочных наблюдений для физического OP-08/OP-14. До подтверждения допускается только ручная запись наблюдения без автоматического вывода готовности.
4. Последовательность OP-14 содержит две альтернативы. Для UI можно отобразить обе, но нельзя предполагать, что пользователь выполнял любую из них.
5. Пользователь подтвердил **две большие решётки** и медовые корпуса только 2/4; не превращать число временных сеток или постоянных технических решёток в те же значения.
