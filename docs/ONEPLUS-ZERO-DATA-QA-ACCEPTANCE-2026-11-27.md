## Контракт и ограничения F0–F2

- **Цель:** за минимальное число сеансов закрыть проверяемые задачи: компиляция и подпись тестового бинарника; старт и навигация Android; долговечность локальной тестовой записи; холодный офлайн; UI/доступность; read-only копия созданных синтетических данных. Для видео — отдельно установить работоспособность камеры/записи при наличии такой функции; **не** утверждать распознавание пчёл.
- **Входные ресурсы:** только OnePlus, доступ к скачиванию QA APK, встроенная память и краткие искусственные записи. ПК/USB нужны только для расширенной проверки SHA, ADB, независимой физической копии и сложных сбоев — не обязательны для первого сеанса.
- **Среда:** отдельный disposable QA Android package `ru.paseka.journal.qa` с именем «Пасека QA — тест», собственной Android-песочницей. `ru.paseka.journal` не устанавливать/не обновлять; не очищать ни один другой пакет или браузер. Использовать только файл `PASEKA-ONEPLUS-QA-ONLY.apk` из прошедшего CI этой ветки, сверив `QA-PROVENANCE.json` (SHA исходного коммита, SHA-256 APK, package ID и публичный cert fingerprint).
- **Принцип сборки:** `capacitor.config.json` изменяется только внутри временной CI checkout, после `npm run web:prepare`; собранный `applicationId` и фактический APK проверяются независимо. Оригинальный конфиг main не меняется. Debug-сертификат CI временный, поэтому in-place update этой QA-версии **не обещается**; изменения пользовательских тестовых данных надо экспортировать, а не переустанавливать поверх.
- **Доступ к внешним ресурсам:** не входить в настоящую Neon/Cloudflare учётную запись; не загружать синтетику в облако. Для локальных тестов включать авиарежим. Не использовать настоящее имя/координаты/телефон/пароли в тестовых записях.
- **Стоп:** несовпадение ID/подписи/хеша, неподтверждённое происхождение APK, запрос удаления, доступ к существующим данным, невозможность отличить QA от рабочей версии, несогласованная запись на диск вне QA, непрошедший CI. Фиксировать FAIL/BLOCKED, не обходить проверку и не устанавливать опасную сборку.

## Четыре цикла (не объединять искусственно)

| Цикл | Действия разработчика, без телефона | Действия пользователя на OnePlus | Доказательство и критерий |
|---|---|---|---|
| 0. Автоматический, до установки | Проверить текущий main SHA, full `npm test`, отдельную QA-конфигурацию, точные CI по коду, собрать и проверить **фактический** QA APK и signer; сохранить артефакт с provenance | Нет | `CI_VERIFIED_EXACT_SHA` + `BINARY_PROOF`, но не device pass. Если CI красный/отсутствует — не отправлять APK на установку |

| 2. Синтетическая запись и offline | Повторно использовать существующие валидаторы/IDB/старые schema-regressions, без создания нового тестового фреймворка | В QA создать условный улей `QA-UL-01` **под существующим поддержанным профилем**, одну тестовую запись наблюдения `QA-НЕФАКТИЧЕСКАЯ-ЗАПИСЬ`; перезапустить QA; проверить сохранение и отсутствие дубликатов; включить авиарежим, полностью закрыть QA через список приложений, запустить снова, прочитать и при необходимости изменить лишь тестовую запись | Прошла запись → реальный commit → перезапуск → повторное чтение → редактирование; офлайн не должен требовать сети для локального журнала. Сам экспорт и внутренний fake-IDB **не равны** полному независимому Android restore, B01 остаётся открыт до отдельного безопасного восстановления на чистой цели |

**Почему цикл 4 отдельно:** у пользователя нет оригинального видео пчёл, разрешённых конкретных весов детектора и эталонной разметки. Пустая/синтетическая запись не проверяет распознавание; автоудаление (PASEKA02 #442, V0–V6) остаётся **FROZEN**, даже при PASS для камеры.

**STOP после каждого цикла:** один доказанный дефект → целевое исправление → повтор только затронутого сценария + регрессия. Не ставить десятки раз старые диагностические APK. Пользователь передаёт один обезличенный результат, разработчик сам разбирает CI, логи и исходники, заводит отдельный Draft при необходимости.

## Границы публикации/внедрения

Создание APK в CI и его скачивание **не являются** выпуском в production. Нет merge в `main`, Pages/Cloudflare deployment, изменений рабочей IndexedDB, новых Android permissions или разрешения на удаление. QA APK с отличающимся applicationId не заменяет испытаний совместимого обновления рабочего пакета и полной резервной копии. Для реального релиза необходимы отдельный допуск, стабильный signer, доказанная история и физическое восстановление.
