## Следующая контрольная точка — обновление существующей установки, без очистки данных

**Входное условие:** `DEVICE_FIRST_USE=USER_REPORTED_PASS`; на OnePlus теперь есть синтетические данные. Повторное чистое тестирование **не требуется**. Следующий полезный сценарий — сохраняются ли улей, семья и обе заметки при обновлении приложения.

**Ворота перед первой установкой обновления:**
1. Обозначить точный APK `candidate SHA`, `appId`, `versionCode` и fingerprint сертификата подписи, сопоставить их с установленным APK. GitHub ZIP digest не эквивалентен SHA APK или сертификату; пользовательские слова «установил» не заменяют эту проверку.
2. Убедиться, что обновление не требует `adb uninstall`, очистки хранилища, удаления приложения или перехода на другое packageId; при несовпадении подписи блокировать upgrade.
3. Проверить реальную пригодность резервной копии **до** теста изменения storage/migrations. Текущий legacy JSON download может не включать полные бинарные медиа, а полный P0 restore остаётся отдельным Draft #452. Сохранённые на телефоне тестовые данные не считать несуществующими, даже если не содержат медиа.
4. Если нельзя безопасно подтвердить пункт 1–3, **не устанавливать обновление** на этот телефон; вести дальнейшие CI/эмуляторные проверки без касания пользовательского приложения. Не выдавать синтетические тесты за upgrade-device proof.
5. После допуска выполнить обновление **без удаления**, проверить прежний улей, семью и обе заметки, добавить одну новую тестовую запись, повторить офлайн-перезапуск. Зафиксировать версию и результат. Это отдельный gate `DEVICE_UPGRADE_E2E`, который пока `NOT_TESTED`.

`#452` full backup/restore, `#469` first-use gate и `#442` video cleanup не объединять автоматически и не выдавать за один готовый production-релиз. Merge и release требуют отдельных разрешений.
