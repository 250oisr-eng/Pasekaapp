# B11 — защита офлайн-оболочки от успешного HTTP-редиректа

Дата: 2026-11-25. Связанный [Draft #515](https://github.com/250oisr-eng/Pasekaapp/pull/515), кодовая база `d2c5242dae5321fa500734c47ec6547ebc1445d3`.

## F0–F2: контракт и ограничение

В #515 уже запрещены неполные HTTP 204/206 при сохранении PWA shell. Но ответ HTTP 200 после перенаправления (`Response.redirected===true`) проходит через `cacheableResponse` и может кэшировать не исходный JS/HTML, а страницу входа или другую страницу сервера. Это подтверждённый **путь в коде**, не доказанный инцидент на реальном OnePlus.

Пользовательский сценарий: скачать/запустить PWA онлайн, затем пользоваться только подлинной полной офлайн-оболочкой. Если сервер вместо ресурса перенаправляет запрос, новая оболочка не активируется и ошибочный ресурс не попадает в кеш. Сеть остаётся авторитетной для текущего ответа, но кэшировать под исходным путём перенаправлённый файл нельзя.

F2 = LIMITED_SAFE_DRAFT: изменяется только SW cache policy. Не меняются IndexedDB, медиа, профили ульев, пользовательские CacheStorage, Android APK, production. Установка/публикация запрещена без B01 backup/restore, B04/B05 signer/rollback и явного разрешения.

## F3–F5: правило и регрессии

`cacheableResponse` дополнительно требует `response.redirected!==true` при прежних условиях status 200, basic/default, отсутствие private/no-store. Не менять прежний cache namespace v319 и правила удаления только старых строго именованных shell cache.

Два теста:
- `tests/service-worker-install-private.test.mjs`: перенаправленный 200 отклоняется до `skipWaiting`; asset отсутствует в кешe.
- `tests/sw-cache-boundary.test.mjs`: во время обычного fetch перенаправленный 200 возвращается вызывающему коду, но не кэшируется.

Существующие проверки 204/206/404, private/no-store, user cache, offline fallback и соседних assets должны продолжать проходить. Полный CI на точном SHA; реальный cold-offline OnePlus остаётся NOT_TESTED.

## F6–F7: интеграция

Stacked Draft на #515, **не самостоятельная опубликованная версия**. Без merge родителя, APK update, deployment, очистки user data или удаления видео. Release и физическая проверка отдельно, только после подтверждённых ворот B01/B04/B05.

## Дополнительный B11 gate: query-specific shell responses

Повторная проверка показала, что обычный `fetch` мог записывать под общим namespace оболочки успешный ответ `index.html?token=…` либо `js/hive-model.js?session=…`. При дальнейшем `cache.match({ignoreSearch:true})` такой вариант потенциально мог использоваться как основной ресурс. Это кодовый риск смешения канонических и query-specific ресурсов, **не доказанный инцидент**. Новый предикат `!url.search` при *записи* в кеш оставляет онлайн-ответ доступным вызывающему коду, но сохраняет офлайн-оболочку только для путей без параметров. Чтение через прежний `ignoreSearch` и fallback не меняются.

Новые негативные тесты: HTML-навигация и JS-ресурс с synthetic query не вызывают `cache.put`, канонический JS без query по-прежнему кэшируется. Реальные секреты в тестах отсутствуют; IndexedDB и запись оригиналов не затрагивались.
