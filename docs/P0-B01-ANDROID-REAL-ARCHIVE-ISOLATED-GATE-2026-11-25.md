# B01 — чтение реального архива в отдельной Android-среде (только план физического теста)

Дата: 2026-11-25. Код: Draft PR #534. Не запускать на рабочем OnePlus.

## Подтверждено до этапа

- Установленная `ru.paseka.journal` на OnePlus не менялась.
- Исходный реальный архив: 299 687 байт, полный SHA256 `049cec79d7e0a49c5fc2ca33f81d0b9871ca141e8fdf58aecbdd2307c37c98ff`. Payload SHA256 `bc837c49744e2b03d489f7d35f959afdae717a85b14e828c7eb1763f2252f107`.
- Источник и копия на другом **логическом** томе ПК: SHA256 MATCH. Другой физический диск не доказан.
- На ПК архив уже восстановлен в пустую in-memory IndexedDB, затем закрыт и открыт с byte verification — PASS.
- Синтетический тест на Android emulator API35, отдельный APK `ru.paseka.journal.disasterproof2`: restore/restart PASS на SHA `17c67787d42c7fcd74e84c34443c12d904d04f64`. Не путать с реальным архивом.

## Новый диагностический сценарий

Файлы `diagnostics/disaster-phone-proof/owner-archive-runner.js` и `scripts/prepare-disaster-phone-proof.mjs` подключают локальный `<input type=file>` **только** в тестовый APK. При выборе пользователя:

1. Проверить версию архива, размер **299687**, exact whole-file SHA256, manifest payload SHA256 и три обязательных stores с точными counts `main=1`, `full_backup=1`, `entrance_media=0`.
2. Убедиться, что отдельной базы `paseka-b01-owner-disposable-v1` **не существует**. Если она есть — `BLOCKED`; никакого удаления/очистки ради повторения.
3. Создать лишь эту новую пустую IndexedDB в **отдельном** диагностическом приложении. Восстановить туда полный архив через проверенный `PasekaDisasterArchive.inspectArchive` и `atomicRestore`. Исходный файл не трогать.
4. Проверить SHA/счётчики после записи и после закрытия/повторного открытия базы.
5. Вывести обезличенное `PASEKA_B01_ANDROID_OWNER_ARCHIVE_REPORT` со статусом `PASS_TARGET_READBACK_NOT_PROCESS_RESTART`. Этот статус **НЕ доказывает перезапуск процесса Android**.
6. Только после внешне подтверждённого `adb shell am force-stop` **конкретного диагностического пакета** и повторного открытия ждать `PASS_READBACK_AFTER_RELAUNCH_DEVICE_CLASS_UNVERIFIED`. Без доказанного `ro.kernel.qemu=1`, package ID и ADB-журнала этот второй статус **НЕ означает** подтверждённый Android-emulator reboot proof.

Скрипт не запрашивает разрешения на доступ к `ru.paseka.journal`, не отправляет пользовательские данные по сети, не вызывает upload/fetch/XHR и не выводит значения записей. Исключения редактируются до коротких безопасных кодов; JSON и имена семей не выводятся.

## Условия физического прогона (пока НЕ выполнены)

Исполнять только на доверенном ПК с установленными Android SDK/emulator, отдельным AVD Android API35 и ADB. Не выполнять установку APK, импорт или `adb push` без предварительного **однозначного подтверждения**, что цель — именно эмулятор, а не рабочий OnePlus:

- `adb -s emulator-5554 get-state` = `device`, `adb -s emulator-5554 shell getprop ro.kernel.qemu` = `1` и `adb -s emulator-5554 shell getprop ro.build.version.sdk` = `35` (или отдельно подтверждённая совместимая версия).
- До переноса архива эмулятор обязан быть в режиме полёта (`settings get global airplane_mode_on=1`) и без default route (`ip route`); при наличии сети `BLOCKED`. Использовать AVD без подключённого Google-аккаунта. Это защита от случайной передачи данных, но не доказательство абсолютной изоляции.
- Запускаемый APK **только** `ru.paseka.journal.disasterproof2`, а не `ru.paseka.journal`. Проверить идентификатор из manifest и SHA256 отдельного APK.
- Копировать на этот тестовый эмулятор лишь **дополнительную** копию архива (с исходного ПК файла без удаления/переименования), например в Downloads через `adb -s emulator-5554 push`. Файл не должен попадать в GitHub Actions, публикации, артефакты сборки или журналы.
- Запустить тестовый APK, выбрать JSON через локальный файловый селектор и сохранить **только обезличенный** отчёт. При `BLOCKED` остановиться; не чистить тестовую базу ради успеха.
- Для process-persistence: после первого PASS внешним ADB остановить **только тестовый пакет** и запустить его снова, затем сверить отчёт. Никаких команд к рабочему `ru.paseka.journal`.

## Не доказано и не разрешено

До выполнения физического теста с самим пользовательским JSON: реальный архив → Android WebView restore/reopen **NOT_TESTED**. После возможного PASS этот сценарий подтвердит только **локальную отдельную тестовую среду**, но не обновление установленной APK, не перенос через production-подпись, не проверку Android rollback и не безопасность удаления видео. B01 частично закрыт, B05 и #442 остаются BLOCKED/FROZEN.

Проверки выполняются на CI только с синтетическими файлами. Исходный JSON, его содержимое и ключи не добавлять в репозиторий.
