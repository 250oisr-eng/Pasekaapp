## F1 — гарантированная граница тестового пакета

- Код `scripts/prepare-p1-oneplus-smoke.mjs` запускается **после копирования в `www/`**, заменяет `capacitor.config.json` только внутри окружения CI на **отдельный** `ru.paseka.journal.p1smoke` и вставляет тестовый runner в копию HTML. Рабочая версия Android `ru.paseka.journal` не обновляется. Отказ при другом исходном appId/неоднозначном HTML.
- `diagnostics/p1-oneplus-smoke/runner.js` — экранная проверка **фактической загрузки** 14 OP и модулей physical manifest + guided OP11/12/13/14 в Android WebView. Проверка трех fail-closed вариантов OP13 выполняется без доступа к настоящей базе: обычный маршрут заблокирован, неизвестный вариант заблокирован, отсутствие личного наблюдения силы семей заблокировано.
- Диагностика дополнительно требует, чтобы небезопасный до восстановления реального архива `PasekaSectionalPhysicalBrowserCommitV2` **не был загружен в живую оболочку**. В раннере нет команд IndexedDB, сетевых запросов, CAS, удаления пользовательских медиа и архивов. Для различения повторных запусков он использует только **отдельный локальный маркер** тестового пакета.
- Визуальный результат `P1_ISOLATED_PREVIEW_SMOKE_PASS` означает лишь **запуск и доступность read-only модулей WebView**. Поля `p1ReleaseReady=false`, `independentSecondDeviceArchive=NOT_VERIFIED`, `p1CasPersistence=NOT_TESTED`, `forceStopObserved=NOT_DETECTABLE_BY_WEBVIEW` запрещают трактовать его как полную приёмку.
- Android target/min SDK **35** (Android 15+). Зависимость от Android реального OnePlus и его системного поведения может быть подтверждена только после установки APK пользователем. **Никакой APK не устанавливался на телефон из GitHub Actions.**

## F2 — минимальные действия для физической проверки на OnePlus

Испытывается только изолированный пакет. Оригинальное приложение не удалять, не сбрасывать и не очищать.

1. Открыть на OnePlus [выполненный CI run #45348217564](https://github.com/250oisr-eng/Pasekaapp/actions/runs/45348217564) → **Artifacts** → скачать `paseka-p1-oneplus-isolated-smoke-apk` → распаковать ZIP. Внутри должны быть `app-debug.apk` и манифест с **указанным выше SHA-256**. Не брать обычный `paseka-debug-apk`: его пакет совпадает с рабочим.
2. Установить **только** этот test APK на отдельный ID `ru.paseka.journal.p1smoke`. Если система Android попросит разрешить установку для проводника, выдать разрешение только этому источнику на время установки; после установки можно отозвать. На телефоне появится `Пасека · P1 Проверка TEST`. Рабочие приложения и пользовательский архив не изменять.
3. Открыть тестовое приложение с обычной сетью. **Проверить лично** экран с `P1_ISOLATED_PREVIEW_SMOKE_PASS`; зафиксировать его скриншотом или кнопкой «Скопировать результат». Если видна ошибка `BLOCKED`, сохранить конкретный код и не пытаться обходить.
4. Выключить Wi-Fi и мобильные данные. Принудительно остановить **только тестовое** приложение через системные настройки Android, снова открыть его и зафиксировать второй экран. В отчёте отдельно указать, что force-stop выполнен вручную. WebView сам по себе **не может доказать**, что система выполнила force-stop. `networkReportedByWebView` — лишь подсказка: при расхождении проверить состояние сети вручную.
5. Передать **только два скриншота результата** либо текст диагностического JSON. Не пересылать никакие пользовательские Blob/видео, реальный архив, личные данные пасеки или секреты.

**Ожидаемый статус после этих действий:** `P1_ISOLATED_PHONE_SMOKE_DEVICE_VERIFIED` только если фактические экранные PASS и офлайн-возобновление независимо подтверждены человеком. Этот статус не разрешает сохранить OP, выполнить реальный restore или удалить видео. При `BLOCKED` — отладка в отдельной Draft-ветке, не трогая рабочую установку.
