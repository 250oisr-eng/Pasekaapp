# Подготовка разрешённых bbox-данных для обучения детектора YOLOX

Дата: 2026-11-20. Инструмент: `tools/prepare-bee-coco.mjs` (Node.js, без дополнительных зависимостей).

## Практический результат

Теперь можно конвертировать **предварительно проверенные и вручную размещённые** размеченные изображения пчёл из нормализованных YOLO bbox координат `[cx,cy,w,h]` в три COCO JSON файла: `train.json`, `validation.json`, `test.json`. Это формат аннотаций, а **не обученная модель** и не рабочий Android inference.

Условия:
- Нет загрузки исходных файлов, облачных API, платных вычислений, использования пользовательских видеозаписей, перезаписи существующих выходных JSON и удаления файлов.
- Разметка в manifest содержит единый класс `bee`, нормализованные координаты bbox, реальные размеры изображения и проверенный SHA-256 каждого файла.
- До конвертации требуется вручную установленный `datasetLicenseReviewed:true`. Это декларация ответственного исследователя, **не автоматическая юридическая проверка**; нельзя выставлять true без фактического анализа лицензии выбранной версии и авторства файлов.
- Все изображения должны лежать внутри `dataset_root/images/`; символьные ссылки наружу отклоняются `realpath`-проверкой. Перед любым созданием выходных COCO JSON файлы читаются и сверяется SHA-256.
- Для каждого изображения обязателен `sourceVideoId` и `sourceVideoSha256`: одинаковые исходные ролики не могут попадать в разные train/validation/test. Эти метаданные всё ещё *декларативные*; необходимо получить SHA-256 ролика из фактического источника.
- Изображения от одного улья, соседние съёмки или преобразования могут отличаться хешами — нужна ручная/group holdout проверка иного уровня, за пределами этого инструмента.

## Пример входного manifest

```json
{
  "schemaVersion": 1,
  "datasetId": "licensed-honeybee-dataset",
  "datasetVersion": "confirmed-version",
  "datasetLicenseReviewed": true,
  "images": [
    {
      "id": "frame001",
      "path": "images/frame001.jpg",
      "split": "train",
      "sourceVideoId": "verified-video-1",
      "sourceVideoSha256": "<64-char sha256 of original video>",
      "imageSha256": "<64-char sha256 of this jpg>",
      "width": 640,
      "height": 480,
      "boxes": [[0.5, 0.5, 0.2, 0.15]]
    }
  ]
}
```

Требуются также отдельные изображения `validation` и `test` с уникальными SHA кадров и исходных роликов. Пример — только схема, placeholder SHA нельзя использовать для реальной операции.

Команда (только при наличии реально проверенных данных):

```bash
node tools/prepare-bee-coco.mjs ./manifest.json ./licensed_dataset ./generated_annotations
```

### Важное ограничение для YOLOX

Выходные COCO JSON содержат `file_name: images/*.jpg`, а сами изображения остаются в исходной папке `dataset_root`; **копирование изображений и готовое дерево данных для YOLOX этим инструментом не выполняются**. Перед обучением необходимо настроить YOLOX custom Exp и доступ к папке изображений, не считая этот шаг уже выполненным. CLI запускается только вручную.

## Лицензионные источники

- YOLOX официальный код Apache-2.0 и ONNX: https://github.com/Megvii-BaseDetection/YOLOX ; документация custom training https://yolox.readthedocs.io/en/latest/train_custom_data.html .
- Mendeley Data: https://data.mendeley.com/datasets/8gb9r2yhfc/5 — отдельная запись датасета сообщает **CC BY 4.0** для версии 5, 7200 кадров/8 ульев и YOLO labels, включая направление; статья https://pmc.ncbi.nlm.nih.gov/articles/PMC10831503/ сообщает **CC BY-NC-ND** для *статьи*. Устанавливать лицензию именно файлов скачиваемого датасета по соглашениям площадки и notices в архиве **до использования**; не переносить автоматически лицензию статьи на набор или наоборот.
- Неясность прав официального YOLOX pretrained weights https://github.com/Megvii-BaseDetection/YOLOX/issues/1915 — исключить использование весов до разрешения, рассматривать обучение **с нуля** на лицензированных материалах.
- Никакой из этих источников пока не подтверждает реальную точность модели на летке нашей пасеки или достаточность тренировочного объёма.
