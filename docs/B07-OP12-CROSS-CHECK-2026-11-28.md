## F3–F4: проблема и решение

Отдельные проверки физического `sectionalLayouts` и `familyEvents` могут быть корректны каждая сама по себе, но описывать **разные** семьи, позиции и диафрагмы. Новая локальная библиотека `js/sectional-op12-cross-check.js` берёт актуальный `sourceRevisionId`, точный профиль, единственный `ALTERNATIVE_WINTERING_COLUMN`, вызывает штатный `PasekaSectionalPhysicalLayout.validate`, затем по `techProcessId` выбирает однозначное историческое событие `OP-12 / alternative_wintering_configured` и сравнивает его с физической моделью по каждой позиции lower/middle/upper, по ID всех трёх семей, по числу корпусов 2/1/1 и по ID обеих диафрагм. История нескольких лет без выбранного `techProcessId` **FAIL CLOSED**. Отсутствие истории, неверная ревизия, несоответствие семей, поддельный статус семьи, потерянная диафрагма или чужой профиль не дают успешной проверки.

**Инварианты:** результат `readOnly:true`, `readyForPersistence:false`, `completionRecorded:false`. Не изменяются физические корпуса, матки, истории, IndexedDB или архив. `strongestSelectionConfirmed:false`: само событие не доказывает осмотр и сравнение силы семей. Модуль не включён в живой HTML/SW.
