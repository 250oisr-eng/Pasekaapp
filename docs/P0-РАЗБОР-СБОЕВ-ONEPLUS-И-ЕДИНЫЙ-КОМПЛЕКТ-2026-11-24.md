## Корневые причины; что исправлено

| Симптом на компьютере пользователя | Точная причина | Исправление и проверка |
|---|---|---|
| `DIAGNOSTIC_MANIFEST_MISMATCH` при первом запуске | `GITHUB_SHA` на `pull_request` относится к синтетическому CI merge-коммиту, а не к исходному `head.sha` | В манифест добавлен отдельный `sourceSha`; оба SHA проверяются по назначению |
| ADB выдавал help вместо `devices` | Некорректная передача массива аргументов PowerShell → ADB | `Invoke-Adb -Arguments @(…)` с явными строковыми аргументами; реальный Windows PowerShell 5.1 проверен |
| Сообщение `xxxx KB/s …` принималось за сбой установки | ADB пишет нормальный прогресс в stderr; Windows PowerShell 5.1 иногда превращает stderr в `ErrorRecord` | Отличать stdout/stderr от фактического `LASTEXITCODE`; дополнительно требовать `Success` и `pm path` |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | `ru.paseka.journal.disasterproof` уже установлен с другой подписью; Android правильно отказывается обновлять | **Не удалять старый тестовый пакет.** Новый `ru.paseka.journal.disasterproof2`, отдельная песочница; нет `adb uninstall`, `pm clear`, `install -r` |
| Повторный mismatch после исправления package ID | Пользователь получил старый артефакт: манифест `sourceSha=b1a33b82…` вместо требуемого `3677797d…`; все архивы имели почти одинаковое название | **Единый ZIP с вложенным оригинальным APK**, без самостоятельного поиска/загрузки artifact |
| Возможная путаница первого запуска и повторного старта | Старые строки `logcat` могли восприниматься как результат нового шага | Проверка `packageId`, времени Android в формате epoch и **отдельного ожидаемого кода** первого и второго запуска |
| Первая Windows CI обвязка завершилась красным, хотя тесты прошли | Последняя негативная ветка ожидаемо возвратила процессу код 1, оставшийся в `LASTEXITCODE` runner | Добавлен финальный `exit 0` **только после проверки всех негативных сценариев**; следующая Windows CI SUCCESS |

Проблемы с подготовкой теста не означают дефект исходного восстановленного архива, порчу пользовательского видео или отказ Android WebView.
