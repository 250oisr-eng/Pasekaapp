# B01 — единая проверка внешнего архива и файлов, без установки APK

**Важно:** этот инструмент **не создаёт** резервную копию и не подключается к OnePlus. Он анализирует только уже существующие локальные файлы. Один отчёт охватывает три независимые проверки, но не может доказать полноту всей пасеки/Android MediaStore и не заменяет физическое восстановление.

## Факт OnePlus и STOP: здесь нет кнопки полного экспорта (26.11.2026)

**Эта инструкция относится к внешним, уже существующим файлам на ПК, а НЕ к интерфейсу установленного OnePlus APK.** На OnePlus 10 Pro/NE2213 (Android 16/API 36) ранее ADB подтвердил наличие `ru.paseka.journal` версии 1.0; отдельно применялся `ru.paseka.journal.disasterproof2`. Пользователь **25.11.2026 прямо сообщил**, что в установленной «Пасеке» кнопки полного архива IndexedDB нет; автоматический `FULL_EXPORT_NOT_FOUND` согласуется с этим фактом. В `main` на веб-странице исходного `index.html` есть кнопка «Скачать полный архив текущей базы», но **нет подтверждения, что этот код установлен/опубликован на OnePlus**. Нельзя направлять пользователя в раздел «Резервное копирование → P0» телефона: этот путь **не существует в подтверждённом интерфейсе устройства**.

**Состояние источников, а не догадка об экранных кнопках:** Android package signer SHA-256 старой установленной QA-сборки ранее прочитан; разные signers блокируют upgrade. Протокол `ru.paseka.journal.disasterproof2` ранее показал `DEVICE_RESTART_PROOF_FAILED`, `PROOF_TIMEOUT`, `DIAGNOSTIC_SIGNER_MISMATCH`; ни один результат не доказывает восстановление, а также не требует повторной установки. Указанные результаты не устанавливают, как выглядит каждый экран; скриншот актуального телефона не предоставлен. Не выдумывать точные подписи/кнопки диагностического APK.

**Фактический безопасный путь резервирования:**
1. Если на ПК уже есть завершённый экспорт, сохранить его неизменным. Исторический `paseka-v1` архив с тестовыми записями и успешной локальной проверкой — **частичный**; не объявлять его полным.
2. Для **полного** резервирования приватного IndexedDB нужен отдельный проверенный способ считать реально установленный WebView profile через разрешённый ранее `run-as ru.paseka.journal` и выполнить локальную *согласованную* копию файлов хранилища с контролем изменяемости. Обычный USB MTP/DCIM **не открывает** `/data/data/.../app_webview/IndexedDB`; набор `RUN-LOCAL-AUDIT.cmd` **не копирует** эти файлы. Не рекомендовать сырое копирование активной LevelDB в качестве доказанной восстанавливаемой БД; сначала обеспечить корректный snapshot без удаления/force-stop, либо использовать проверенный full export совместимой установленной версии.
3. Копии из Camera/Gallery/Downloads/MediaStore учитываются отдельно и только после определения фактического расположения. Не считать отсутствие видео по заявлению об отсутствии эксплуатационных записей доказательством нуля файлов на телефоне.
4. Внешний read-only ZIP проверяет **только имеющиеся** архив и две папки; с отсутствующим полным архивом выход `BLOCKED_MISSING_LOCAL_EVIDENCE` является правильным и безопасным, **не успешным backup**.
5. Реальное восстановление может проводиться исключительно на **отдельной пустой цели** со совместимым profile, фиксированными SHA и сохранением текущего диагностического APK. Ни uninstall, ни install поверх несовпадающей подписи, ни clear data/erase не разрешены.

**Следующее зависимое действие:** не просить пользователя искать кнопку на OnePlus. Необходима фактическая локальная инвентаризация `run-as`/профилей и, при достижимости непротиворечивого снимка, разработка **отдельного fail-closed экспортера** для установленного пакета — с доказательством независимого восстановления прежде чем называть задачу B01-PHYSICAL завершённой.

## Windows без установки Node.js

Для локальной проверки на компьютере предусмотрен ZIP-артефакт CI `PASEKA-B01-UNIFIED-LOCAL-READONLY-KIT` из **того же проверенного SHA** Draft #542. В нём только изолированный `node.exe`, необходимые JS и `fake-indexeddb`, CMD/PowerShell с GUI-выбором файлов, **без APK/ADB/установщика**. Распаковать ZIP на ПК, запустить `RUN-LOCAL-AUDIT.cmd`, выбрать существующий JSON-архив (если он есть) и при наличии обе папки видео. Ничего не выбирали — отчёт честно покажет `NOT_PROVIDED`.

**Единственная запись Windows-оболочки — новый обезличенный файл `PASEKA-UNIFIED-AUDIT-*.json` в папке распакованного инструмента.** Ни архив, ни медиа-оригиналы, ни устройство не изменяются. Если выбран только один из двух каталогов, отчёт будет `BLOCKED`. Личные файлы никуда не отправляются; ZIP распаковывать на доверенном ПК. Не запускайте старые диагностики OnePlus.

Если в workflow нет зелёной проверки **на текущем SHA**, этот ZIP не использовать. Обязательно отличать успешную упаковку от независимого физического восстановления.

## Один запуск

На компьютере с Node.js и зависимостями проекта:

```powershell
node scripts/run-unified-recovery-audit.mjs --archive "D:\\ExternalPaseka\\paseka-idb-full.json" --media-source "D:\\ExportedVideos" --media-copy "E:\\SeparateBackupVideos" --expected-files 10
```

Все пути и число **10** условные, не взяты из устройства. Укажите собственные проверенные локальные пути. `--expected-files` можно опустить, но тогда полноту исходного инвентаря нельзя считать подтверждённой. Отдельные параметры `--archive` и пара `--media-source`+`--media-copy` optional: если отсутствуют, отчёт честно покажет `NOT_PROVIDED`. Ни одна отсутствующая проверка не получает PASS.

Вывод — **один JSON** с полями `archive`, `isolatedMemoryReopen`, `externalMediaCopies`, `deviceOriginalsInventory`, `independentPhysicalRestore`, `androidInstalledSigning`, `durableSigningKey`, `licensedBeeVideoModel`. Путь, имена, содержимое медиа, фамилии и hash файлов в JSON не попадают.

## Статусы и коды

- `LOCAL_CHECKS_VERIFIED_PHYSICAL_GATES_OPEN` + exit 2: структура внешнего IndexedDB архива, повторное открытие его **временной памяти** и перечисленные копии файлов совпали. Это **НЕ** физический PASS.
- `BLOCKED_MISSING_LOCAL_EVIDENCE` + exit 2: ещё нет одного или нескольких входов.
- `BLOCKED_LOCAL_CHECK` или `BLOCKED_INVALID_INVOCATION` + exit 1: ошибка, повреждение, расхождение или неверные аргументы. Не предпринимать автоматических исправлений.
- **Exit 0 намеренно не предусмотрен.** Полный B01 требует отдельно подтверждённого архивирования всех оригиналов, настоящего независимого восстановления на пустой цели, долговечности накопителя, точных byte SHA и проверенного состояния OnePlus.

## Правила безопасности

Не запускать старые установочные CMD с OnePlus и не очищать существующее диагностическое приложение `ru.paseka.journal.disasterproof2`: физический `DIAGNOSTIC_SIGNER_MISMATCH` уже подтверждён. Не использовать этот скрипт как разрешение на удаление оригинальных видео. #442 остаётся FROZEN; лицензионная модель распознавания пчёл не подтверждена. Скрипт не пишет на диск, но Node.js читает предоставленные ему локальные файлы, поэтому запускать только на доверенном ПК без передачи в CI/чат.
