# Карточка функции — дата последнего осмотра из сохранённого журнала (26.11.2026)

**F0:** ветка Draft #544 уже поддерживает ручной расчёт напоминаний; на main нет заполнения даты из журнала. Поиск исходной даты из `S.records` до изменения отсутствовал. Затрагиваются только `js/season-planning.js`, экран «Планирование» в `index.html` и существующий набор `tests/season-planning.test.mjs`.

**F1:** пользователь выбирает улей в разделе планирования, нажимает «Подставить последний сохранённый осмотр», получает дату последней записи типа «Осмотр» по этому улью. После этого отдельно нажимает существующую кнопку «Рассчитать дату следующего контроля». Ничего не сохраняется автоматически, расчёт не подтверждает факт осмотра.

**F2:** все данные уже в памяти `S.records`, никакие новые API/разрешения/сеть/Android/платные сервисы не требуются. Физическая технология OP и нормы осмотра не изменяются; интервал пользовательский, не технологическая обязанность.

**F3:** игнорируются записи другого улья, архивные события, записи иных типов, ошибочные и будущие даты. Поле последнего осмотра по умолчанию пустое, а не «сегодня». Смена улья очищает прежнюю дату и расчёт. Ввод даты или интервала сбрасывает устаревший результат. Данные не мутируются, ID не подменяются. При отсутствии записей — разъяснение без автозаполнения.

**F4–F5:** дополнительный helper `latestSavedInspection`, один селектор и кнопка, четыре негативных теста. Проверить целевые, Fast, Governance, Android на точном SHA. Тесты не равны физическому UX.

**F6–F7:** дополнение к существующему Draft #544, без нового PR, не затрагивает B01, restore, оригиналы видео, SQLite/IndexedDB или активный профиль улья. Отмена — revert данных коммитов. Слияние разрешено после проверок.
