## Что реально делает функция

- `js/p0-source-inventory.js`, публичный только для интерфейса `PasekaP0SourceInventory.readOnlyInventory(db)`: **одна IndexedDB `readonly` транзакция** по текущему `paseka-v1`, store names, `count()`, схемы ключей.
- `main.state`: агрегированные количества записей журнала, вложений, видео/изображений в формате Data URL, непрозрачных или повреждённых медиа. **Примечание:** чтобы посчитать Data URL, браузер получает существующее `main.state` со строками из IDB в памяти, но **не записывает их в отчёт и не расшифровывает содержимое**. Большие старые состояния могут потребовать значительную оперативную память.
- `full_backup`: read-only количество копий и статистика вложений. Это **не внешняя проверенная резервная копия**. Значения предыдущих состояний также считываются/клонируются в память, поэтому на больших архивах возможен отказ из-за ресурсов; отказ не должен считаться успешной проверкой.
- `entrance_media`: наличие `Blob`, `blob.size`, несовпадения заявленных размеров, число оригиналов. Нет `Blob.arrayBuffer()`, вычисления SHA байтов, удаления или изменения Blob.
- Все неожиданные stores (включая экспериментальные `archive_staging`/`archive_history`, если они фактически существуют) перечисляются только по схеме и количеству и помечаются `UNINSPECTED_STORE`. **Не** заменяет ранее реализованный frozen read-only 5-store `PasekaVideoArchiveV2CopyInventory` из #441.
- Экран резервного копирования: отдельная кнопка скачивания агрегированного `paseka-g0-readonly-v1` JSON и read-only числа вложений, ещё не сохранённых в IndexedDB, по текущей вкладке; никакого фонового сканирования или облачной отправки.
- `sw.js`: offline shell `paseka-shell-v314` → `v315`, precache нового модуля, сохранены origin/метод/route границы, очищаются только старые собственные `paseka-shell-` кеши.

Отчёт всегда `status=PARTIAL_READONLY`, `scope=CURRENT_INDEXEDDB_ONLY`, `osMediaStore=NOT_ACCESSED`, `externalFiles=NOT_ACCESSED`, `otherOrigins=UNKNOWN`, `originalByteHashesVerified=false`, `backupVerified=false`, `restoreVerified=false`, `cleanupAuthorized=false`. Не передаёт имена/ID ульев, имена видео, фото, журнал, URL вложений, Blob/файлы и текст предыдущих резервных копий.

## Конкретные границы достоверности

| Источник | Что можно узнать после авторизованного запуска в живом origin | Не доказано |
|---|---|---|
| `paseka-v1/main` | Хранится ли `state`, количество записей и вложений, типы Data URL | Достоверность/воспроизводимость исходных видео, точный SHA |
| `paseka-v1/entrance_media` | Сколько записей, есть ли `Blob`, заявленные/фактические размеры | Идентичность байтов оригинала, место ОС-копий, право удаления |
| `paseka-v1/full_backup` | Сколько резервных записей и вложений | Независимость хранения, восстановление и квоты |
| Другие stores | Схема и числа, explicit `UNINSPECTED` | Содержимое v2 ledger/staging/rollback |
| Android Camera / MediaStore / Downloads / Gallery | **Ничего** — доступ к OS-источникам не предоставлен | Количество копий, хэши, provenance, наличие внешнего носителя |
| Второй аппарат | **Ничего** | G1–G6 независимое восстановление |
