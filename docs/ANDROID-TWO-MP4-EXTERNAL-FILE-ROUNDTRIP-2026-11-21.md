## Аудит штатного Android Downloads bridge: ограничение перед физическим тестом

Прочитан исходник `scripts/prepare-android-archive-download.mjs`. Метод `PasekaArchiveDownloadBridge.beginFile(displayName, mimeType)` проверяет формат `paseka-full-backup-YYYY-MM-DD.paseka` и MIME, затем вызывает `MediaStore.Downloads.EXTERNAL_CONTENT_URI` `insert` с `RELATIVE_PATH = Downloads/Пасека`. Он **не выполняет предварительную безопасную проверку уникальности** имени и не фиксирует отдельный путь/URI для уже существующих архивов, чтобы доказать отсутствие collision. Нельзя считать, что Android автоматически сохранит именно запрошенное имя при совпадении с существующим или что старые файлы не затронуты: это требует отдельной проверки API на устройстве.

`finishFile` и `cancelFile` могут удалять **только URI своей текущей сессии**, однако по исходнику нельзя доказать, какой URI/filename MediaStore вернёт при collision; ненадёжный результат должен остановить тест. Для следующего физического интеграционного испытания использовать только **новый отдельный test package**, новую строго ограниченную тестовую область, безопасный способ выявления collision и закреплённый на SHA одноразовый сценарий; штатную production папку и ранее созданные пользовательские архивы не использовать. Запрещены попытки `pm clear`, перезаписать `proof325` или удалить предыдущие архивы ради теста.

# PASEKA01: два синтетических MP4, запись в отдельный файл и повторное чтение

Дата: 2026-11-21. Stacked Draft PR #328 поверх #327. Этот документ отделяет проверенное в CI от ещё не проверенного на Android.

## Подтверждённый физический исходный этап

Пользователь на OnePlus NE2213/API36 получил `ISOLATED_ANDROID_TWO_MP4_EXPORT_PASS` в изолированном пакете `ru.paseka.journal.archive.proof325`: проверки двух pinned MP4 в отдельной IndexedDB, in-memory PASEKA01 и SHA после остановки и повторного запуска. Это **не** сохранённый Android Downloads-файл, не реальный импорт и не распознавание.

## Изолированная проверка внешнего файла (Node CI)

Новый файл `tests/android-two-mp4-external-file-roundtrip.test.mjs`:

1. Создаёт **новую** базу `fake-indexeddb` с двумя FFmpeg-синтетическими MP4 по 893 байта, SHA-256 `794e1dcb2598dff510b8f4b7cafea57a500cbfd57a1e57a99247a9bb7d784b9f` и `bc9abbf1f109a7f2feb8787d52bce8363eb3c577ef2acd67ae4fcdf59a892eff`. Никаких пользовательских файлов.
2. Вызывает живой `PasekaArchive.exportArchiveFromDatabase` и формирует настоящий бинарный `PASEKA01`.
3. Открывает **исключительно новый** файл в уникальном временном каталоге runner через `open(...,'wx')`, записывает, вызывает `fsync`, закрывает и повторно читает файл с диска.
4. Сверяет независимый SHA-256 файла до/после, байты экспорта, `parseArchiveBlob`, `verifyArchive` и `validateArchiveForRestore` (только предварительная проверка, **без** изменения активной базы).
5. Проверяет запрет перезаписи существующего файла (`EEXIST`), обнаружение порчи одного байта видео (`CHECKSUM_MISMATCH`), усечения и неизменность соседней IndexedDB.
6. Временная тестовая область runner удаляется по завершении тестов; никакие телефонные файлы и production-базы не трогаются.

**CI:** [Fast quality checks #44936845758](https://github.com/250oisr-eng/Pasekaapp/actions/runs/44936845758), код SHA `f8951094c36ef788f883f64919d5894cc42ba45e`, **1227/1227 PASS**, 0 fail. Общая Android-сборка на том же SHA должна проверяться отдельно после завершения, её успех не подразумевается по Node-тестам.

## Важные ограничения

- Тест **не** обращается к `MediaStore.Downloads`, штатному Android JavaScript bridge или реальному Android файловому каталогу.
- `validateArchiveForRestore` подтверждает проверку данных архива до восстановления, но **не** выполнение restore commit и не сохранность остальных хранилищ после восстановления.
- Вступивший в силу физический PASS in-memory proof325 остаётся неизменным; установленный `proof325` не перезаписывался и не очищался.
- Декодирование MP4, реальные видео пчёл, разрешение на использование внешних обучающих датасетов, распознавание и автоматическое удаление видео остаются **NOT TESTED / DISABLED**.
