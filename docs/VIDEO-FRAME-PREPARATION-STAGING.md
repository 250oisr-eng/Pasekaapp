# Подготовка кадров леткового видео — staging-only (2026-11-20)

Состояние: изолированный, неактивный модуль. Это **не распознавание пчёл**, не обработчик ИИ, не очередной фоновый процесс, не право на удаление.

## Основание и безопасность
- Текущий `js/entrance-analysis.js` извлекает технические показатели яркости, резкости и разницы кадров; **не выдаёт JPEG кадров для AI inference**, не распознаёт пчёл и не выдаёт авторизующий результат.
- `canDeleteVideoOriginal` сохраняется для совместимости API, но теперь **безусловно возвращает false**. Прежние флаги `completed/resultPersisted/serverDeleteConfirmed` недостаточны: копии и Android provenance не подтверждены. Реальная функция `deleteEntranceVideoBlob` уже блокирована в #241.
- `js/entrance-frame-preparation.js` реализует **только локальное и временное** декодирование из Blob с проверкой текущего `blobSha256`, `bytes`, `id`. Не отправляет кадры/видео по сети, не меняет IndexedDB/реальную базу, не создаёт файлов.
- Для ограничения нагрузки допускает 2–4 JPEG кадров не более 640 пикселей по максимальной стороне; каждый кадр ограничен 350000 символами data URL. Это **технические защитные ограничения**, а не нормы съёмки или технологии пасеки. При недоступном decoder, несовпадении SHA/размера, abort, невалидном JPEG либо недекодируемом файле возвращает явную ошибку и пустой результат.
- Объектный URL освобождается в finally, видео останавливается, canvas очищается; готовые data URLs остаются в возвращённом объекте только в памяти вызывающего кода. JS не гарантирует немедленную очистку памяти или отсутствие неуправляемых копий у браузера; будущий вызывающий код обязан удалить ссылки после использования.
- Результат всегда содержит `recognitionSucceeded:false`, `cleanupAuthorized:false`. Он не может напрямую вызывать ledger `recordRecognitionResult`, требующий подтверждённого `recognitionStatus='completed'` от **реального** обработчика.
- Модуль **не подключён** в `index.html`, не добавлен в PWA Service Worker, не используется в пользовательском UI и не заявляет поддержку Android устройства. Он просто упакуется в Android `www/js` при полном build, но не загружается приложением.
- Исходный файл и все reserve/rollback копии сохраняются. Экспортированное внешним Android Camera/Gallery видео не может быть удалено из IndexedDB. Не объявлять соответствие правилу удаления после распознавания до end-to-end испытаний.

## Тесты и следующий этап
`tests/entrance-frame-preparation.test.mjs` проверяет границы, SHA, MIME/размер, fake decoder, JPEG, abort, отсутствие fetch/storage/подключения к UI, очистку object URL. Существующий `tests/entrance-analysis.test.mjs` теперь требует постоянного отказа в eligibility для удаления.

Следующий шаг: CI на точном SHA; затем отдельная архитектура и проверяемый реальный распознаватель (video frame → detection/tracks → результат, а не текстовый chat answer), без скрытых платных внешних служб. После этого — source-bound durable ledger и отдельный all-copy Android cleanup.
