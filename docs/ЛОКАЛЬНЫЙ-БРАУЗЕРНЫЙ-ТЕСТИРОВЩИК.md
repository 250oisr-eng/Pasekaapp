# Локальный браузерный тестировщик Windows 11

## Назначение

Скрипт **scripts/local-browser-smoke.mjs** автоматически запускает установленный Google Chrome и проверяет базовую работоспособность локальной версии приложения «Пасека». Он предназначен для повторяемых проверок после изменений интерфейса и основных разделов.

## Требования

- Windows 11.
- Google Chrome установлен на компьютере.
- Node.js 20.10 или новее; рекомендуется Node.js 22 LTS. Требуется встроенный WebSocket Node.js.
- Не требуются Playwright, Selenium, платные сервисы, дополнительные npm-пакеты или ручной запуск Python HTTP-сервера.

## Запуск

Откройте PowerShell в корневой папке проекта (там, где находится package.json) и выполните:

    node --version
    npm run test:browser:local

Если Chrome установлен в нестандартной папке, перед запуском задайте путь:

    $env:PASEKA_CHROME_PATH = 'C:\Путь\к\chrome.exe'
    npm run test:browser:local

Скрипт сам запускает локальный HTTP-сервер на случайном порту, открывает отдельный экземпляр Chrome, выполняет проверки, сохраняет отчёт и закрывает браузер. Python HTTP-сервер запускать не нужно.

## Что проверяется

1. Приложение загружается, заголовок и основная навигация присутствуют.
2. Для каждого из 11 основных разделов существует соответствующая панель.
3. Переключение на каждый раздел действительно активирует правильную панель: «Обзор», «Ульи», «Лёток», «Журнал», «ИИ», «Медоносы», «Клещ», «Инцидент», «План», «Потери», «Ещё».
4. После перехода на главную страницу приложение повторно загружается без потери доступности основной навигации.
5. Фиксируются необработанные JavaScript-исключения, вызовы console.error и HTTP-ошибки локальных ресурсов.
6. Для основных экранов сохраняются снимки: обзор, ульи, лёток, журнал и настройки.

## Изоляция и безопасность

- Chrome запускается с новым временным профилем в системной временной папке. Обычный профиль Chrome, история, cookies, расширения и пользовательские данные не открываются и не очищаются.
- IndexedDB и localStorage тестового экземпляра изолированы от обычного Chrome. Скрипт не создаёт и не изменяет реальные записи пасеки; он только открывает разделы и перезагружает страницу.
- HTTP-сервер слушает только 127.0.0.1, не доступен из локальной сети или интернета. Для браузерной вкладки используется тестовое имя paseka.test, которое Chrome принудительно разрешает в 127.0.0.1; DNS-запрос наружу для него не требуется.
- Перед открытием приложения браузерная сессия настраивается так, чтобы разрешать запросы только к точному адресу локального тестового сервера. Остальные запросы страницы блокируются до отправки. Это не позволяет тесту обращаться к Neon, Cloudflare Worker или другим внешним сервисам. Попытки обращения фиксируются по имени хоста.
- Регистрация Service Worker нейтрализуется в тестовой вкладке, а сетевой обход Service Worker включён. Это исключает обновление/чтение кеша и фоновые запросы воркера.
- Временный профиль удаляется после завершения, в том числе после ошибки. Отчёты и снимки остаются в проекте.

## Результаты

Каждый запуск создаёт отдельную папку:

    .local-test-results/<дата-время>/
      report.json
      home.png
      hives.png
      entrance.png
      journal.png
      settings.png

report.json содержит статус, перечень проверок, ошибки браузера и локального HTTP, список заблокированных внешних хостов и снимки экранов. Каталог .local-test-results/ исключён из Git.

Код завершения:
- 0 — все автоматические проверки прошли;
- 1 — найдена ошибка или не удалось запустить тест.

При неуспехе передайте ChatGPT файл report.json и, если требуется визуальный разбор, соответствующие PNG из той же папки.

Для контроля изменений в репозитории добавлен workflow .github/workflows/windows-browser-smoke.yml. Он запускает те же проверки на Windows runner GitHub Actions и сохраняет отчёт/снимки в артефакте windows-browser-smoke-report (срок хранения — 7 дней).

## Ограничения

Это первый безопасный smoke-тест браузерного интерфейса, а не полная проверка приложения. Он не проверяет создание/удаление ульев, изменение реальных записей, миграции IndexedDB, backup/restore, работу микрофона/камеры, Android WebView, производительность на телефоне или качество офлайн-распознавания. Такие проверки должны выполняться отдельными сценариями на изолированных фикстурах и целевом OnePlus 10 Pro 5G.

## Платформа испытаний

Windows 11 — основная настольная среда локального браузерного тестирования. OnePlus 10 Pro 5G остаётся целевым физическим Android-устройством. Автоматическая проверка Chrome на Windows не заменяет испытания Android.


## Read-only Android preflight через ADB

Для проверки доступности целевого телефона и фиксации его фактической конфигурации добавлен `scripts/android-device-preflight.ps1`.

Запуск из PowerShell в корне проекта:

    npm run test:android:preflight

Эта команда запускает только self-tests парсера и не требует телефона. Для реальной диагностики после установки Android SDK Platform-Tools и подтверждения USB-отладки на телефоне:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/android-device-preflight.ps1

Скрипт принимает ровно одно авторизованное ADB-устройство и проверяет NE2213. Он считывает версию Android/build, SKU/модель, security patch, батарею, разрешение/density экрана, версии Chrome и Android System WebView, а также версию установленного приложения. Отчёт сохраняется в `.local-test-results/android-preflight/<timestamp>/report.json`.

**Границы:** скрипт ничего не устанавливает и не удаляет, не запускает приложение, не открывает IndexedDB, не читает личные файлы, не снимает экран, не собирает logcat, не меняет настройки или сеть и не включает ADB по TCP/IP. Серийный номер устройства в отчёт не записывается. Это только проверка соединения и конфигурации, не функциональный тест Android.

## Проверка сохранения на физическом Android-устройстве

В изолированной тестовой APK с package ID `ru.paseka.journal.test` карточка «Проверка сохранения — тестовая APK» доступна в разделе «Ещё». CI внедряет её только в сгенерированные Android web assets после `npm run web:prepare`; исходный `index.html` и production/PWA интерфейс диагностического кода не содержат.

1. Открой в тестовой APK раздел «Ещё» и карточку проверки сохранения.
2. Нажми «Записать тестовую отметку». Выполняется штатный `save()`, затем контрольное чтение из основной записи IndexedDB.
3. Полностью закрой приложение через список последних приложений Android и запусти его снова.
4. Сообщение о найденной после запуска тестовой отметке подтверждает сохранение основного состояния.
5. Нажми «Удалить тестовую отметку». Сценарий проверит удаление из основной базы и обновление автокопии.

Тест не создаёт улей, семью, матку, рамки или запись журнала и не меняет версии IndexedDB/schemaVersion. Маркер — служебное поле состояния, а не факт о пасеке. Использовать только изолированную APK.
