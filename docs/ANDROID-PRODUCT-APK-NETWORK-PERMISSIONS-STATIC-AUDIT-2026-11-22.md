## Реализованный автоматический контроль

- Новый скрипт `scripts/audit-android-product-apk.mjs` берёт **только путь APK**, локальную утилиту `aapt` и исходники для read-only-инвентаризации. Сверяет точный product packageId и SHA256, парсит фактический список разрешений, создаёт JSON без токенов, содержимого файлов пасеки или сетевых обращений.
- `tests/android-product-apk-static-audit.test.mjs` проверяет ошибочные/чужие packageId, повреждённый вывод `aapt`, дубли разрешений, классификацию сетевых/медиа прав, отсутствие ложных физических утверждений.
- `.github/workflows/android-debug.yml` запускает аудит **после** `assembleDebug`, публикует JSON отдельным артефактом и блокирует CI, если изменится точный пакет или отчёт станет утверждать `productInstalledPermissions`/`productNetworkTrafficObserved` без измерений.

## Следующий безопасный этап

1. Только **read-only** физический аудит установленной версии **реального** `ru.paseka.journal`: пакет, подпись/версия и разрешения через PackageManager; не заменять старый APK новым без явного решения, не удалять пользовательские данные.
2. Для измерения трафика заранее определить точный UID пакета, контролируемое окно наблюдения и разрешённый метод измерения; не утверждать отсутствие трафика по факту отсутствия сетевых разрешений. Убедиться, что в отчёт не попадут содержимое запросов, персональные токены или видео.
3. Реальные `A02_REAL_PASEKA01`, `A03_REAL_PASEKA02` и Android `A08_ANDROID_FORCE_STOP` отдельно **NOT_TESTED**, очистка видео и restore **не разрешены**.

Параметры безопасности неизменны: `cleanupAuthorized:false`, `restoreAuthorized:false`, `archiveSafe:false`. Ни запись в production, ни развёртывание, ни merge не выполнялись.
