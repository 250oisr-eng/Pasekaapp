- **Нельзя обходить согласия**: любой вызов GitHub CI, чтение исходников, обновление документов и создание Draft допустимы; merge, release, production database operation и delete требуют соответствующего решения пользователя и выполненных техворот.

## Минимальные действия пользователя по порядку

**Действие A — только merge безопасного архивного чтения.** После final review пользователь может отдельно написать: «Разрешаю слить только PR #472 в main; не публиковать, не устанавливать приложение и не выполнять восстановление/удаление». Затем разработчик проверяет main SHA, CI и Pages, но не делает release. Это **не** делает полный backup доказанным.

**Действие B — рассмотрение #473 после отдельного CI PASS.** Отдельно разрешить merge только fail-closed проверки схемы; в этом PR нет миграций и удаления. Не давать согласие, если exact-SHA CI FAIL/UNKNOWN.

**Действие C — при следующей доступности ПК с OnePlus.** USB + разрешённый ADB *read-only* аудит установленного `ru.paseka.journal`, без замены APK. Перед очередным физическим тестом напомнить пользователю подготовить нужный файл/оригинал и доступ к ПК; не требовать действий сейчас, если его нет.

**Действие D — независимая резервная копия.** После безопасного разрешённого выпуска read-only экспорта отдельно сохранить полный файл ВНЕ телефона, открыть его повторно, проверить SHA, перечень stores и фактические оригиналы. Реальный restore делать **только** в отдельной пустой среде/устройстве, не на рабочем OnePlus.

**Действие E — signing key.** Пользователь хранит постоянный приватный keystore и пароли в своём защищённом месте с резервной копией. В репозиторий/чат отправлять максимум публичный certificate fingerprint. После этого можно испытать 2 последовательно подписанных отдельным appId QA APK, не трогая старый пакет.

**Действие F — отдельный релиз.** Только после конкретных физически пройденных сценариев, проверок текущего `main`, и нового явного разрешения публикации на названный SHA. Никакое одобрение PR не даёт согласия на publication/deploy.

**Действие G — реальная видеодетекция и автоудаление.** Только после лицензированных weights, легальных реальных видео, эталона, восстановления и всех V0–V6: отдельное решение на ограниченное удаление; при отсутствии данных оставить #442 FROZEN.
