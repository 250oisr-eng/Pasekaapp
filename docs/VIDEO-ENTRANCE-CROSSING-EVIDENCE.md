# Определение направления по пересечению линии летка — неактивный эксперимент (2026-11-20)

`js/video-crossing-evidence.js` принимает **уже известные** положения одного объекта (x/y/timeSec), а также явно заданную линию летка и сторону «внутрь». Положение летка нельзя вывести из ориентации кадра автоматически, без калибровки пользователем. Обязательны две конечные точки линии в координатах 0..1, `insideSide='positive'|'negative'` и определённая `tolerance` (значение может быть 0, если пользователь/калибратор явно выбрал 0). Нет параметров по умолчанию, которые могли бы угадать направление.

Для строго монотонных минимум трёх точек один переход через линию даёт черновое `in` или `out`. При отсутствии пересечения, нескольких пересечениях, точках на линии, плохих данных или калибровке — `unknown` либо явная ошибка. Это **геометрия по предоставленным точкам, не реальный tracker**. Точность, сохранность ID объекта, скорость съёмки и источник координат не проверены. Да и реальные кадры не были обработаны моделью.

Результат даже для одиночного `in`/ `out` всегда помечен `directionVerified:false`, `recognitionSucceeded:false`, `cleanupAuthorized:false` и `reviewRequired:true`. Не использовать для automatic status `completed`, изменения состояния семьи, экологического/биологического диагноза или удаления.

Модуль не загружается в `index.html`/Service Worker, не работает с сетью/хранением и не трогает настоящие данные. `tests/video-crossing-evidence.test.mjs` покрывает inversion insideSide, отсутствие/повтор пересечения, невалидную калибровку и временные ряды. Для реального inference нужны проверенная модель, физически откалиброванный леток, связность tracking IDs и benchmark на видео пользователя.
