# OnePlus — единый минимально ручной сеанс комплексных испытаний

Дата: 2026-11-25. **Статус:** CONTRACT_READY / PHYSICAL_BLOCKED. Этот документ — план будущего безопасного сеанса, **не команда сейчас подключать телефон** и не разрешение менять приложение/данные.

## 1. Цель и текущие запреты

Вместо множества отдельных ADB-проб — **один** заранее подготовленный, ограниченный по времени набор последовательных проверок с итоговым JSON. Уже подтверждённый read-only V5 сертификата установленного APK не повторять без изменения установленного пакета. Использовать существующие Draft #524/#525–#528 и не разрабатывать параллельный USB-скрипт без необходимости.

Блокеры: B01 — **нет доказанной полной внешней копии IndexedDB + MediaStore/Gallery + всех оригиналов и независимого восстановления**; B04/B05 — отсутствует доказанная возможность безопасного подписанного обновления/rollback; #442 — видеоанализ/очистка FROZEN; cold-offline на текущем OnePlus — NOT_TESTED.

Пока B01 не завершён, запрещены `adb install`, `pm clear`, `uninstall`, `run-as` с записью, изменение WebView/IndexedDB, очистка кеша, удаление/перемещение оригиналов, использование production-базы как мишени restore, загрузка личных архивов в GitHub/чат. Нельзя получать «зелёный» физический результат только от одного ADB stdout или наличия папок.

## 2. Формат одной сессии

### Входы, проверяемые автоматически

| Вход | Источник / доказательство | Если отсутствует |
| --- | --- | --- |
| Exact GitHub SHA диагностического пакета | текущий проверенный Draft, Android/Windows/Governance CI на этом SHA | STOP, не запускать неизвестный .cmd |
| OnePlus identity | реальное `adb devices`, установленный package `ru.paseka.journal`, versionCode и fingerprint, без раскрытия серийного номера в публичном отчёте | `NOT_VERIFIED` |
| Полный локальный файл архива | пользовательский локальный экспорт; исходные байты не преобразовывать и не загружать в CI | `B01 BLOCKED`; никакого restore |
| Независимая пустая цель | отдельный тестовый файл/IndexedDB в sandbox ПК, ни один production store не открыт на запись | `RESTORE_NOT_TESTED` |
| Gallery/MediaStore и внешние оригиналы | локальный перечень и SHA по **реальным** источникам, только после законного/технического разрешения на чтение | `FULL_ORIGINAL_COVERAGE_UNKNOWN` |
| Подписанный кандидат и rollback | точный signer match/долгоживущий ключ и восстановление обратно; исходная установка не меняется | `UPGRADE_BLOCKED` |

### Автоматические этапы в одном пакете

**S0 — preflight (read-only).** Проверка фиксированного ID устройства, версии Android, доступности ADB, соответствия package и версии. Использовать хешированный/редактированный device ID, не serial в публичном JSON. При расхождении — STOP, никаких изменений.

**S1 — локальный источник (read-only).** Отдельно различать обычный JSON state и `paseka-idb-full-v1` с `main/full_backup/entrance_media`. Проверить размер, регулярность файла, отсутствие symlink, manifest, stores, версии, SHA, bytes; не переписывать файл. Обычный JSON никогда не объявлять полным видеоархивом. Сверх лимита 64/512 MiB — BLOCKED до потокового безопасного инструмента, а не незаметно обрезать.

**S2 — независимое восстановление (только пустой disposable sandbox).** Для настоящего экспортированного полного архива проверить import, count, byte SHA, close/reopen, повторный readback, старые stores, прежние семейные ID и события. Любая ошибка — FAIL; исходный файл остаётся нетронутым. Эмуляция в fake-indexeddb #524 подтверждает только структуру, а не физический restore телефона.

**S3 — учёт внешних оригиналов (read-only, если доступ законен).** Перечень известных мест app-private/IndexedDB/Gallery/MediaStore/Downloads/PC, хеш, происхождение и доступность **без чтения в чат и GitHub**. Не смешивать равный размер с идентичным SHA. Отсутствие хотя бы одного источника не даёт `FULL_BACKUP_PASS`.

**S4 — Android compatibility (без обновления).** Сверить сертификат установленного APK и подписанного кандидата, versionCode, API и rollback-совместимость. При отсутствии private key или невосстановимых данных — `UPGRADE_BLOCKED`. Повторять V5 signer-скан только при новом установленном APK.

**S5 — офлайн и UI:** только после S1–S4 и отдельного разрешения на конкретный тестовый APK — один cold-start без сети, выбор **синтетического тестового** улья, запись тестового события, принудительный stop/reopen, проверка сохранности/rollback, проверка голосового черновика и read-only видеоочереди. Никаких реальных технологических операций и фактических подкормок без пользователя. На текущей production-среде не создавать тестовых семей/видео ради эксперимента.

**S6 — нагрузка и видео:** только когда пригодны реальные разрешённые видео/модель V0–V6 — CPU/RAM/тепло/энергия, устойчивость при нехватке места и разрыве, независимая проверка результата. Без эталона или лицензии статус `FROZEN`, а не искусственный PASS. Оригиналы **не удалять**.

**S7 — итог:** локальный обезличенный JSON со статусом каждого шага, exact candidate SHA, версией приложения и понятной причиной STOP. Машинные статусы `PASS/FAIL/NOT_TESTED/BLOCKED/FROZEN`; ни один незавершённый шаг не превращается в PASS. Отчёт не включает секреты, пользовательские тексты, видео или полный serial. Автоматическое удаление отчётов и копий не включать.

## 3. Участие пользователя — минимальное

**Сейчас: 0 действий.** Не нужно присылать архивы, делать скриншоты, переустанавливать программу, повторять старые signer-пробы или вводить команды.

Только после готового безопасного Windows-пакета и подтверждённых предшествующих ворот пользователь в **одной согласованной сессии**:
1. Подключает OnePlus к ПК через USB, разблокирует экран и однократно разрешает доступ ADB, если система запросит.
2. Запускает **один** проверенный `.cmd` из локального пакета. Дальше проверки и генерация отчёта выполняются автоматически; если B01 отсутствует, пакет останавливается без записи.
3. Передаёт только обезличенный JSON-результат, **не** оригиналы, архивы, ключи, токены и файлы из хранилища приложения.

Если для полноценного теста требуется переключение авиарежима, тестовая APK-установка, ввод пароля или подтверждение изменений, это *отдельный поздний сценарий*, только после выполнения ворот и явного разрешения. В отсутствие пользователя возле ПК не инициировать повторные пробы.

## 4. Обязательный контроль разрывов и отрицательных случаев

| Сбой | Ожидаемое безопасное поведение |
| --- | --- |
| USB отключен, ADB unauthorized, другой serial/package | STOP, исходное приложение и данные не изменять |
| Не найден full-archive, найден только обычный JSON или 1090-byte TAR | B01 BLOCKED; не выдавать его за полный backup |
| Ошибка checksum, неполный manifest, нехватка места, отсутствует источник Gallery | Отказ без удаления/обрезания источника |
| APK подписан другим сертификатом | NO_INSTALL, NO_UPGRADE |
| Android cold-offline не запускался | NOT_TESTED, независимо от зелёного Node CI |
| Долгий или прерванный видеоролик, нет лицензированной модели | FROZEN; оригинал оставить |
| Неподтверждённая физическая операция или план ИИ | Не создавать подтверждённый факт |
| Обрыв связи с ChatGPT / GitHub CI | Локальный результат сохраняется; прогресс по SHA в репозитории, перезапуск без повторного изменения данных |

## 5. Критерий завершения

Сеанс считается **DEVICE_VERIFIED только по реально пройденным подэтапам**, а не одним общим `PASS`. Полный recovery B01 отдельно требует оригинальный архив плюс независимое восстановление всех источников. Результат может быть частичным, например `S0=PASS, S1=BLOCKED, S2–S6=NOT_TESTED`. Это правильный безопасный итог. Выпуск/merge остаётся вне полномочий QA.
