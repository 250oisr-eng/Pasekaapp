# P1 — read-only JSON: проверка связи семьи с ульем (25.11.2026)

## F0–F2
Проверка относится к локальному JSON состоянию старых версий OnePlus, не к полному архиву и не к restore. Исходный `scripts/audit-oneplus-json-transfer.mjs` проверял существование `record.hive` и `record.family` по отдельности, но не замечал, что оба ID существуют, однако семья относится к другому улью. Такая запись может быть закономерным историческим перемещением либо несогласованными данными — без источника не исправлять автоматически.

F2: LIMITED_SAFE_DRAFT. Независимое чтение, без устройства, записи пользовательских данных, валидации операций или миграции.

## F3–F5
Если одновременно присутствуют `record.hive`, `record.family` и `family.hive`, которые расходятся, добавляется предупреждение с индексом записи без идентификаторов, фамилий и текста журнала. Статус `REVIEW_REQUIRED`, не `BLOCKED`: старые переезды и архивированные семьи требуют ручного анализа, а не удаления записей. Отсутствующая историческая семья по-прежнему вызывает отдельное предупреждение; непротиворечивые записи остаются `JSON_STATE_PREFLIGHT_ONLY`. Мутаций нет.

Тесты проверяют конфликт двух валидных ульев, прежние совместимые записи, неизвестную историческую семью, отсутствие пользовательских ID/текста в отчёте и неизменность входного объекта.

## F6–F7
Только Draft, без merge, восстановления, APK update, публикации или удаления. CI проверять на точном SHA. B01 полноценной копии и независимого восстановления не закрывает.

## Дополнительный случай: семейная запись без собственного улья

При read-only проверке записи с `record.family`, но без `record.hive`, невозможно подтвердить, где событие происходило, даже если текущее `family.hive` известно: семья могла перемещаться. Это теперь **`REVIEW_REQUIRED`**, без назначения улья, миграции или удаления. Обобщённая запись только по улью, без семейной привязки, сохраняет прежний допустимый статус. Три синтетических регрессии проверяют отсутствующий/null/пустой hive, приватность отчёта и неизменность входного JSON. Не считать это дефектом пользователя или доказательством потери записи.

## Ещё один непроверяемый случай исторической связи

Если запись содержит валидные `record.family` и `record.hive`, но сама найденная семья не имеет текущего `family.hive`, аудитор не вправе выводить правильность исторического местоположения из одной записи. Возвращается `REVIEW_REQUIRED` с индексом строки без ID/имён/содержимого. Разделён случай семьи без текущего hive и отсутствующей в каталоге семьи: для последней остаётся прежнее предупреждение. Два новых отрицательных теста, данные неизменны, это не восстановление `entrance_media`. Точный кодовый HEAD и CI — в Draft PR #516.
