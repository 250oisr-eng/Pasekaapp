# Проверка нового интерфейса «Пасека 2.0» на OnePlus

**Только отдельное тестовое приложение** «Пасека UX — проверка», package `ru.paseka.journal.qa.ux20261127`, Android 15 (API 35) или новее. Основной исходный код: 6526fe6d7041ef5c52f6115e1c29f1306ca9ab1b. Сборка из QA-ветки не меняет runtime основного приложения, production APK, существующий QA, реальные записи, резервные копии или видео. Подпись debug одноразовая. Не обновлять существующие пакеты, не удалять приложение и данные. Если Android показывает «Обновить приложение» вместо установки нового, ОСТАНОВИТЬСЯ. Не импортировать реальные архивы, не подключать аккаунты, не запускать внешний ИИ/камеру. Только вымышленные записи. Сборка не доказывает физический тест.

## Установка
1. С GitHub Actions скачать ZIP **PASEKA-ONEPLUS-UX-QA-20261127** после успешного CI. Распаковать. Сверить packageName, runtimeMainSha и apkSha256 в QA-PROVENANCE.json; на Windows `Get-FileHash .\PASEKA-ONEPLUS-UX-QA-ONLY.apk -Algorithm SHA256`. Сверить с опубликованным CI SHA APK. ZIP и APK имеют разные SHA.
2. Передать на телефон только PASEKA-ONEPLUS-UX-QA-ONLY.apk. Установить новый отдельный пакет (Android 15+). Разрешить установку из конкретного источника только при необходимости и затем отключить разрешение. Если установка не удалась, ничего не удалять и не сбрасывать.
3. Открыть «Пасека UX — проверка». На первом запуске тестовая база должна быть пустой. Рабочая «Пасека» и прежняя «Пасека QA — тест» остаются без изменений.

## Один цикл приёмки
01. Главная: пять разделов + ИИ, нет дублирования, обрезки и перекрытий; открыть каждый раздел, вернуться «Назад»; поворот портрет/альбом.
02. Режимы: выбрать полевой, домашний, ночной; проверить читаемость шапки, меню, карточек и полей, видимость нижней навигации. Полевой режим — проверить одной рукой/в перчатках и в ярком свете. Если условий нет, NOT_TESTED.
03. Создать один условный улей поддерживаемого профиля (не активировать новый секционный профиль), две условные семьи с разными именами/кодами; если нельзя завершить штатную комплектацию без догадок, отметить FAIL и остановить соответствующий этап.
04. В карточке улья открыть «Осмотр этой семьи» для первой семьи. Проверить выбранную семью и пустые значения. Ввести учебную заметку, нажать «Отмена». В журнале записи быть не должно.
05. Сохранить два учебных осмотра первой семьи с разными датами и допустимыми значениями занятости, например 1 и 2 рамки, затем один осмотр второй семьи со значением 0 (если штатная форма принимает). Проверить различие неизвестного и нуля, динамику только первой семьи, даты и отсутствие смешения. Это искусственные данные, не фактические показатели.
06. В основной карточке улья открыть «Конструкция и рамки». После завершения штатной комплектации карта показывает только учтённые установленные корпуса, номера рамок, статусы и историю. Открыть рамку, закрыть без изменений. Штатные настройки должны оставаться доступными. Никаких реальных физических операций.
07. Поиск/журнал: найти первую семью и её записи, перейти в историю и обратно. Проверить, что сохранено ровно три учебных осмотра, без дубликатов.
08. Выключить Wi-Fi и мобильную сеть, включить авиарежим; закрыть только тестовое приложение из недавних, открыть снова. Проверить данные, режим оформления, карточки и карту без сети. Вернуть сеть.
09. При возможности включить TalkBack; проверить доступные имена кнопок, карточки, поля, возврат из диалога, затем вернуть исходную настройку. Если не проверено — NOT_TESTED.
10. Проверить по наблюдению, что рабочее приложение и старый QA остались прежними, нет неожиданного запроса на обновление или импорт. Не открывать и не изменять реальные записи ради теста.

СТОП: системная ошибка, пропажа данных, повторная запись, неправильная семья, неподдерживаемая конфигурация, запрос на замену установленного пакета. Сохранить состояние тестового приложения; сообщить номер пункта и обезличенный текст ошибки. Не устранять сбросом/переустановкой.
