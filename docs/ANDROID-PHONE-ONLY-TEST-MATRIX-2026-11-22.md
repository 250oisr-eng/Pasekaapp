# Android: комплект проверок только с телефона — 2026-11-22

Статус: **план и инструкции подготовлены; единый Android APK НЕ собран; новый физический прогон НЕ выполнялся**. Пользователь временно располагает только Android-телефоном, поэтому не давать ADB, USB, PowerShell, ПК-команд и сценариев, требующих доступа к ПК.

## Исходные ограничения
- Устройство по прежним отчётам: OnePlus NE2213, Android API 36. Повторно не считать устройство проверенным до запуска на нём каждого конкретного APK.
- Последний независимый реальный ONNX smoke: `LOCAL_ONNX_WASM_ADD_2_EXACT` PASS — только самописная арифметическая модель Add(3,2)=5. **Не означает распознавание пчёл**.
- Отдельная синтетическая проверка кадров: PR #347, `SYNTHETIC_MP4_THREE_FRAMES_EXTRACTED` PASS, 3 кадра 64×64; реальные видео не использовались.
- Синтетические архивные preflight: PR #361, семь тестов PASS; **настоящий backup/restore и архивы не проверены**.
- Разрешения изолированного APK: PR #364, `A09_INSTALLED_PERMISSION_AUDIT_ONLY` PASS. Это не доказательство разрешений продукта.
- Restore335 V10 PR #380: `BLOCKED / SOURCE_FIXED_NAME_NOT_MATCHED_PRESERVE`. Неизвестный private-файл сохранять. **STOP физические пробы Restore335**, не переустанавливать APK, не очищать кэш/хранилище, не пробовать V11 и не удалять файл.
- В настоящее время нет проверенного физического протокола распознавания пчёл, правильности учёта вход/выход, доступа к настоящим видео, полного архива и удаления исходного видео. Их нельзя ставить PASS.
- Оригинал видео должен быть удалён **после успешного распознавания**, но не до полного подтверждения безопасности удаления и восстановления. Пока весь cleanup заблокирован.

## Процедура для телефона
1. Не удалять существующие диагностические приложения, их private-data, оригинальные ролики или резервные копии. Особенно не трогать Restore335.
2. Для *конкретного* теста открыть ссылку на проверенный GitHub Actions run для **точного SHA**, скачать APK через Artifacts (если есть доступ и артефакт не истёк). Если нет доступа/истёк — отметить `BLOCKED_ARTIFACT`, не использовать похожий APK. GitHub Actions zip не переименовывать в APK; распаковать и устанавливать именно APK. Не обещать, что GitHub позволит загрузку на мобильном браузере.
3. Устанавливать только уникальный диагностический packageId. Не заменять основной `ru.paseka.journal`, не предоставлять лишних разрешений.
4. В диагностике нажать «Провести тест», затем «Копировать результат»; вставить JSON целиком в чат. Если кнопок нет — описать фактический интерфейс; не додумывать результат.
5. Если тест возвращает `BLOCKED`, `NOT_TESTED` или `NOT_AUTHORIZED`, сохранить исходные данные и перейти к следующему **независимому** тесту без повторных попыток восстановить или удалить медиа.
6. При передаче результата: `testId`, `packageId`, `APK code SHA`, `status`, `code`, `checks`, `cleanupAuthorized`; не передавать секреты, приватные пути, названия пользовательских видео или их содержимое.

## Приёмка
- `PASS` означает только успешное выполнение утверждений данного теста. Все непроверенные поля сохраняются как `NOT_TESTED`.
- Запрет на очистку снимается не на основании M01–M10, а лишь после доказанного распознавания, точной привязки исходного видео, полного учёта копий, проверки резервного восстановления, атомарного удаления и результатов физического теста на конкретном SHA.
- Ни Draft PR, ни удачная сборка CI не означают production-release или разрешение на merge.

Включить только синтетические тесты, не включать Restore335, реальное видео или cleanup; до реализации не называть dashboard готовым.
