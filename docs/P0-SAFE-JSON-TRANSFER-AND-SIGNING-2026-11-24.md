# P0 — изолированный перенос JSON и долговременная Android-подпись

Контрольная точка: 24 ноября 2026. Статус: **CONTRACT_READY; TRANSFER_NOT_TESTED; SIGNING_NOT_PROVISIONED**.

## Причина

Пользователь подтвердил на OnePlus: чистая установка, первый улей, семья, две заметки, офлайн-перезапуск — PASS. Теперь на телефоне есть **тестовые записи**; очистка данных запрещена. Оригинальные debug APK нескольких CI сборок подписаны **разными** сертификатами. Подробности в [P0-ANDROID-APK-SIGNING-CONFLICT-2026-11-24.md](./P0-ANDROID-APK-SIGNING-CONFLICT-2026-11-24.md).

**Обычное обновление APK той же packageName с другим signer невозможно**. Даже новая постоянная подпись не станет совместимой со старой, если исходный закрытый ключ недоступен. Поэтому старое установленное приложение должно оставаться неизменным.

## F0–F2: карта зависимостей

- **Приложение-источник**: сообщённая пользователем установленная `ru.paseka.journal`; фактическая installed подпись ещё не считывалась. 
- **Переносимые основные данные**: `S.hives`, `S.families`, `S.records`, метаданные и другие поля `S` из существующего `downloadBackup()`: `{app:'Paseka',state:S}`.
- **Не доказана переносимость**: отдельно сохранённые IndexedDB-видео летков `entrance_media` и иные внешние источники. Путь полной копии и восстановления P0 — отдельный Draft [#452](https://github.com/250oisr-eng/Pasekaapp/pull/452).
- **Цель**: отдельное QA-приложение с **другим** Android `appId`, одновременно установленное со старым, с тем же исходным веб-кодом и явно обозначенным тестовым назначением. Действующий `scripts/prepare-oneplus-first-use-config.mjs` из Draft #469 применяет `ru.paseka.journal.firstuseqa` только при явном CI-флаге и фиксированной ветке; это ещё **не** подтверждённый установленный APK. Не смешивать с default `ru.paseka.journal`.
- **Первый независимый gate**: выполнить локальный **read-only** аудит реального скачанного JSON до импорта. Новый `scripts/audit-oneplus-json-transfer.mjs` принимает файл и опциональные ожидаемые счётчики; не сохраняет приватные записи, не отправляет их в сеть, не изменяет устройство.

## Безопасный CLI-аудит JSON

После получения оригинального JSON из приложения и сохранения его вне телефона:

```bash
node scripts/audit-oneplus-json-transfer.mjs /path/to/paseka-backup.json --expect-hives=1 --expect-families=1 --expect-records=2
```

Эти количества **только для первого синтетического пользовательского сценария на OnePlus**. Если пользователь добавлял другие записи, реальный ожидаемый счётчик требуется корректировать без удаления данных. Старые/неполные backup-форматы могут иметь другие структуры; инструмент честно блокирует неизвестный формат.

Инструмент проверяет `app:'Paseka'`, объект `state`, массивы `hives/families/records`, непустые и уникальные IDs, тип `record.media`, ссылки семей/журнала и соответствие ожидаемым количествам. Исторические отсутствующие ссылки переводят результат в `REVIEW_REQUIRED`, а не маскируются. Отчёт содержит счётчики, схему, обобщённые предупреждения и **не** содержит текстов заметок, имён, идентификаторов семей или данных файлов.

Результат `JSON_STATE_PREFLIGHT_ONLY` — **не доказательство успешного импорта/восстановления**. Даже при нём невозможно утверждать, что видео или другие внешние файлы перенесены. JSON не загружать в публичные CI artifacts, PR body, external AI или GitHub logs.

## Дальнейшие ворота переноса

1. **Read-only source**: выгрузить оригинальный JSON с действующего телефона **без очистки**. Сохранить независимую копию вне приложения и проверить, что файл читается.
2. **Isolated sandbox**: независимо от OnePlus восстановить JSON в отдельном тестовом IndexedDB origin, пройти startup integrity guards и проверить конкретно улей, семью и обе заметки, включая перезапуск без сети.
3. **Signing custody**: создать долговременную пару signing key/certificate **в защищённой среде владельца**; приватный ключ и пароли не помещать в репозиторий, документы, build artifacts или журнал. Сформировать минимум одну офлайн-резервную копию и безопасную процедуру восстановления ключа. **Нельзя считать случайный CI debug certificate долговременным ключом**.
4. **Независимый package**: подготовить и подписать новый тестовый APK с `appId=ru.paseka.journal.firstuseqa`, подтвердить packageId, versionCode и certificate SHA-256 на **конкретном бинарном APK**. Не использовать прежнее `ru.paseka.journal` для этого APK.
5. **Физическая проверка**: только после gate 1–4 можно предложить установку второй иконки приложения. Исходный установленный пакет, база и две тестовые заметки **остаются** на телефоне. Реставрация JSON — только после подтверждения корректного независимого экземпляра и без обращения к данным исходного.
6. **Повторное обновление QA**: будущий QA APK с тем же `appId`, тем же сертификатом и не уменьшающимся `versionCode` должен проходить `scripts/check-oneplus-upgrade.mjs`; физическое подтверждение только после backup и наблюдаемого сохранения данных.

## Условия остановки

- Нет контролируемого долгоживущего signing key → `SIGNED_CANDIDATE=BLOCKED`.
- Нет подтверждённого оригинального JSON или тестовый импорт/перезапуск не PASS → `DEVICE_TRANSFER=BLOCKED`.
- Исходное приложение оказывается не `ru.paseka.journal`, либо ключ/подпись неизвестны → не изменять/не удалять его.
- PASEKA02 video cleanup [#442](https://github.com/250oisr-eng/Pasekaapp/issues/442) остается FROZEN; этот протокол не даёт разрешения на удаление/восстановление видео.
- Merge #469/#452 и любая публикация требуют отдельного разрешения пользователя.
